# ModlistTool v2 — спецификация и архитектура

Новый движок по мотивам монолита `index.html` (≈196k строк, v4xx–v7xx).
Монолит — идейный прототип: что он умеет, берём; как он это делает — нет.

## 1. Почему монолит упирается в ~1k модов

Найдено по коду:

- Всё исполняется в одном потоке браузера: 0 Web Worker, 0 WASM, 0 SharedArrayBuffer.
- Обход диска — File System Access API (`showDirectoryPicker`, `getDirectoryHandle`):
  каждый каталог — асинхронный вызов через границу браузера, с `await nextFrame()` между модами.
- Каждый путь хранится строкой в IndexedDB (`PathStorage.writeModPaths`, `overwritePathOwners`,
  `conflictPathDict`, `overwriteChainPathChunks`…). Owners/chains/contexts перестраиваются
  через курсоры IDB с партиционированием по FNV-хешу строки пути.
- Над этим — десятки слоёв «presentation / projection / authority / compatibility» (V4xx→V7xx),
  каждый со своим кешем и своей инвалидацией. Сотни self-test'ов проверяют исходники функций
  через `Function.prototype.toString`.

Итог: одни и те же данные материализуются многократно (строки путей × моды × слои),
отсюда сотни миллионов строк в активной работе.

## 2. Инвентарь функций (паритет)

### Проект / файлы
- Старт: «С возвращением» (autosave) / восстановить из контейнера / новое состояние из профиля MO2
  (`modlist.txt`, `plugins.txt`, `loadorder.txt`, папки mods и overwrite).
- `.mnlth` — переносимый контейнер проекта; `modlist.txt` — загрузка/сохранение; autosave.
- История действий (journal), undo-снимки.

### Основной вид (classic) — три панели
- **Разделители**: список, поиск, цвет/эмодзи/декор, свернуть/раскрыть все, создать/переименовать/
  покрасить/копировать (с метой)/удалить, функциональные (SYNC/Overwrite) разделители.
- **Моды**: карточки в цвете разделителя, вкл/выкл (Alt+клик), мультивыбор Ctrl/Shift,
  drag-n-drop (порядок, перенос между разделителями), контекстное меню, поиск, фильтры по тегу/стикеру/эмодзи,
  бейджи W/L/M/X и +n, OW-summary разделителя, счётчики вкл/выкл, мета-строки (метрики-шаблоны).
- **Сводка**: вкладки «Моды/разделители», «Дерево», «Floating meta», «Conflicts: карточки», «Conflicts: таблица».
- Второй вид — **explorer** (Ctrl+2), до 4 окон модов.

### Анализ («пробег»)
Стадии (из `buildRunSessionStagesForConfig`):
1. Поверхность — дешёвые сигнатуры модов, переиспользование результатов.
2. Бездна — полное дерево маршрутов (все файлы всех модов).
3. Compact tree и индексы.
4. Overwrite-папка как системный мод.
5. BSA/BA2 manifest → virtual paths в дерево.
6. Плагины: TES4 header, тип (ESM/ESP/ESL), мастера, record signatures, REFR/ACHR.
7. Метрики: размер, файлы, папки, плагины, DDS/NIF/PEX/HKX/DLL/архивы, VRAM DDS (точный),
   профиль содержимого, top-расширения, топология путей, «cargo»-сигналы.
8. Правила тегов, правила стикеров.
9. Индекс владельцев файлов → **exact chains** (файлы, сгруппированные по упорядоченному стеку
   владельцев) → **contexts** (связные компоненты модов через цепочки) → normalized/route groups.
10. Кастомные пробеги.
Модалка «Пробег анализа»: ход стадий, live runtime, лог, «Принять».

### Конфликты
- Карточки цепочек и таблица контекста (stack view), «зубной ряд» файлов (W/L/O/M),
  пометка цепочек/контекстов решёнными, пользовательские объединения цепочек,
  имя/иконка/цвет цепочки, копия цепочки «для ИИ», проводник файлов, игнор-файлы.
- Мастер порядка перезаписи: dry-run план, строгость, locked-моды, создать разделитель/стикер, undo.

### Плагины
- Список plugins, порядок загрузки (в т.ч. расчётный), мастера/зависимые, каскадное включение,
  blacklist, scan-side-only (найдено сканом вне loadorder), копирование списка.

### Слой пользователя
- Теги и стикеры (коллекции, правила), заметки к модам, логические группы (composite mod),
  мета-блоки (в т.ч. пользовательский JS), визуальные эффекты (резонанс тегов, точки/полоски,
  интенсивность, анимация), hover-облачко с настраиваемыми секциями.

### Sync / commit (запись в MO2)
- Сверка проекта с ФС: найденные/отсутствующие/переименованные папки, принять/восстановить/перенести в deleted.
- Commit workflow: pre-commit check → backup-версии `profile/monolith/versions` → запись
  `modlist.txt`, `plugins.txt`, `loadorder.txt`, папки разделителей с `meta.ini`.
- Доноры: внешняя сборка (её `modlist.txt` + mods), кандидаты на перенос, валидация сходимости.

### Прочее
Мобильный/тач-режим, диагностика IDB, console help. **Не переносим** (не нужно в новой архитектуре):
диагностику IndexedDB, legacy project.json, self-test'ы по исходникам.

## 3. Архитектура v2

```
modlisttool.exe  (Go 1.24, только stdlib, один файл; UI встроен через go:embed)
 ├─ mo2       ModOrganizer.ini, modlist/plugins/loadorder.txt, meta.ini
 ├─ scan      параллельный обход N корней модов (worker pool), сигнатуры, кеш сканов
 ├─ formats   TES4 header, BSA (v103/104/105), BA2 (GNRL/DX10), DDS → VRAM
 ├─ index     интернирование путей (дерево каталогов + словарь имён),
 │            колоночная таблица провайдеров, сортировка, owners → chains → contexts
 ├─ project   пользовательский слой (теги, цвета, заметки, группы) — JSON, журнал
 └─ server    HTTP API + SSE прогресс, встроенный web UI (go:embed)
web UI (Svelte + Vite)  — открывается в браузере на 127.0.0.1
```

Принципы:
1. **Одна истина** — `Engine` держит снимок анализа (immutable после постройки) + модель порядка.
   UI получает только проекции, всё вычисляется из них. Никаких параллельных кешей в UI.
2. **Ничего тяжёлого не материализуется**. Путь = `uint32`, мод = `uint32`; конфликты — CSR-массивы.
   Списки файлов отдаются страницами.
3. **Изменение порядка не требует пересканирования** — стеки владельцев пересортировываются
   по новым приоритетам, сканы кешируются по сигнатурам.
4. Порядок модов и папки на диске — канон MO2; запись только через явный commit с бэкапом.

### Модель конфликтов
- Провайдер = (путь, мод, источник: loose | archive, размер).
- Стек пути = провайдеры, отсортированные: loose выше архивов, внутри — по приоритету MO2.
- Конфликтный путь — стек ≥ 2 разных модов.
- **Exact chain** — множество конфликтных путей с одинаковым стеком модов.
- **Context** — связная компонента графа «мод—мод» по цепочкам.
- Бейджи мода: **W** — файлы, где мод победитель; **L** — где проигрывает;
  **M** — где он в середине стека; **X** — мод полностью перекрыт (ни одного выигранного конфликтного файла
  и нет уникальных файлов).


> Почему Go, а не Rust: сборка под Windows из этой среды для Rust недоступна (std для windows-gnu
> не скачивается), Go кросс-компилирует из коробки. По задаче (обход диска, хеш-таблицы, сортировки,
> горутины) разницы в классе производительности нет.

## 4. Замеры (синтетика, контейнер 2 vCPU / 7 ГБ, файлы в page cache)

| Сценарий | Результат |
|---|---|
| 2 500 модов, 2,87 млн файлов + 7 тыс. записей BSA, холодный обход (с чтением ~1 млн DDS-заголовков) | 64 с, пик RSS 836 МиБ |
| Тот же билд из кеша сигнатур (повторный пробег / старт программы) | обход 3,8 с + индекс 1,9 с |
| Память в работе после индексации | ~516 МиБ |
| Пересчёт конфликтов после перемещения мода (222 тыс. конфликтных путей, 167 тыс. цепочек) | 0,1–0,14 с |
| Чистое ядро: 5 000 модов, 9,9 млн провайдеров (in-memory) | индекс 7,3 с, пересчёт 0,3 с |
| `/api/modlist` на 2 500 строк | 9 мс |

Реальный внешний SSD по USB будет медленнее на холодном проходе (упор в IO), кеш снимает это для повторных запусков.

## 5. Статус v0.1 — что уже есть

- Открытие инстанса (ModOrganizer.ini, base_directory/%BASE_DIR%, профили), **несколько папок модов**.
- modlist.txt: чтение, порядок, вкл/выкл, перенос модов и разделителей (drag-n-drop, контекстное меню),
  undo/redo, сохранение с бэкапом в `<profile>/monolith/versions/<время>/`, несохранённый порядок
  переживает перезапуск.
- Цвета разделителей из meta.ini (`@Variant` QColor), версии/Nexus id модов.
- Пробег: параллельный обход, кеш по сигнатурам, BSA (v103–105) и BA2 (GNRL/DX10) как виртуальные пути,
  TES4 header (ESM/ESL/мастера/HEDR), опционально record scan (REFR/ACHR), VRAM DDS из заголовков.
- Конфликты: loose > архив, стеки, exact chains, contexts, W/L/M/X/+n, VRAM победителей, отметки «решено».
- UI: classic (разделители | моды | сводка) и explorer (Ctrl+2), вкладки Сводка/Конфликты/Дерево/
  Контексты/Плагины/Файлы, теги (ручные + авто по содержимому), заметки, цвета.
