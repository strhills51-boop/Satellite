# Пробег анализов монолита — обзор (v503 «Analysis Orchestrator», CP1–CP12)

Источник: монолит, `runOrchestratedAnalysisCutoverV503` (строка ~134039), модули
`ModlistTool*V503` (~166063–173818), базовая линия `modlisttool.run-kernel-baseline.v1`.
Режим **«Бездна»** (`full`) идёт через новый оркестратор. Режим **«Поверхность»** (`surface`) — через старый путь
(`analyzeModsDirectoryLegacyV503`). Старые функции стадий (`runArchiveStage`, `runMetricCollectionStage` …)
в «Бездне» больше не главные: их заменили анализаторы оркестратора.

## Словарь (CP2, `modlisttool.analysis-orchestrator.vocabulary.v1`)

| Сущность | Смысл | В NG |
|---|---|---|
| `RunGeneration` | поколение пробега: `staging → authoritative \| aborted`, ссылка на предыдущее | снимок результата; публикуется атомарно, устаревший отбрасывается |
| `RouteSource` | источник путей: `kind` (`mod-folder`, архив, overwrite…), `owner`, `parentSourceId`, `origin` (`loose`/архив) | `ScanJob` + архивы как дочерние источники |
| `Observation` | одно наблюдение: путь, расширение, размер, mtime, происхождение | запись обхода (`LooseFile`, `ArchiveEntry`) |
| `WorkUnit` | отложенная работа анализатора над источником | задача пула |
| `Sink` | приёмник результатов (обязательный или нет) | слой фактов |
| `BarrierToken` | барьер: финализатор ждёт, пока все открытые токены закроются | точка соединения стадий |
| `RunEvent` | событие с номером последовательности, фазой, источником, анализатором | события задачи (NG-D003) |
| `RuntimeSnapshot` | живая проекция: источники, работа, барьеры, анализаторы, очереди, счётчики, проблемы | окно пробега |

**Контракт анализатора:** `id`, `executionClass` ∈ `stream-consumer` (читает наблюдения) / `source-expander`
(порождает новые источники, например архив → его записи) / `barrier-finalizer` (работает после барьера, например
конфликты); `failurePolicy` ∈ `mandatory` / `optional` / `degraded`; функции `accepts(observation)`,
`consume(...) → { facts, sources, work, warnings }`, необязательные `flush`, `finalize`. Анализаторы регистрируются
в реестре контрактов. Это прямой предок «анализатора» из пяти типов расширений Satellite (PHILOSOPHY «Эволюция»).

## Порядок пробега «Бездна» (CP12 cutover)

1. **Sync/discovery** — список папок `mods`; сверка с проектом **до** surface (`buildSyncReconcileResult`, записи SYNC).
2. **Surface** — сигнатура каждого мода; классы `new` / `unchanged` / `changed`.
3. **Route planning** («модель трёх маршрутов», V505/V506/V515): для каждого мода свой `executionRoute`:
   - `scan` — полный физический обход;
   - `indexed` — индекс путей прошлого поколения переиспользуется, а анализаторы, которых не хватает,
     досчитываются;
   - `reuse` — артефакты целиком из прошлого поколения.
   Решение принимается по **возможностям артефакта** (`artifactCapabilities`): `loosePaths`, `routeMetadataV2`,
   `archiveVirtualPaths`, `archiveEntrySizesV555`, `metrics`, `ddsVramV613`, `tags`, `stickers`. Если появился
   новый анализатор, пересчитывается только его возможность, а не весь мод. Если нужных артефактов нет, пробег
   блокируется **до** deep.
4. **Staging generation** — новое поколение создаётся в состоянии `staging`.
5. **Живой пробег** (`LiveRunSession.runShadow`): единый ограниченный обход (`UnifiedLooseTraversal`) порождает
   наблюдения и отдаёт их анализаторам с обратным давлением (`observationWindow 64`, `maxPendingObservations 128`,
   `maxPendingWorkUnits 128`, `maxActiveArchiveReaders 1`, `routeChunkSize 128`, `yieldEveryNItems 128`).
   Анализаторы:
   - `DynamicArchiveSources` (source-expander): BSA/BA2 → виртуальные пути с размерами записей;
   - `StreamingAggregates`: метрики мода (размер, число файлов, виртуальные файлы, маршруты, расширения,
     компактные факты: теги, стикеры, папки);
   - `PluginAnalyzer`: плагины в свободных файлах;
   - `DdsVramCollector` (CP15): VRAM текстур **в том же обходе**, без отдельного прохода;
   - `ConflictFinalizers` (barrier-finalizer).
   Папка `overwrite` — обычный источник в том же обходе.
6. **Печати** (seals): единый реестр staging (`UnifiedStagingLedger`: моды scan/reuse, пути, отсутствие устаревшего),
   печать возможностей (у каждого мода полный физический индекс, нет потерянных возможностей), приёмка трёх
   маршрутов, печать сигнатур.
7. **Конфликты** — один авторитетный финализатор: владельцы → цепочки и контексты из staging-путей, сверка
   паритета.
8. **commit.ready → promote** — поколение становится авторитетным; при любой ошибке `abort` (staging удаляется,
   старый результат остаётся).
9. **После promote:** проекции архивов и плагинов, агрегаты и метрики (с VRAM и метриками конфликтов),
   нормализованный слой цепочек (`materializeOverwriteNormalizedLayerV501`), пользовательские пробеги (`custom`),
   жизненный цикл логических групп, холодная миграция.
10. **Finalize** — «Можно принять результат».

## Что берём в NG и чем отличаемся

- **Берём модель целиком:** источники → наблюдения → анализаторы по контракту → барьеры → финализаторы;
  поколения со staging и атомарной публикацией; маршруты scan/indexed/reuse по возможностям.
  Ядро NG уже устроено близко: кеш по моду = reuse, `sat-core` финализирует конфликты.
- **Возможности вместо единой версии кеша.** Сейчас в NG кеш инвалидируется целиком (`CACHE_VERSION`). Переходим
  на версию каждого анализатора: новый анализатор досчитывает только своё (маршрут `indexed`).
- **Ограничители потока** монолита (окна, очереди, один читатель архивов) нужны были браузеру. В NG ограничение
  задаёт I/O-пул. Параметры не копируем, а подбираем по замерам.
- **Сигнатура — сознательное расхождение.** Формула монолита (`buildAnalysisSignature`): имя папки + число
  записей корня + имена папок корня + имена файлов корня + расширения корня. То есть только корень и только
  имена: замена текстуры внутри мода не обнаруживается. И, судя по формуле, сигнатура зависит от имени папки,
  поэтому сверка переименований по сигнатуре (`signatureBuckets` в `buildSyncReconcileResult`) не может сработать —
  **проверить на монолите.** В NG сигнатура v2 не зависит от имени папки, смотрит на глубину 2, размеры и mtime.
- **Хранилище:** IndexedDB, печати хранилищ и холодная миграция — это способы монолита выжить в браузере.
  В NG их заменяют снимок в памяти и контейнер проекта (ADR 0007). Смысл печатей сохраняем как **инварианты**,
  которые проверяются перед публикацией: полный индекс у каждого мода, нет потерянных возможностей,
  нет устаревших путей.
