# UI монолита — разбор по живому запуску

Монолит запущен в Chromium (Playwright). Папки MO2 подложены через OPFS вместо `showDirectoryPicker`.
Тестовая синтетика: 60 модов, 12 разделителей, ~5 тыс. файлов, 54 цепочки.
Прошли: старт → новый workspace → пробег анализа → все основные экраны.

## 2. Ключевые экраны

**Конфликты** — полноэкранная модалка с переключателем **Карточки / Таблица / 2 области**, плюс «Дерево», «Игнор файлов», «Закрыть».
- *Карточки*: поиск; селектор контекста «Все контексты · 1 ctx · 54 chains · 60 mods · 307 files»; тумблеры «Фронт решений» / «✓ Решённые»; строки контекстов с генерируемыми именами (`gameplay·textures·architecture·patches·Fixes mod 0008 → …`) и кнопками «Все», ○, ▶.
- *Таблица* — главный экран. Заголовок контекста; слева моды, сгруппированные по разделителям (сворачиваемые). Справа **«зубной ряд»**: столбец на каждый файл/стек, клетка зелёная = выигрывает, красная = проигрывает, пустая = не участвует. Есть сортировка («Релевантность цепочке», «Сила конфликта»), подсветка выбранного мода. Внизу статус стека: `Stack stack_114 · 10 files · meshes · 3× .wav …`.
- *2 области* — карточки слева, таблица справа.

**Блок «Конфликты» в сводке**: список цепочек мода (эмодзи-иконка + сгенерированное имя + ○ «решено», «+4» свёрнутых). Под ним участники в виде строк с фоном-«зубами» и пунктирной жёлтой кромкой, выбранный мод зелёный.

**Блок «Дерево»**: ASCII-дерево (`├─ 📁 actors`) с иконками типов и сводками `3x .dds`, `1x .hkx` по листьям.

**Hover-облачко**: закрепляемый поповер с секциями Теги (+Добавить) · Plugins (blacklist) · Note (+Создать note).

**Контекстное меню мода**: заголовок `Мод: X`, **поле-фильтр разделителей**, список «Перекинуть в: <разделитель>», «Создать новый пустой мод», «Переименовать», «Массовые операции…», «Выключить».

**Пробег анализа**: карточки «Синхронизация» и «Поверхностный сигнатурный анализ» (бейдж ГОТОВО/РАБОТАЕТ, прогресс, плитки-счётчики). Большая карточка «Глубинный анализ» с крупным процентом, «Текущая операция», подвкладки (Обход источников / Stream / Post-deep / Promotion) и **сетка иконок-стадий** со счётчиками (📁 5,183 · 🗄️ 5/5 · 🧩 9/9 · 📊 61/61 · ⛓️ 237 · 🌳 5,382). Внизу статус-бар и «Принять».
Окно настройки пробега: карточки стадий с бейджами «Включен / Всегда включен / Выключен», выбор папок mods и overwrite.

**Sync panel**: шаги 1–5 (mods folder → profile folder → pre-commit check → refresh versions → execute commit) с цветом статуса; «Active sync records» с FS-резолюцией (create folder / remove from project / ack only); «Deployment processors»; «Проверка перед commit».

**Старт**: карточка `ModlistTool.mo2 | Monolith`, три action-карточки LOAD / INIT / TXT, потом шаг «Initialize new workspace» с проверкой modlist/plugins/loadorder (зелёные карточки, score 92/100).

## 4. Что заметил по ходу (поведение монолита)

- Пробег на 60 модах / 5 тыс. файлов — ~30 с. Новый движок делает то же за доли секунды.
- Если в папке mods лежат папки разделителей (`X_separator`, MO2 их создаёт), пробег падал:
  `Metric project entity is unavailable for non-reuse mod Animation_separator`. Пришлось удалить их из тестовой папки.
- После перезагрузки страницы и «Продолжить» конфликты/дерево были пустыми до нового пробега. Возможно, это эффект моей подмены папок, а не баг.
- Цвета разделителей из `meta.ini` MO2 монолит не подхватывает: плитки серые, цвет задаётся своей декорацией.

## 5. План переноса вида в v2 (по порядку)

1. Каркас: шапка с конвейером, плитки разделителей, flow-сетка модов со строкой-представителем, счётчики `a:b:c`, пилюли OW.
2. Сводка как стопка перетаскиваемых блоков: Выделение, Теги, Notes, Дерево (ASCII), Конфликты (цепочки + участники).
3. Модалка конфликтов: Карточки / **Таблица с «зубным рядом»** / 2 области — с виртуализацией по обеим осям (в монолите она тормозит на больших контекстах).
4. Окно пробега в стиле монолита (карточки стадий, сетка иконок).
5. Explorer-окна, hover-облачко, контекстное меню с фильтром, декорации и эффекты.
6. Sync panel.
