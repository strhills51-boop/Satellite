# NG-D003 — Слой приложения и dev-оболочка

- Статус: **open** (запланирована, после NG-D002)
- Пункты карты: PHILOSOPHY §8 Фаза 0 (граф зависимостей проекций, jobs), Фаза 3.5 (реестр команд)
- ADR: 0002, 0004, 0006

## Цель

Единый конвейер приложения поверх ядра: команды, запросы, события, поколения, задачи с отменой —
и тонкая dev-оболочка (HTTP + WebSocket), на которой UI и Playwright-тесты работают без Tauri.

## Контракт закрытия (черновик)

1. `sat-app`: типы Command / Query / Event с serde; экспорт TypeScript-типов автоматически.
2. Конвейер команды: `dispatch → policy → mutation слоя → invalidation → новое поколение → event`;
   команды не трогают UI (правило прототипа Satellite `no-render-from-command`).
3. Проекции объявляют зависимости; изменение порядка пересчитывает только перезапись, а не таблицу (проверено тестом).
4. Задачи (пробег анализа) отменяемы; устаревший результат не публикуется (поколение, как `superseded` в процессорах монолита).
5. **Решения по записям SYNC** (сами записи создаёт пробег, NG-D002): статусы `pending / confirmed / ignored /
   resolved` как команды; при `pending` фиксация заблокирована.
6. (перенесено в NG-D002: сверка и импорт проекта)
7. **Фиксация:** `Plan` операций → pre-commit проверка (отпечаток записей, свежесть пробега) → версия-бэкап
   (`modlist.txt`, проект до) → применение → журнал; удаление = перенос в `deleted/<время>`. Проверено на копии
   сборки во временной папке, включая откат при ошибке на середине.
8. `apps/devserver`: HTTP для команд и запросов, WebSocket для событий; сценарий «открыть → пробег → решить записи
   SYNC → переместить мод → undo → зафиксировать с бэкапом» проходит интеграционным тестом.
9. Бюджеты: ответ запроса видимой страницы < 50 мс на сборке 2,9 млн файлов.
