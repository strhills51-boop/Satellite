# NG-D001 — Фундамент ядра на Rust

- Статус: **closed** (2026-10-30)
- Пункты карты: PHILOSOPHY §8 Фаза 0 (перенос фундамента, тесты форматов, бенчмарки)
- ADR: 0001, 0002, 0003, 0005

## Цель

Перенести проверенную модель данных прототипа v0.1 (Go) в Rust-воркспейс с правильными границами слоёв,
так чтобы на ней можно было строить приложение (NG-D002) без переделок фундамента.

## Контракт закрытия

1. Воркспейс `crates/`:
   - `sat-core` — без `std::fs`/сети; интернер путей, `ProviderTable`, проекция перезаписи (стеки, exact chains,
     contexts, W/L/M/X/+n, VRAM победителей);
   - `sat-formats` — TES4-заголовок и счёт записей, BSA v103–105, BA2 GNRL/DX10, DDS → VRAM;
   - `sat-mo2` — ModOrganizer.ini, modlist/plugins/loadorder.txt (round-trip байт в байт), meta.ini, QColor;
   - `sat-scan` — параллельный обход (rayon), сигнатуры, кеш сканов.
2. `cargo test --workspace` зелёный; `cargo clippy --workspace -- -D warnings` чистый; `cargo fmt --check` чистый.
3. Зависимости только с permissive-лицензиями (ADR 0003): проверка списком `cargo metadata`.
4. **Сверка с эталоном:** на одной и той же синтетической сборке Rust и Go дают одинаковые
   число путей, провайдеров, конфликтных путей, цепочек, контекстов и W/L/M для каждого мода.
5. **Бюджеты** (синтетика): пересчёт проекции ≤ 200 мс на 10 млн провайдеров; сборка таблицы не медленнее Go;
   пиковая память не выше Go.

## Вне рамок

Приложение (команды, проекции, события), оболочки Tauri/dev-сервер, UI — это NG-D002+.

## Решения

- Собственный разбор плагинов вместо `esplugin`: тот под GPL-3.0 (ADR 0003).
- Тёплые структуры неизменяемы; проекция перезаписи — отдельный снимок, пересобираемый по приоритетам.

## Находки и риски

- **Ловушка прототипа Go:** несохранённый порядок молча применялся при открытии профиля (`pendingOrder`).
  Первая сверка дала 137 расхождений именно из-за этого — Go работал на другом порядке. Урок для NG-D002:
  отложенное намерение пользователя должно быть **видимым состоянием**, а не тихой подменой канона.
- **Память:** RSS процесса не равен живой памяти — освобождённые входные данные аллокатор не сразу отдаёт ОС.
  Для бюджетов меряем живую кучу таблицы (`ProviderTable::heap_bytes`) и пиковый RSS отдельно.
- **Интернер:** первая версия хранила каждое имя дважды (ключ в нижнем регистре + оригинал). Переход на общую
  арену строк + цепочки по хешу сократил сборку таблицы с 6,2 до 3,0–3,7 с и кучу до 718 МиБ на 9,4 млн провайдеров.
- **Риск:** холодный обход на этой машине 69,6 с против 64,2 с у Go (2 vCPU, файлы в page cache, ~1 млн чтений
  DDS-заголовков). В контракт не входил; разобрать в профилировании сканера (кандидаты: лишний `metadata()`
  на файл, порядок параллелизма между модами и внутри мода).
- **Не проверено на реальных файлах:** парсеры проверены на собственных фикстурах. Нужны настоящие образцы
  BSA/BA2/ESP/DDS (пункт Фазы 0 остаётся открытым).
- Среда 2 vCPU: абсолютные времена на машине пользователя будут лучше, параллельные части масштабируются по ядрам.
