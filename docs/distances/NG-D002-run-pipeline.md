# NG-D002 — Конвейер пробега: все стадии монолита

- Статус: **open** (2026-10-30)
- Пункты карты: PHILOSOPHY §8 Фаза 0 (jobs), Фаза 1 (паритет анализа)
- ADR: 0002, 0006, 0007

## Цель

Сначала **весь** пробег анализов с паритетом поведения монолита, потом оптимизации по замерам (решение владельца).
Пробег — задача движка из явных стадий: у каждой стадии объявлены входы и выходы, есть прогресс и события, её можно
отменить. Результат проверяется на сборке владельца (`X:\MO2`, 7 525 модов).

## Стадии монолита (инвентарь по коду)

Режимы: **Поверхность** (`surface`) — discovery + сигнатуры + сверка; **Бездна** (`full`) — всё.

| # | Стадия монолита | Что делает | Состояние в NG |
|---|---|---|---|
| 1 | `sync` (discovery) | читает все папки `mods` | есть (`sat-cli analyze`) |
| 2 | `surface` | сигнатуры: unchanged / changed / new; сверка с проектом → записи SYNC | сигнатуры есть; сверки нет |
| 3 | `deep` | манифесты путей изменившихся модов | есть (обход + кеш) |
| 4 | `compact` | компактная сборка / холодная миграция в IDB/`.mnlth` | не переносится: другой холодный ярус (ADR 0007) |
| 5 | `archives` | BSA/BA2: записи как виртуальные пути | есть, проверить паритет полей |
| 6 | `plugins` | заголовки, мастера, blacklist, порядок | заголовки есть; остальное нет |
| 7 | `metrics` | профиль содержимого мода | частично (`ModMetrics`); сверить набор метрик |
| 8 | `tags` | правила тегирования (выкл. по умолчанию) | нет |
| 9 | `stickers` | правила стикеров (выкл. по умолчанию) | нет |
| 10 | `overwrite-folder` | папка overwrite как системный мод | сканируется как мод; сверить маршрутизацию |
| 11 | `overwrite` | владельцы путей, цепочки, контексты, normalized / route groups | стеки, цепочки, контексты есть; normalized / route groups нет |
| 12 | `custom` | пользовательские пробеги (`customRuns`, `customArmed`) | нет |
| 13 | `finalize` | итоги, принятие результата | нет |

Настройки пробега монолита (`analysisConfig`): `deepEnabled`, `archiveScanEnabled`, `tagRulesEnabled`,
`stickerRulesEnabled`, `customArmed`, `conflictIgnorePaths` (`meta.ini`, `desktop.ini`, `thumbs.db`), `pluginBlacklist`.

## Контракт закрытия

1. Для каждой стадии из таблицы: файл `docs/parity/run/<стадия>.md` (что делает монолит, его входы и выходы,
   спорные места) и реализация в движке, либо явное решение «не переносится» с причиной.
2. Минимальная модель проекта (ADR 0006): импорт из `modlist.txt` + папок; сверка `sat-core::sync::reconcile` —
   чистая функция, записи `fs_created / fs_deleted / fs_rename_candidate` с идемпотентными отпечатками; таблица
   тестов на каждый тип, переименование по сигнатуре (единственный кандидат — да, два — нет).
3. Пробег — задача со стадиями: прогресс по стадиям, события, отмена; устаревший результат не публикуется.
4. Режимы «Поверхность» и «Бездна» и настройки `analysisConfig` с тем же смыслом, что в монолите.
5. Паритет на данных: где монолит может посчитать то же (небольшая выборка модов), результаты совпадают;
   расхождения объяснены.
6. Прогон на сборке владельца проходит все стадии; отчёт по стадиям (время, объёмы).

## Вне рамок

Оптимизации, кроме очевидных архитектурных (они идут после, по замерам). Фиксация на диск и dev-сервер — NG-D003.
UI — NG-D004.

## Решения

- Порядок: ширина раньше глубины. Сначала все стадии с честным поведением, потом скорость.
- Стадия `compact` не переносится: она лечила хранение строк в IndexedDB, в NG холодный ярус другой (ADR 0007).
