# NG-D002 — Конвейер пробега: все стадии монолита

- Статус: **open** (2026-10-30)
- Пункты карты: PHILOSOPHY §8 Фаза 0 (jobs), Фаза 1 (паритет анализа)
- ADR: 0002, 0006, 0007

## Цель

Сначала **весь** пробег анализов с паритетом поведения монолита, потом оптимизации по замерам (решение владельца).
Пробег — задача движка из явных стадий: у каждой стадии объявлены входы и выходы, есть прогресс и события, её можно
отменить. Результат проверяется на сборке владельца (`X:\MO2`, 7 525 модов).

## Модель монолита

В монолите пробег переделан: режим «Бездна» идёт через **Analysis Orchestrator v503** (CP1–CP12), а не через
старые функции стадий. Подробно — `docs/parity/run/00-overview.md`. Коротко: sync/discovery → surface →
планирование маршрутов (`scan` / `indexed` / `reuse` по возможностям артефакта) → staging-поколение →
единый обход с анализаторами по контракту (архивы как порождаемые источники, агрегаты, плагины, DDS VRAM) →
печати → авторитетный финализатор конфликтов → promote / abort → проекции, нормализованный слой, custom,
логические группы → finalize.

| Часть | В NG сейчас |
|---|---|
| sync/discovery + сверка | **есть**: `sync::records::reconcile`, `Project::observe` |
| surface (сигнатуры) | есть, v2 сильнее монолита (сознательное расхождение) |
| маршруты scan / indexed / reuse по возможностям | **есть**: по штампам анализаторов (`sat-scan::analyzer::plan`) |
| поколения staging → promote / abort | **есть**: `sat-core::run` (`Authority`, печати); `sat-cli` публикует проект только после печатей |
| анализаторы по контракту + барьеры | **контракт и реестр есть** (`metrics`, `dds-vram`, `plugins`, `archives`); барьеров нет |
| архивы (source-expander) | есть, сверить поля (размеры записей) |
| агрегаты / метрики | частично (`ModMetrics`) |
| плагины | заголовки + скан записей; паритет — `docs/parity/run/01-plugins.md` |
| DDS VRAM в том же обходе | есть |
| финализатор конфликтов | есть (стеки, цепочки, контексты) |
| нормализованный слой цепочек | нет |
| теги, стикеры, custom | нет |
| логические группы | в движке порядка (ADR 0008); в анализе (композит) — нет |

## Контракт закрытия

1. Для каждой части из таблицы: файл `docs/parity/run/NN-<часть>.md` (что делает монолит, его входы и выходы,
   спорные места) и реализация в движке, либо явное решение «не переносится» с причиной.
1a. Анализаторы — по контракту монолита (`executionClass`, `failurePolicy`, `accepts / consume / flush / finalize`),
   встроенные регистрируются так же, как будут регистрироваться расширения.
1b. Маршруты `scan / indexed / reuse` по версиям анализаторов вместо единой версии кеша.
1c. Поколение `staging → authoritative | aborted`; перед публикацией проверяются инварианты печатей монолита.
2. Минимальная модель проекта (ADR 0006): импорт из `modlist.txt` + папок; сверка `sat-core::sync::reconcile` —
   чистая функция, записи `fs_created / fs_deleted / fs_rename_candidate` с идемпотентными отпечатками; таблица
   тестов на каждый тип, переименование по сигнатуре (единственный кандидат — да, два — нет).
3. Пробег — задача со стадиями: прогресс по стадиям, события, отмена; устаревший результат не публикуется.
4. Режимы «Поверхность» и «Бездна» и настройки `analysisConfig` с тем же смыслом, что в монолите.
5. Паритет на данных: где монолит может посчитать то же (небольшая выборка модов), результаты совпадают;
   расхождения объяснены.
6. Прогон на сборке владельца проходит все стадии; отчёт по стадиям (время, объёмы).

## Вне рамок

Оптимизации, кроме очевидных архитектурных (они идут после, по замерам). Фиксация на диск и dev-сервер — NG-D003.
UI — NG-D004.

## Решения

- Порядок: ширина раньше глубины. Сначала все стадии с честным поведением, потом скорость.
- Стадия `compact` и холодная миграция не переносятся: они лечили хранение строк в IndexedDB, в NG холодный
  ярус другой (ADR 0007).
- Сигнатура surface — сознательное расхождение с монолитом (см. обзор): v2 ловит изменения глубже корня
  и не зависит от имени папки.

## Находки и риски

- Отпечаток записи по нормализованному имени (как в монолите) склеивает разные папки `Mod A` и `Mod-A` в одну
  запись. В NG ключ отпечатка — точное имя в нижнем регистре; нормализованное имя — только для сопоставления.

- Сигнатура монолита содержит имя папки, а сверка переименований ищет совпадение сигнатур — похоже, переименование
  по сигнатуре в монолите не срабатывает никогда. Проверить на монолите.

## Доказательства закрытия

- П. 2 (частично): `sat-core::sync::records::reconcile` — 5 тестов: синхронно → нет записей; созданные и удалённые
  для модов и разделителей; нормализованное совпадение и неоднозначность; переименование одной записью только при
  уникальной сигнатуре (два кандидата — нет; без сигнатуры — нет; мод ≠ разделитель); решения переживают повторную
  сверку, исчезнувшее расхождение снимается. `sat-cli analyze` печатает сводку сверки.
- П. 2 (модель проекта): `sat-core::project::Project` — 4 теста (импорт → переименование найдено на следующем прогоне;
  решения переживают `observe`; расхождение с `modlist.txt` видно и не применяется; serde туда-обратно).
  Сквозная проверка на синтетике 2,9 млн файлов: первый прогон импортирует проект, переименование папки → ровно
  одна запись `renamed`, возврат имени → запись снимается. Приоритеты перезаписи берутся из канона проекта.

- П. 1a/1b: `sat-scan::analyzer` — контракт (`id`, `version`, `ExecutionClass` stream-consumer / source-expander,
  `FailurePolicy` mandatory / optional / degraded, `structural`, `reads_virtual`), реестр (порядок регистрации =
  порядок диспетчеризации, проверка id, дубликатов), встроенные анализаторы зарегистрированы как будущие расширения;
  архивы — порождающий источник, их записи — виртуальные наблюдения для `dds-vram`. Кеш хранит штампы
  (`id`, `version`, хеш настроек); маршрут: штампы совпали → `reuse`; устарели неструктурные → `indexed` (кешированный
  индекс путей, перезапуск только устаревших; перезапуск порождающего тянет за собой читателей виртуальных записей;
  отключённый известный анализатор только чистит свои факты); устарел структурный или неизвестный → `scan`.
  Тесты: reuse → indexed (включение DDS: без обхода, 1 чтение, результат = свежий обход) → indexed-очистка →
  scan при смене списка игнора; перенос записей первого формата (обе старые сигнатуры). Синтетика 601 мод /
  188 тыс. файлов: отчёт совпадает с прежней сборкой до байта (кроме времени), холодный скан не медленнее
  (819 против 1 012 мс), включение `--records` даёт `indexed=481`, читаются только 69 плагинов, обход 35 мс
  против 6,4 с. Старый кеш владельца подхватывается без холодного прогона.

- П. 1c: `sat-core::run` — статусы и таблица переходов монолита (`AUTH_ALLOWED`), `Authority<T>`: `begin` → `Staging`,
  `promote` проверяет, что авторитет не сменился с начала пробега, и что печати пусты; при отказе ничего не
  публикуется, staging возвращается вызывающему (abort = drop). Печати: staging = ровно ожидаемые моды, каждый
  один раз; конфликтные инварианты (нет цепочек ⇒ нет контекстов, контексты ≤ цепочки ≤ конфликтные пути).
  Ошибка анализатора мода — деградация (в отчёт `degraded`), а не провал пробега (монолит валил пробег из-за
  одного архива). `sat-cli analyze`: Running → Staging → печати → Committing → Verifying → Promoting → Completed,
  проект пишется только при пройденных печатях; отчёт несёт `run`, `seals`, `degraded`. 3 теста.
