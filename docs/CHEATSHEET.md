# Шпаргалка владельца: как пощупать Satellite NG

Живой документ: меняется вместе с кодом. Если команда отсюда не работает — это баг шпаргалки, скажи Claude.

## Что сейчас можно пощупать

| Что | Где | Что видно |
|---|---|---|
| `sat-cli` — ядро на твоей сборке | `sat-cli.exe` из CI (ниже) | скан, синхронизация, перезапись, плагины, отчёт JSON |
| Order Lab — движок порядка в браузере | артефакт «Order Lab» в claude.ai (список артефактов) | миллион записей, перенос, группы, цвета, undo — только патчи строк. **Устарел:** нет нескольких видов и клавиатурного курсора, обновится позже |

Интерфейса пока нет — это следующая большая веха (PHILOSOPHY, Фаза 2).

## Где взять `sat-cli.exe`

1. GitHub → репозиторий `strhills51-boop/Satellite` → вкладка **Actions** → последний зелёный запуск `ci` на `main`.
2. Внизу страницы запуска — **Artifacts** → `sat-cli-windows` (zip, внутри `sat-cli.exe`). Нужно быть залогиненным.
3. Распаковать куда угодно, например `C:\sat\sat-cli.exe`. Установка не нужна.

Собрать самому (если стоит Rust): `cargo build --release -p sat-cli` → `target\release\sat-cli.exe`.

## Что Satellite делает с твоей сборкой

- **Только читает** папки `mods`, `overwrite`, `profiles` и `ModOrganizer.ini`. `modlist.txt`, `plugins.txt`,
  `loadorder.txt` и моды не трогаются никогда.
- Пишет только в `<профиль>\satellite\`: проект `project.v0.json` (канон, декорации, записи SYNC) и кеш скана
  `cache\` (чтобы второй прогон не перечитывал диск). `--no-save` — не писать проект.
- Удалить всё, что сделал Satellite = удалить папку `<профиль>\satellite\`.

## Команды

Во всех примерах `X:\MO2` — папка MO2 (где `ModOrganizer.ini`). Профиль берётся из `selected_profile`.

### Главная: анализ сборки

```bat
sat-cli analyze X:\MO2 --report report.json
```

Печатает строки и пишет полный отчёт в `report.json`. Полезные флаги:

| Флаг | Зачем |
|---|---|
| `--report FILE` | отчёт JSON (всё, что ниже, плюс W/L/M/+n по каждому моду) |
| `--profile NAME` | другой профиль вместо выбранного в MO2 |
| `--no-save` | ничего не писать в проект (кеш всё равно пишется) |
| `--force` | пересканировать всё, игнорируя кеш (холодный прогон) |
| `--records` | дополнительно посчитать записи в плагинах (медленнее, читает плагины целиком) |
| `--listed-only` | сканировать только моды из `modlist.txt`, а не все папки `mods` |
| `--reimport` | забыть сохранённый проект и импортировать `modlist.txt` заново |
| `--io-threads N` | число потоков чтения диска (по умолчанию — по числу ядер) |
| `--cache DIR` | кеш в другом месте |
| `--mods DIR --profiles DIR [--overwrite DIR]` | папки по отдельности (как выбор папок в монолите), без `ModOrganizer.ini` |

**Как читать вывод** (строки в консоли):

- `sync: matched=… created mods/separators=… deleted …=… renamed=…` — сверка папок с проектом: найдено, новое,
  пропавшее, переименованное.
- `mods=… cache=… missing=… files=… archive=… paths=… providers=… conflicts=… chains=… contexts=… X=…` —
  сколько модов, сколько взято из кеша, файлы, записи архивов, виртуальные пути, конфликтные пути, точные цепочки,
  контексты, полностью перекрытые моды (X — в игре их не видно).
- `plugins=… full=… light=… overflow=…/… versioned=… missing-masters=… owner-off=… missing=…` — плагины:
  всего, активных полных и лёгких, сверх лимита (полных/лёгких), плагинов в нескольких модах сразу,
  с недостающими мастерами, лежащих только в выключенных модах, упомянутых, но не найденных.
- `timings_ms={…}` — время этапов; `peak_rss_mib` — пик памяти.
- `degraded mods: …` — моды, которые прочитались частично (недоступная подпапка и т. п.).

**Что сверить с MO2** (это и есть проверка ядра):

- `full` + `light` ≈ число активных плагинов во вкладке плагинов MO2; индексы MO2 (`FE:xxx`) — у лёгких.
- `missing-masters` — MO2 помечает такие плагины предупреждением.
- Второй прогон подряд: `cache=` ≈ числу модов и время `scan` маленькое — значит кеш работает (холодного
  пересканирования нет).

### Внешний донор (папка модов вне MO2)

```bat
sat-cli donor X:\MO2 --donor-mods E:\more-mods [--donor-modlist E:\more\modlist.txt] --report donor.json
```

Сверяет чужую папку модов с твоей сборкой (какие есть, каких нет, совпадения по именам).

### Разобрать один файл

```bat
sat-cli inspect "X:\MO2\mods\Some Mod\Some.esp" "X:\MO2\mods\Some Mod\Some.bsa"
```

Плагин: флаги, версия заголовка, мастера, автор. Архив: тип, число записей, суммарный размер и VRAM, первые записи.

### Бенчмарки (без сборки, синтетика)

```bat
sat-cli bench-synth --mods 5000 --files 1100
sat-cli bench-order --entries 1000000
```

`bench-synth` — таблица провайдеров и перезапись на 5 000 модах × 1 100 файлов (~7 млн путей), включая
инкрементальное обновление после перемещения одного мода. `bench-order` — движок порядка на миллионе записей
(перемещение, курсор, undo).

## Если что-то пошло не так

- Пришли Claude: команду, последние ~30 строк консоли и `report.json`, если он есть (в нём нет содержимого модов,
  только имена и числа).
- Падает на конкретном файле — `sat-cli inspect <файл>` и вывод.
- Странные числа конфликтов или плагинов — назови мод или плагин, который выглядит неправильно, и что показывает MO2.
- Подозрение на кеш — прогон с `--force`.

```sh
python3 tools/check-map.py                              # семантическая карта (якоря @sat:)

```

Куда смотреть в репозитории: `PHILOSOPHY.md` (направление и дорожная карта) → `docs/adr/` (решения, 0010 — ядро и
движок) → `docs/semantic/MAP.md` (понятие → якорь → файл) → `docs/parity/` (что делает монолит и как это в NG).
