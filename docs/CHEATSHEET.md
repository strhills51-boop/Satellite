# Шпаргалка владельца: как пощупать Satellite NG

Живой документ: меняется вместе с кодом. Если команда отсюда не работает — это баг шпаргалки, скажи Claude.

## Что сейчас можно пощупать

| Что | Где | Что видно |
|---|---|---|
| **`sat-devserver` — окно списка модов в браузере** | `sat-devserver.exe` из CI (ниже) | твоя сборка: карточки модов потоком в колонки, бейджи цепочек, клавиатурный курсор, перенос Alt+↑↓, вкл/выкл, фильтр, undo; ПКМ — меню мода и «Покрасить…»; сводка — «Декорация мода», «Конфликты» с таблицей контекста, плагины. **Песочница**: ничего не сохраняет |
| `sat-cli` — ядро на твоей сборке | `sat-cli.exe` из CI (ниже) | скан, синхронизация, перезапись, плагины, отчёт JSON |
| Order Lab — движок порядка в браузере | артефакт «Order Lab» в claude.ai (список артефактов) | миллион записей, перенос, группы, цвета, undo — только патчи строк. **Устарел:** нет нескольких видов и клавиатурного курсора, обновится позже |

Настоящего приложения пока нет: `sat-devserver` — оболочка разработки поверх того же API, что будет у приложения (ADR 0004).

**Есть в ядре и API, но ещё нет в окне** (интерфейс — отдельным этапом, вместе с владельцем): классический вид
(только текущий разделитель или выбранные стопкой, `flow_index_in`), несколько видов одной книги (`OpenView`),
полный список плагинов (`Query::Plugins`) и его правка (отметка, скрытие, каскад), записи SYNC с решениями и план
фиксации (`Query::Sync`, `Command::Decide`). Из командной строки уже работают `sat-cli sync` и `sat-cli commit`.

## Где взять `sat-cli.exe` и `sat-devserver.exe`

1. GitHub → репозиторий `strhills51-boop/Satellite` → вкладка **Actions** → последний зелёный запуск `ci` на `main`.
2. Внизу страницы запуска — **Artifacts** → `sat-cli-windows` (zip, внутри `sat-cli.exe` и `sat-devserver.exe`). Нужно быть залогиненным.
3. Распаковать куда угодно, например `C:\sat\sat-cli.exe`. Установка не нужна.

Собрать самому (если стоит Rust): `cargo build --release -p sat-cli` → `target\release\sat-cli.exe`.

## Что Satellite делает с твоей сборкой

- **Только читает** папки `mods`, `overwrite`, `profiles` и `ModOrganizer.ini`. `modlist.txt`, `plugins.txt`,
  `loadorder.txt` и моды не трогаются никогда.
- Пишет только в `<профиль>\satellite\`: проект `project.stll` (канон, декорации, записи SYNC, решения, факты
  модов — один файл, открывается любым zip-архиватором; внутри построчные `project\*.ndjson`) и кеш скана `cache\`
  (чтобы второй прогон не перечитывал диск). `--no-save` — не писать проект. Ранний `project.v0.json` с папкой
  `facts\` при первом прогоне сам переводится в `project.stll` (старые файлы остаются — их можно удалить).
- Удалить всё, что сделал Satellite = удалить папку `<профиль>\satellite\`.

## Пощупать в браузере: `sat-devserver`

```bat
sat-devserver X:\MO2
```

Без сборки (например, на другом компьютере — достаточно скопировать один файл `project.stll`):
`sat-devserver --project <project.stll или его папка>` — порядок, декорации, конфликты, цепочки и метрики берутся
из проекта.

Сканирует сборку (через тот же кеш, что `sat-cli analyze` — если `analyze` уже прогонялся, откроется за секунды) и пишет
`open http://127.0.0.1:7878/`. Открой этот адрес в браузере. Флаги: `--profile NAME`, `--port N`. Остановить — `Ctrl+C`
в консоли.

- **Ничего не сохраняется.** Ни в MO2, ни в проект: все правки живут в памяти, пока сервер работает. Порядок берётся
  из проекта Satellite, если `sat-cli analyze` его уже создал, иначе из `modlist.txt`.
- Сервер слушает только `127.0.0.1` — с других машин недоступен.
- Клавиши — внизу страницы. Кликни в список, чтобы он получил фокус клавиатуры. Клик — фокус, `Ctrl`+клик —
  в выделение, `Shift`+клик — диапазон, клик по кружку — вкл/выкл, клик по стрелке разделителя — свернуть.
- Перенос мышью (drag) пока нет — только `Alt`+`↑↓`.
- Над списком: модель бейджей («Коллекция цепочек» / «OW N»), колонки («Поток · 340 / 260» / «Одна колонка»),
  плотность значков. Стрелки `↑↓` в потоке идут по порядку модов, а не по колонкам.
- ПКМ по моду — меню монолита: фильтр разделителей, «Перекинуть в», вкл/выкл, «Покрасить…» (палитра 8 × 16), сброс.
- Сводка справа: **«Декорация мода»** — для фокуса или выделения (поля, где моды расходятся, помечены `mixed`;
  «Default» снимает декорацию; кнопки — последние декорации); **«Конфликты»** — нормализованные цепочки мода,
  участники с «зубами», кружок «решено»; кнопка **«Таблица»** открывает таблицу контекста (моды × файлы, клик по
  строке — фокус на мод, `Esc` — закрыть).

## Команды

Во всех примерах `X:\MO2` — папка MO2 (где `ModOrganizer.ini`). Профиль берётся из `selected_profile`.

### Главная: анализ сборки

```bat
sat-cli analyze X:\MO2 --report report.json
```

Печатает строки и пишет полный отчёт в `report.json`. Полезные флаги:

| Флаг | Зачем |
|---|---|
| `--report FILE` | отчёт JSON (всё, что ниже, плюс W/L/M/+n по каждому моду) |
| `--profile NAME` | другой профиль вместо выбранного в MO2 |
| `--no-save` | ничего не писать в проект (кеш всё равно пишется) |
| `--force` | пересканировать всё, игнорируя кеш (холодный прогон) |
| `--offline` | без сборки: факты модов берутся из проекта (`project.stll`), а не со скана; ничего не сохраняет |
| `--tags` | найти теги модов по встроенному набору правил (детекторы монолита): сводка и метрика `tags` для `--find` |
| `--tag-rules FILE` | то же по своему набору правил (формат — `rules/tags/monolith-builtin.json` в репозитории) |
| `--find "УСЛОВИЕ"` | напечатать моды, подходящие под условие (см. «Поиск модов по условию») |
| `--records` | дополнительно посчитать записи в плагинах (медленнее, читает плагины целиком) |
| `--listed-only` | сканировать только моды из `modlist.txt`, а не все папки `mods` |
| `--reimport` | забыть сохранённый проект и импортировать `modlist.txt` заново |
| `--io-threads N` | число потоков чтения диска (по умолчанию — по числу ядер) |
| `--cache DIR` | кеш в другом месте |
| `--mods DIR --profiles DIR [--overwrite DIR]` | папки по отдельности (как выбор папок в монолите), без `ModOrganizer.ini` |

**Как читать вывод** (строки в консоли):

- `sync: matched=… created mods/separators=… deleted …=… renamed=…` — сверка папок с проектом: найдено, новое,
  пропавшее, переименованное.
- `mods=… cache=… missing=… files=… archive=… paths=… providers=… conflicts=… chains=… contexts=… X=…` —
  сколько модов, сколько взято из кеша, файлы, записи архивов, виртуальные пути, конфликтные пути, точные цепочки,
  контексты, полностью перекрытые моды (X — в игре их не видно).
- `plugins=… full=… light=… overflow=…/… versioned=… missing-masters=… owner-off=… missing=…` — плагины:
  всего, активных полных и лёгких, сверх лимита (полных/лёгких), плагинов в нескольких модах сразу,
  с недостающими мастерами, лежащих только в выключенных модах, упомянутых, но не найденных.
- `timings_ms={…}` — время этапов; `peak_rss_mib` — пик памяти.
- `degraded mods: …` — моды, которые прочитались частично (недоступная подпапка и т. п.).

**Что сверить с MO2** (это и есть проверка ядра):

- `full` + `light` ≈ число активных плагинов во вкладке плагинов MO2; индексы MO2 (`FE:xxx`) — у лёгких.
- `missing-masters` — MO2 помечает такие плагины предупреждением.
- Второй прогон подряд: `cache=` ≈ числу модов и время `scan` маленькое — значит кеш работает (холодного
  пересканирования нет).


### Поиск модов по условию

```bat
sat-cli analyze X:\MO2 --no-save --find "size > 1 GB && plugins > 0"
sat-cli analyze X:\MO2 --no-save --find "ext.dds >= 500 && !enabled"
sat-cli analyze X:\MO2 --no-save --find "name ~ \"texture\" && loses > wins"
```

Печатает подходящие моды: позиция, имя, разделитель. Язык: сравнения `> >= < <= == !=`, `~` — «содержит» (без
регистра), `&& || !`, скобки, арифметика, `min max round floor ceil abs clamp`, размеры `KB MB GB TB`. Метрики:
`name separator enabled priority size files dirs root_files depth archives archive_files plugins dds vram nif pex
hkx dll nested_archives source_files wins loses mid unique overridden`, а также `ext.<расширение>` (`ext.esp`) и
`dir.<папка верхнего уровня>` (`dir.meshes`). Синоним: `weight` = `size`. Ошибка показывает место; опечатка ловится до скана. Тот же язык
пойдёт в условные стикеры и кейсы счётчиков (ADR 0013).

Профиль содержимого (как в монолите): `kind` (основной вид: textures, meshes, scripts, animations, native, mixed,
none), `kinds`, `coverage80`, `archived_share` (% содержимого в архивах), `package` (empty, plugin-and-assets,
plugin-centric, asset-only, support-only, other), `profile` (все метки через запятую), `cargo` / `cargo_signals`
(вложенные архивы, исходники, отладочные файлы), `top_ext`, `ext_kinds`, `extensionless`, `domains`,
`presentation`, `deep_paths`, `long_paths`, `junk`, `data_wrapper`.

```bat
sat-cli analyze X:\MO2 --no-save --content
sat-cli analyze X:\MO2 --no-save --find "cargo && size > 100 MB"
sat-cli analyze X:\MO2 --no-save --find "data_wrapper > 0 || junk > 0"
sat-cli analyze X:\MO2 --no-save --find "profile ~ \"voice-package\""
```

`--content` печатает сводку по сборке: формы пакетов, основные виды, частоту меток, моды с грузом не для игры
(первые 20) и с системным мусором (первые 10).

### Игнор-лист конфликтов

```bat
sat-cli ignore X:\MO2 --add meta.ini --add docs/ --add textures/sky/a.dds
sat-cli ignore X:\MO2 --remove docs/
```

Пути, которые не считаются конфликтом: `meta.ini` — файл с таким именем где угодно, `docs/` — папка с таким именем
где угодно, `textures/sky/a.dds` — ровно этот путь (регистр и `\` не важны). Список хранится в проекте и
применяется при следующем `analyze` и в `sat-devserver`.

### Расхождения диска с проектом и фиксация

```bat
sat-cli sync X:\MO2
sat-cli sync X:\MO2 --decide 1 adopt_to_project --decide 2 ignore
sat-cli commit X:\MO2
sat-cli commit X:\MO2 --apply
```

`analyze` находит расхождения (новая папка, пропавшая, переименованная) — `sync` их показывает с номерами и
возможными ответами; `--decide N ОТВЕТ` записывает решение в проект Satellite (диск не трогает). `commit` печатает
план и блокеры; **только с `--apply`** меняет сборку: сначала копии `modlist.txt`, `plugins.txt`, `loadorder.txt` и
проекта в `profiles\<профиль>\satellite\versions\<время>\`, потом операции по одной с журналом, при любой ошибке —
откат. Папки не удаляются: «удалить» = перенос в `satellite\deleted\<время>\` рядом с `mods`. `modlist.txt`
пишется из канона проекта. Если диск поменялся после анализа — план блокируется: прогони `analyze` ещё раз.

### Внешний донор (папка модов вне MO2)

```bat
sat-cli donor X:\MO2 --donor-mods E:\more-mods [--donor-modlist E:\more\modlist.txt] --report donor.json
```

Сверяет чужую папку модов с твоей сборкой (какие есть, каких нет, совпадения по именам).

### Разобрать один файл

```bat
sat-cli inspect "X:\MO2\mods\Some Mod\Some.esp" "X:\MO2\mods\Some Mod\Some.bsa"
```

Плагин: флаги, версия заголовка, мастера, автор. Архив: тип, число записей, суммарный размер и VRAM, первые записи.

### Бенчмарки (без сборки, синтетика)

```bat
sat-cli bench-synth --mods 5000 --files 1100
sat-cli bench-order --entries 1000000
```

`bench-synth` — таблица провайдеров и перезапись на 5 000 модах × 1 100 файлов (~7 млн путей), включая
инкрементальное обновление после перемещения одного мода. `bench-order` — движок порядка на миллионе записей
(перемещение, курсор, undo).

## Если что-то пошло не так

- Пришли Claude: команду, последние ~30 строк консоли и `report.json`, если он есть (в нём нет содержимого модов,
  только имена и числа).
- Падает на конкретном файле — `sat-cli inspect <файл>` и вывод.
- Странные числа конфликтов или плагинов — назови мод или плагин, который выглядит неправильно, и что показывает MO2.
- Подозрение на кеш — прогон с `--force`.

## Для разработки (если захочешь сам)

```sh
cargo test --workspace                                  # все тесты
cargo clippy --workspace --all-targets -- -D warnings   # линтер, как в CI
python3 tools/check-map.py                              # семантическая карта (якоря @sat:)
SAT_MODEL_SEEDS=250 cargo test --release -p sat-core order   # модельные тесты порядка, побольше зёрен
```

Куда смотреть в репозитории: `PHILOSOPHY.md` (направление и дорожная карта) → `docs/adr/` (решения, 0010 — ядро и
движок) → `docs/semantic/MAP.md` (понятие → якорь → файл) → `docs/parity/` (что делает монолит и как это в NG).

## Запланировать мод из архива загрузок

```bat
sat-cli plan-install X:\MO2 --archive "Имя архива.zip" [--name "Имя мода"] [--after "Мод, после которого"] [--disabled]
sat-cli analyze X:\MO2
sat-cli commit X:\MO2            (план: install …)
sat-cli commit X:\MO2 --apply    (распаковка в mods, modlist.txt, проект)
```
Архив должен лежать в папке загрузок MO2. Мод сразу встаёт в порядок, а `analyze` показывает его конфликты ещё до
установки (по оглавлению архива). Форматы: zip и 7z (rar — пока нет). Архив с FOMOD-установщиком: `--show` печатает шаги и варианты (`[x]` — в
силе), `--choose "шаг/группа/вариант"` (можно несколько) выбирает; группа без выбора берёт умолчания установщика.
Выбор записывается в проект, фиксация ставит ровно его.

## Условные стикеры

```bat
sat-cli stickers X:\MO2 --add "тяжёлый=size > 1 GB"
sat-cli stickers X:\MO2 --remove тяжёлый
```
Стикер ставится сам на каждый мод, для которого выражение верно (язык тот же, что у `--find`), и сам снимается.

## Свои счётчики на карточках

```bat
sat-cli counters X:\MO2 --add "wl={wins}/{loses}" --case "wl|loses > wins|bad"
sat-cli counters X:\MO2 --add "вес={size:bytes}" --show-if "вес|size > 100 MB"
```
Шаблон: текст и `{выражение}` (формат `:bytes` или `:pct`). Случай: условие и тон (первый выполненный). Счётчики
приходят окну вместе со строками; рисовать их будем вместе.

## Лог-группы и фабрики

```bat
sat-cli group X:\MO2 --add Костюмы --from "Первый мод" --to "Последний мод"
sat-cli factory X:\MO2 --add "Костюмы=Костюмы (собрано)" --link
sat-cli commit X:\MO2            (план: build …)
sat-cli commit X:\MO2 --apply
```
Законченную группу можно **запечь и запечатать**: `--seal` — фиксация соберёт мод, участники уйдут в
`satellite\deleted`, группа закроется. Это не отменяется следующей фиксацией, поэтому нужно подтверждение:
`sat-cli commit X:\MO2 --apply --confirm "Костюмы (собрано)"`.

`--downscale 1` у фабрики — текстуры выхода вдвое меньше по сторонам (вчетверо по весу): отбрасывается верхний
мип-уровень, без перекодирования, не меньше 512 px. Фабрика костюмов: `--downscale 1 --pack`.

`--pack` у фабрики — упаковать выход в архивы BSA с пустым ESL-плагином (игра загрузит архивы, плагин не
займёт полного слота; фиксация сама впишет его в plugins.txt). Тысячи файлов становятся двумя-тремя. В игре
ещё не проверено — проверь на небольшой группе.

Группа — подряд идущие моды; анализ считает её одним модом. Фабрика собирает группу в один выходной мод (жёсткие
ссылки — без лишнего места на том же диске), ставит его после группы и выключает участников (`--keep-members` —
оставить). Изменилась группа — следующая фиксация пересоберёт.

## Правка настроек мода (патч)

```bat
sat-cli patch X:\MO2 --mod "3BA" --file "SKSE\Plugins\CBPConfig.txt" --set "Breast/fStiffness=0.8"
sat-cli patch X:\MO2                      (список, «base holds» / «BASE CHANGED»)
sat-cli commit X:\MO2 --apply
```
Оригинал мода не трогается: исправленная копия ложится в мод «Satellite Patches» в конце порядка. Мод обновился —
фиксация остановится и попросит проверить патч (`--rebase` — принять новую основу).
