# ADR 0012 — Стиль карточки мода и раскладка потоком

- Статус: **принято** (2026-11-01), направление владельца: «контейнер элемента списка — референс монолит»
- Связано: ADR 0008 (движок порядка, патчи строк), ADR 0009 (виды), ADR 0010 (истина «декорации», закон 11),
  конспект `docs/semantic/monolith/12-mod-card.md` §1, §3

## Контекст

В монолите карточки модов идут **потоком в несколько колонок** внутри разделителя, а пользователь настраивает
контейнер каждого мода: ширину, перенос строки до и после, «вся ширина», высоту, поля, а также вид — фон
(9 типов раскраски), обводку, текст, акцент, эмодзи-watermark, эффекты. В NG сейчас одна запись = одна строка
фиксированной высоты: это удобно для виртуализации, но это не тот контейнер, который владелец построил и считает
правильным.

Сложность — масштаб: поток с карточками разной ширины и рядами разной высоты на миллионе записей, без
пересборки всего списка (закон 11, ADR 0008).

## Решение

### 1. Стиль карточки — данные декорации

`CardStyle` — декорация записи (истина «декорации», `Truth::Decoration`), по имени в проекте (как цвет и группы):

- **раскладка:** `width` (px, иначе ширина по умолчанию вида), `break_before`, `break_after`, `full_width`,
  `height` (px, иначе высота по умолчанию), `margin_top`, `margin_bottom`;
- **вид:** `fill` (тип: цвет, градиент →, градиент ↓, радиальный, конический, полосы, диагональ, шахматка,
  точки; цвета 1 и 2), `outline` (скругление, толщина, стиль, цвет), `text` (цвет, размер, жирность, разрядка,
  регистр), `accent` (цвет, ширина), `watermark` (эмодзи, позиция, размер, прозрачность, размытие), `effect`
  (тень, свечение).

Стили интернируются: у тысяч модов один и тот же стиль — одна запись, у записи — индекс. Изменение — операция
книги с отменой (`Op::Style`), как цвет. Поля вида не влияют на раскладку; поля раскладки — влияют.

### 2. Раскладка потоком — проекция вида

Вид получает ширину окна (`SetViewport { view, width }`). Ядро раскладывает **блок разделителя** в ряды:
жадно слева направо, ширина карточки = `width` стиля или ширина по умолчанию вида; `full_width` — свой ряд;
`break_before/after` — перенос; высота ряда = наибольшая высота карточки в нём плюс поля. Строка-представитель
разделителя — свой ряд.

- Раскладка блока кэшируется и пересчитывается **только для затронутых блоков**: перемещение трогает блок-источник
  и блок-цель; стиль — блок записи; ширина окна — все блоки, но лениво (раскладываются видимые, остальные —
  по мере прокрутки, с оценкой высоты до раскладки).
- Над блоками — дерево Фенвика по **высотам** блоков (в пикселях) и по числу рядов: «какой ряд на высоте y»
  и «какая высота до блока k» — O(log n).
- Страница запрашивает **окно рядов** (`Query::Lines { view, y, height }`): ряды, попадающие в видимую область, и
  карточки в них. Патчи строк ADR 0008 остаются протоколом изменений записей; страница по событию перечитывает
  своё окно рядов, как сейчас окно строк, и перерисовывает только изменившиеся карточки.
- Свёрнутый разделитель — один ряд-представитель. Фильтр — раскладываются только видимые записи.

### 3. Где что живёт

| Что | Владелец |
|---|---|
| `CardStyle`, интернирование, `Op::Style` | `order::decor` (данные) + `order::book` (операции) |
| Раскладка блока, Фенвик высот, окно рядов | новый модуль вида `order::flow` |
| Ширина окна, ширина / высота по умолчанию | вид (`order::book` views) |
| Редактор декорации, палитра «Покрасить…», контекстное меню | страница (оболочка), через команды |

## Порядок работ

1. `CardStyle` в декорации: данные, интернирование, `Op::Style` с отменой, сохранение в проекте, команды
   `SetStyle` / `ClearStyle`.
2. Отрисовка стиля на текущей карточке (одна в строке): фон, обводка, текст, акцент, watermark.
3. `order::flow`: раскладка блоков, Фенвик высот, `SetViewport`, `Query::Lines`; страница переходит на окно рядов.
4. Редактор декорации в сводке и палитра «Покрасить…» в контекстном меню мода (как в монолите).

## Последствия

- Карточка становится настраиваемым контейнером, как в монолите, без пересборки всего списка.
- Раскладка зависит от ширины окна, поэтому живёт в виде, а не в каноне: у двух окон с разной шириной — разные
  ряды над одной книгой.
