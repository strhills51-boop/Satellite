# ADR 0013 — Правила как данные: метрики, выражения, теги по наборам правил, системные стикеры, счётчики

- Статус: **принято** (2026-11-01), направление владельца (сообщение 2026-11-01 21:38)
- Связано: ADR 0002 (истины), 0010 (проекции), 0011 (ресурсы и доверие), 0012 (декорация); конспект монолита обл. 17
  (`00-index.md`), области 5 (пробег)

## Контекст

В монолите несколько механизмов делают одно и то же разными кодами и зашиты в код:

- **Теги-детекторы** — 257 правил `BUILTIN_TAG_DETECTORS` (7 400 строк JSON-подобного словаря прямо в `index.html`,
  27 158–34 560): ключи `path`, `folder`, `file`, `ext`, `name`, `plugin`, `root`, `all`, `none`, `score`. Ручные и
  найденные теги смешаны в одном мешке `mod.derived.tags`, сброс пробега стирает ручные (см. обл. 17).
- **Счётчики** (v371–v649, удачная поздняя часть): шаблон = токены «метрика / текст», формат (префикс, суффикс,
  скрыть ноль, ширина, ведущий ноль, компактный вид, разделитель тысяч, знаки после запятой), выражение и «кейсы»
  (`when` → цвет / жирность / рамка). Свой язык выражений (`tokenize/parse/compileCounterExpressionV529`):
  `+ - * / %`, сравнения, `&& || !`, функции `min max round floor ceil abs clamp`, идентификаторы — id метрик из
  реестра `METRIC_REGISTRY`, сгруппированного по темам (`COUNTER_METRIC_CATALOG_GROUPS_V621`).
- **Стикеры** — эмодзи-метки, заданные руками. Владелец собирался сделать из них **системные метки**:
  1. «новый мод» — ставит синхронизация, снимает следующий пробег;
  2. метки намерений — удалён, восстановлен, установлен с донора и т. п.;
  3. метки по условию — поиск «вес > 1 ГБ» и другие составные фильтры: где условие истинно — метка стоит.

Владелец: «теги стоит вынести в отдельный файл правил, который можно дополнять… в будущем будет развитие и
решения сообщества»; «нужен инструментарий стикеризации и снятия стикеров по условиям пользователя и автоматизация».

## Решение

Одна основа — **метрики и выражения**, на ней четыре потребителя. Правила — данные (ресурсы ADR 0011), а не код.

### 1. Метрики (`sat-core::metrics`, `@sat:metrics`)

Реестр метрик области «мод» (затем «разделитель», «проект»): id, название, группа (как каталог монолита),
единица (`байты`, `число`, `флаг`, `текст`). Значение — из фактов скана (`ModMetrics`, по расширениям
`ext.<расширение>`), проекции перезаписи (`wins`, `loses`, `mid`, `unique`, `overridden`), канона (`enabled`,
`priority`, `name`, `separator`). Новые анализаторы добавляют метрики, а не код фильтров.

### 2. Язык выражений (`sat-core::expr`, `@sat:expr`)

Один безопасный язык для фильтров, условий стикеров, кейсов счётчиков и правил:
`size > 1 GB && plugins > 0`, `ext.dds >= 100 || name ~ "texture"`, `!enabled && unique > 0`, `max(wins, loses) > 10`.
Операторы монолита плюс `~` (содержит, без учёта регистра) и единицы размера (`KB MB GB TB`, двоичные).
Пишут так, как думают: синонимы и русские имена метрик (`weight`, `вес`, `плагины`, `разделитель`, `расш.dds`)
и единиц (`ГБ`) разрешаются в один id метрики (`@sat:metrics.aliases`); сохранённое выражение работает, на каком
бы языке его ни написали. Для тех, кто не пишет выражения, окно даёт конструктор «метрика — оператор — значение»,
который собирает то же выражение.
Разбор с позициями ошибок; неизвестная метрика — ошибка компиляции, а не тихий ноль. Нет доступа ни к чему,
кроме метрик (у монолита — запрещённые идентификаторы, у NG — их просто нет в грамматике).

### 3. Теги по наборам правил (`rules/tags/*.json`)

Детекторы монолита выносятся **файлом данных** (`rules/tags/monolith-builtin.json`, тот же формат), к нему
добавляются свои наборы и наборы сообщества (ресурсы ADR 0011: источник, доверие, версия, дайджест). Пробег, если
включён анализ тегов, применяет наборы к фактам — получается **слой найденных тегов** (истина «факты»), отдельный
от ручных (`@sat:order.decor.marks`). Показ объединяет слои и знает происхождение каждого тега. Позже к формату
детекторов добавляется условие на выражении (`when: "dll > 0 && ext.pex == 0"`).

- **Версии формата.** Версия 1 — формат монолита как есть: игла — подстрока, поэтому `"ui"` попадает и в
  `build`, и в `quiet`. Версия 2 — по умолчанию **целые слова** (`match: "word"`; набор может указать явно).
  Встроенный набор остаётся версией 1, пока владелец не посмотрит теги на своей сборке; переход — сменой
  версии, а не правкой кода.
- **Происхождение.** Найденный тег хранит, какие правила какого набора дали ему очки (`FoundTag::rules`): «почему
  у мода этот тег» — первый вопрос к любому набору сообщества.
- **Открыто до наборов сообщества:** спор двух наборов об одном моде (`patch` против `standalone`) — приоритет
  наборов по доверию (ADR 0011) или явные «противоположные» теги; решить вместе с подключением наборов.

### 4. Системные метки (развитие стикеров)

Метка имеет **происхождение**, и от него зависит, где живёт её истина:
- *ручной стикер* — ставит и снимает пользователь (`Marks::stickers`, декорация);
- *событийная метка* — **вид** уже существующей записи, а не отдельное состояние: «новый мод» — запись сверки
  `fs_created`, «пропал», «переименован» — её же виды; «будет удалён / восстановлен / придёт с донора» — операции
  плана фиксации и сессии донора. Запись закрылась (фиксация, повторный пробег) — метка исчезла сама: снимать
  нечего и некому, две истины не могут разойтись (главный источник бед монолита — именно такие дубли);
- *условная метка* — правило «выражение → метка» (п. 2): сохранённый поиск. Проекция пересчитывает её **только для
  модов, чьи метрики изменились** (закон 11): размер — после скана, конфликтные счётчики — после перестановки,
  у затронутых модов.

Показ: системные метки — **значки-статусы** со своим видом (цвет, короткая подпись, подсказка «откуда»), эмодзи
остаются пользователю. Эмодзи не хватит по смыслу, если системных меток станет много, а значок-статус ещё и
объясняет себя. Решение пересматривается, когда владелец потрогает окно.

### 5. Счётчики

Шаблон монолита как данные: токены «метрика / текст», формат токена, выражение, кейсы (`when` на языке п. 2).
Отрисовка — окно; вычисление значения и кейсов — ядро (только для видимых строк).

## Порядок работ

1. Метрики мода и язык выражений; поиск в командной строке (`sat-cli analyze --find "…"`).
2. Набор правил тегов монолита — файлом; движок детекторов по фактам; слой найденных тегов в пробеге.
3. Условные стикеры (правило «выражение → стикер») и событийные («новый мод», намерения фиксации).
4. Счётчики: шаблоны, формат, кейсы; `Query::Rows` отдаёт готовые токены.
5. Ресурсы ADR 0011 для наборов правил: подключение файлов сообщества с доверием и версией.

## Сделано

- Шаг 1 (2026-11-01): `sat-core::expr` — язык (`|| && ! == != < <= > >= ~ + - * / %`, `min max round floor ceil abs
  clamp`, единицы `KB MB GB TB`, текст в кавычках, `null` для не сосканированного), ошибки с позицией;
  `sat-core::metrics` — 25 метрик мода по группам каталога монолита плюс `ext.<расширение>` и `dir.<папка>`;
  `sat-cli analyze --find "…"` — выражение проверяется до скана, печатаются подходящие моды с позицией и разделителем.
- Шаг 2, первая часть (2026-11-01): 257 детекторов монолита вынесены файлом `rules/tags/monolith-builtin.json`
  (формат `satellite-tag-rules`, порог, правила как были); `sat-core::tag_rules` — сопоставление монолита
  (`path file plugin name folder root ext`, `all`, `none`, сумма очков, порог), все иглы поля — один автомат
  Aho-Corasick на набор; `sat-cli analyze --tags` (встроенный набор) или `--tag-rules FILE` (свой): сводка тегов,
  метрика `tags` в `--find` (`tags ~ "skse"`). **Ещё нет:** слой найденных тегов в сессии и окне, объединение с
  ручными, условие-выражение в правиле, подключение наборов как ресурсов.
- Правки по разбору с владельцем (2026-11-01): синонимы и русские имена метрик и единиц (`compile_with` +
  `metrics::resolve`); версия 2 формата правил — целые слова; `FoundTag` — какие правила дали тег; системные
  метки — вид записей сверки и плана, значки-статусы.

## Последствия

- Фильтры, стикеры, счётчики и теги говорят на одном языке: научившись писать условие для поиска, пользователь
  пишет его и для стикера, и для кейса счётчика.
- Правила растут без изменения кода; наборы сообщества — тот же формат.
