# ADR 0018 — Централи конфликтов как данные, ядро без игры

Статус: принято (2026-11-14). Продолжает ADR 0017.

## Контекст

К этому дню у NG два домена конфликтов, и оба выросли вокруг одной оси — порядка загрузки (моды, плагины). Окно
«Конфликты» показывает их двумя проекциями (карточки, таблица), но вкладки зашиты в страницу, а каждый домен имеет свои
запросы. Владелец (2026-11-14):

- порядок загрузки — **одна из централей** конфликта, не единственная: у OAR своя централь — внутренний приоритет
  подмодов; у SPID — алфавит файлов правил; у ограничений — никакой;
- список централей **не хардкодится**: пользователь в будущем добавляет свою;
- Satellite — программа-спутник **под любые игры**, не только Skyrim;
- карточки и таблица — **проекции**; новый вид конфликта попадает в обе сам;
- вкусовые предпочтения — не вид конфликта, а решение (логические группы, ADR 0017: «намеренный»); OAR — случай
  отдельной централи, а не системный вид.

## Решение

### 1. Централь (precedence domain) — данные

`Centrality`: откуда берётся порядок участников одной цели:

| централь | порядок | пример |
| --- | --- | --- |
| `mod_order` | приоритет мода в менеджере | файлы (VFS MO2) |
| `plugin_order` | порядок загрузки плагинов | записи, архивы |
| `field` | число из файла участника (JSON-указатель / ключ INI), больший или меньший выигрывает | OAR `config.json` → `priority` |
| `name` | имя участника по алфавиту | SPID/KID: файлы правил |
| `none` | порядка нет | ограничения, сложение |

Семантика взаимодействия (ADR 0017 §3) — отдельное поле: `last_wins`, `highest_wins`, `lowest_wins`, `additive`,
`exclusive`, `conditional`, `constraint`. Равный ранг у двух участников при семантике с победителем — конфликт
«не решён» (ничья), а не победа первого.

### 2. Домен — адаптер с общей формой вывода

Каждый домен (`ConflictDomain`) отдаёт одно и то же:

- **описание**: id, название, семейство (collision / merge / interaction / constraint), централь, семантика,
  происхождение (встроенный адаптер / пакет игры / пользовательский файл);
- **цепочки**: стек участников (снизу вверх, победитель последним — если он есть), цели цепочки, клетка
  «участник × цель» одним символом (`w` выигрывает, `l` проигрывает, `s` равна победителю, `o` источник, `t` ничья,
  `x` нарушение, `m` участвует без порядка, `-` нет);
- **контексты**: связные компоненты цепочек по общим участникам;
- **счётчики**: целей, конфликтов, нерешённых, по видам.

Из этого строятся **обе проекции** — карточки и таблица — одним кодом, без знания домена. Вкладки окна берутся из
списка доменов, а не из вёрстки. Файлы и записи остаются быстрыми специализированными адаптерами (их объёмы — сотни
тысяч путей и миллионы записей), но отвечают на те же запросы.

### 3. Пользовательские домены — описанием, без кода

`DomainSpec` (JSON, как правила тегов): шаблон пути с захватами — что участник, что цель; централь и семантика.
Пример — OAR: `meshes/actors/{actor}/animations/openanimationreplacer/{mod}/{submod}/{anim}` → участник
`{mod}/{submod}`, цель `{actor}/{anim}`, централь `field` (`{…}/{submod}/config.json`, `/priority`, больший
выигрывает), семантика `conditional`. Движок спецификаций — общий: он работает по фактам путей и читает только
названные файлы. Чего описанием не выразить (разбор плагинов, архивов, мешей) — адаптер в коде, регистрируется так же.

### 4. Пакет игры

Всё игровое уходит в `GamePack` (встроенный JSON на игру, позже — пользовательские): базовые плагины и их порядок,
правило Creation Club, лимиты индексов (полные / лёгкие), правила архивов (порядок архивов — по плагинам; отдельный
файл бьёт архив), опасные сигнатуры записей (удалённые ссылки, навмеши), шаблон FaceGen, спецификации доменов. Ядро
читает пакет, а не константы. Первый пакет — Skyrim SE/AE; формат плагинов Bethesda остаётся адаптером
(`sat-formats`), который пакет называет.

### 5. Виды, которые входят сейчас (ADR 0017 + обсуждение 2026-11-13)

1. **Ограничения** (constraint, без победителя): нет мастера, мастер ниже зависимого, лимиты индексов.
2. **Архивы против файлов** (collision, своя централь): где игра возьмёт не ту копию, что показывает порядок модов —
   отдельный файл ниже по порядку бьёт архив выше; архивы между собой — по порядку плагинов.
3. **Опасные записи**: удалённые ссылки и навмеши (удалены вместо «отключены»), навмеш, правленный двумя и больше.
4. **Поля записей** (merge): конфликт записей делится на «покрыт» (победитель несёт правки всех), «сливаемый»
   (правки теряются, но поля не пересекаются; повторяющиеся подзаписи — коллекции, итог — объединение) и «настоящий»
   (одно поле, разные значения у двоих).
5. **Несогласованность доменов**: FaceGen — запись NPC выигрывает из одного мода, а его лицо — из другого.
6. **OAR** — пользовательской спецификацией из пакета Skyrim (проверка, что централи-данные работают).

7. **Генерации**: выход генератора (из пакета: маркеры выхода, шаблоны входов) ниже мода-входа по порядку.
8. **Версии**: загрузчик SKSE и Address Library против версии игры (версия файла exe).
9. **Правила-строки**: спецификация с `lines` — цели — строки файлов правил (BOS, SPID-экипировка).

Связки ассетов (меш → текстура, тело и скелет) требуют разбора NIF и манифестов архивов самой игры — дальше.

### 6. Счётчики

По монолиту (`commitConflictMetricSummariesV645`): у мода — пути в конфликте, выигрыши, проигрыши, доля выигрышей,
соперники, цепочки, контексты; у участника цепочки — W / L / M / X (выигрывает / проигрывает / нет файла цепочки /
конфликтные файлы вне цепочки). Плюс счётчики доменов в окне (вкладка — число нерешённых).

## Сделано (2026-11-14)

Всё из §1–§6 (2026-11-14, второй заход — генерации, версии, правила-строки, лёгкий диапазон, редакция плагина),
кроме связок ассетов (в дорожной карте). Ограничения известные: «равна победителю» у записи
сравнивает байты как есть (ссылки через разные списки мастеров — разные байты; у полей записей это уже учтено);
повторяющиеся подзаписи и массивы из пакета (ключевые слова `KWDA`) — коллекции, счётчики-производные (`KSIZ`,
`LLCT`, …) не сравниваются; поля
сравниваются по байтам, разбора схем записей нет — «настоящий» может оказаться слиянием, «покрыт» — нет.

## Последствия

- Добавить вид конфликта = адаптер или спецификация; окно и счётчики не меняются.
- Пакет игры — единственное место знаний об игре; вторая игра = второй пакет (+ адаптер формата, если он другой).
- Пользовательская централь не может сломать встроенные: домены независимы, правила одного не переносятся на другой.
