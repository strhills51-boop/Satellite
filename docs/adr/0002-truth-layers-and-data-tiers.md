# ADR 0002 — Слои истины и ярусы данных как структура кода

- Статус: **принято** (2026-10-30)
- Связано: PHILOSOPHY §4 «Слои истины», §5 «Данные: горячие, тёплые, холодные»

## Контекст

Корневая болезнь монолита — каждая подсистема хранила свою копию истины и свою инвалидацию.
Принцип из философии должен быть закреплён в **структуре кода**, иначе он размоется.

## Решение

### Слои истины → границы крейтов и типов

| Слой | Где живёт | Кто пишет |
|---|---|---|
| Факты | `sat-core::facts` (таблица провайдеров, метрики, заголовки) | только сканер через `sat-scan` |
| Канон | `sat-core::canon` (порядок, вкл/выкл, разделители) | ~~только manager adapter~~ → **проект Satellite**, см. ADR 0006 |
| Намерение | `sat-core::intent` (решения, правила, желаемый порядок) | команды пользователя |
| Знание | будущий `sat-knowledge` | сервис/датасет |
| Представление | UI-слой и `sat-core::presentation` (теги, цвета, декорации) | команды пользователя |

- Производные данные (стеки, цепочки, контексты, статистика) — **проекции**: функции от слоёв, никогда не хранятся как истина.
- Изменение канона — только через `Plan` (diff) → проверка → бэкап → применение.

### Ярусы данных

| Ярус | Форма | Примеры |
|---|---|---|
| Горячий | плоские `Vec` целых чисел, пересчёт < 200 мс | приоритеты, стеки, W/L/M/X |
| Тёплый | неизменяемые колонки и CSR-индексы | `ProviderTable`, `PathInterner` |
| Холодный | файлы на диске, mmap | кеш сканов, снимки таблицы, журнал |

- Путь = `PathId(u32)`, мод = `ModId(u32)`, строки хранятся один раз.
- Тёплые структуры неизменяемы после сборки; новое состояние — новый снимок (`Arc`), читатели не блокируются.
- Ничего не материализуется целиком: списки отдаются страницами.

## Последствия

- `sat-core` не зависит от `std::fs`, сети и потоков ОС (кроме `rayon` для чистых вычислений): ядро компилируется в WASM.
- Каждая новая структура данных в PR указывает слой и ярус (правило агентов §9.3).
