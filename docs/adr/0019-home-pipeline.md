# ADR 0019 — Дом: пробег, обработка и фиксация одной связкой из окна

Статус: **принято** (2026-11-16; владелец: «со всем согласен» — запись флагом `--write`, порядок шагов как ниже). Миссия `docs/missions/pipeline.json`, Distance
«Аудит и ADR». Продолжает ADR 0006 (канон в проекте, сборка — сторона), 0007 (контейнер проекта), 0010 (законы ядра),
0014 (файлы и генераторы), NG-D002 (пробег), NG-D003 (слой приложения, фиксация).

## Контекст

Владелец (2026-11-16): связка «синхронизация → обработка → фиксация» (раньше «скан → конфликты → синк») — самая
большая и сложная часть Satellite. Пробег анализов и синхронизация сейчас идут через CLI и PowerShell; их нужно
оформить правильно и довести всю цепочку до окна стратегическими шагами. PHILOSOPHY: «Техпроцесс» (три фазы, каждая
владеет своей истиной), «Спутник» (моды меняет только фиксация), «Файлы» (правка — данные, исполняет фиксация).

## Аудит: что уже есть

Кирпичи почти все на месте и проверены тестами — не хватает **одного владельца связки** и окна над ней.

| Часть | Где | Состояние |
|---|---|---|
| Скан с кешем, пачками, отмена | `@sat:scan`, `@sat:scan.batched`, `@sat:scan.cache`, `@sat:scan.cancel` | готово |
| Статусы пробега, поколения, печати | `@sat:run` (`RunStatus`, `Authority`, `Staging`, `seal`) | в ядре; `Authority` не использует ни одна оболочка |
| Задачи: поколение, вытеснение, единые ворота публикации | `@sat:jobs` | в ядре; ни одна оболочка не использует |
| Сверка диска с проектом, решения переживают пробег | `@sat:sync.records.reconcile` | готово (исправлен дефект монолита §5 п. 1) |
| Ответы на записи командой, план запросом | `@sat:app.sync`, `@sat:app.sync.decide` | готово, но план окна — **неполный**: только канон и записи |
| План фиксации: канон, диск, установки, блокеры, свежесть записей | `@sat:sync.plan` | готово |
| Достройка плана: фабрики, патчи файлов, `plugins.txt` / `loadorder.txt`, проект «после» | `tools/sat-cli/src/commit_cmd.rs` (`factories`, `patches`, `plugin_files`, сборка `after`) | **живёт в оболочке CLI** |
| Исполнение: версия-бэкап, намерение, журнал, атомарная запись, откат | `@sat:mo2.commit` | готово, откат проверен на каждом шаге |
| Файл проекта: атомарное сохранение, чужое сохраняется | `@sat:stll.file.save` | готово |
| Пробег: инвентарь, импорт канона, скан, факты в проект, записи плагинов, сверка, правила | `sat-cli analyze` (`tools/sat-cli/src/main.rs` ≈ 600 строк) | **живёт в оболочке CLI** |
| Загрузка сборки в окно | `@sat:devserver.load` (≈ 300 строк) | **вторая копия пробега**, один раз при запуске, без сверки решений с проектом |
| Окно: записи SYNC, ответы, план | вкладка SYNC devserver | только просмотр; песочница ничего не пишет |

Отсюда пять разрывов:

1. **Пробег в двух оболочках.** `sat-cli analyze` и `devserver load` повторяют одно и то же разными словами
   (импорт канона, инвентарь, скан, сверка, плагины). Это второй владелец одной истины — нарушение закона 1 ADR 0010.
   Монолит болел тем же: SYNC precommit шёл surface-пробегом **мимо** ядра пробега (05-run §2 п. 0, 8).
2. **Достройка плана в оболочке.** Фабрики, патчи и файлы плагинов добавляются к плану в `commit_cmd.rs`, поэтому
   план в окне (`Query::Sync`) не равен плану, который исполнит CLI. Предпросмотр, не совпадающий с исполнением, —
   хуже, чем никакого.
3. **Окно не запускает пробег.** Пробег — только при старте devserver; нет стадий, прогресса, отмены, поколения.
   `@sat:run` и `@sat:jobs` есть, но не подключены.
4. **Обработка не сохраняется.** Решения, канон и декорации в окне живут в памяти; сохранить проект может только CLI.
5. **Фиксации из окна нет.** Нет ворот свежести «тот же пробег, та же ревизия проекта», нет повторной проверки после
   записи.

## Решение

### 1. Дом — один владелец связки (`sat-home`)

Новый крейт `crates/sat-home` (`@sat:home`) — «фиксация дома» из PHILOSOPHY: всё, что Satellite делает со **сборкой
на этой машине**. Над `sat-core`, `sat-scan`, `sat-mo2`, `sat-stll`; под оболочками.

- Владеет: открытием сборки (экземпляр + файл проекта), **пробегом** (стадии ниже), сборкой **полного плана**
  фиксации (то, что сейчас в `commit_cmd.rs`), исполнением фиксации, сохранением проекта.
- Не владеет: смыслом команд и запросов (`@sat:app`), планом как функцией (`@sat:sync.plan`), диском MO2
  (`@sat:mo2`), форматами.
- Код **переносится** из `sat-cli` и `devserver` (не копируется): обе оболочки становятся тонкими. `sat-cli analyze`,
  `sync`, `commit` и окно вызывают одни и те же функции дома — тогда CLI остаётся честным тестом окна.

`sat-app` не зависит от `sat-home` (ядро приложения без диска, ADR 0004): дом даёт приложению то, что нужно, через
узкий trait, как проводник получает диск через `FileSource`. Оболочка связывает их.

### 2. Пробег — задача с поколением

Один вход «пробег» (урок монолита: precommit тоже идёт через него):

```
обнаружение → поверхность (сигнатуры корней) → сверка (записи SYNC) → скан (кеш, пачками)
  → факты в проект → записи плагинов → конфликты → печати → публикация поколения
```

- Задача рода `run` (`@sat:jobs`): новая вытесняет старую, отмена между пачками, поздний результат не публикуется.
- Результат собирается в `Staging` (`@sat:run`) и публикуется **целиком** после печатей; сбой — поколение
  отбрасывается, окно продолжает работать на прежнем. Сломанный архив — деградация мода, а не отказ пробега
  (05-run §6, сознательное отличие от монолита).
- Режимы: «поверхность» (сигнатуры + сверка, секунды) и «полный». Поверхность — то же самое, что ворота свежести
  фиксации (п. 4).
- Окно показывает стадии, счётчики, время, отмену (контракт снимка пробега — `RunStatus` + счётчики стадий).
- Публикация в сессию — команда «новые факты» (`Change{Facts, All}`, закон 11 ADR 0010): канон, декорации и
  решения не трогаются; записи SYNC приходят слиянием, ответы сохраняются (`@sat:sync.records.reconcile`).

### 3. Обработка — команды над проекциями, проект сохраняется

- Всё, что пользователь делает в окне (ответы SYNC, порядок, декорации, решения по цепочкам, патчи, фабрики,
  намерения), — уже команды `sat-app`. Они меняют истину в памяти; у проекта появляется **ревизия** (счётчик
  принятых команд, меняющих истину проекта).
- **Сохранение проекта** — отдельная операция дома: `.stll` атомарно (`@sat:stll.file.save`), неизменившиеся факты
  копируются как есть. Окно показывает «не сохранено» по разнице ревизий.
- Сохранение проекта ≠ фиксация: проект — истина пользователя, сборка его не видит, пока не зафиксировано
  (ADR 0006). Автосохранения монолита не переносим (11-sync §4.8): сохраняем по команде и перед фиксацией.

### 4. Фиксация — план, предпросмотр, ворота, поколение, проверка, откат

1. **План** — функция дома над проектом и последним поколением пробега: `@sat:sync.plan` + фабрики + патчи +
   файлы плагинов + проект «после». Окно и CLI получают **один и тот же** план; предпросмотр = то, что исполнится.
2. **Ворота:** нет `pending` и блокеров; план построен на текущем поколении пробега и текущей ревизии проекта; перед
   исполнением — поверхностный пробег (п. 2) и сравнение: сменились папки или сигнатуры затронутых модов → план
   устарел, показать почему, перестроить.
3. **Исполнение** — задача рода `commit` через `@sat:mo2.commit` (версия, намерение, журнал, атомарная запись,
   откат). Во время фиксации команды, меняющие истину, отклоняются (один писатель, закон 9 ADR 0010).
4. **Проверка:** после записи — поверхностный пробег; ожидание — ноль новых расхождений, иначе отчёт. Успех
   закрывает записи и ставит в истории книги метку «зафиксировано» (а не стирает её, 11-sync §6 п. 5).
5. **Откат** — уже есть; окно показывает итог (`Committed` / `RolledBack` / `RollbackIncomplete` с журналом).

### 5. Песочница и запись

Devserver по-прежнему по умолчанию **песочница**: ничего не пишет, все кнопки записи видны, но недоступны с
объяснением. Запись (сохранение проекта и фиксация) включается **флагом запуска** (`--write`), который оболочка
показывает в шапке окна. Это вопрос владельцу (ниже), потому что меняет его правило «devserver — песочница».

### 6. Шаги (Distances миссии)

| Шаг | Что | Доказательство |
|---|---|---|
| 1. Дом | крейт `sat-home`; пробег и достройка плана переносятся из `sat-cli` / `devserver`; CLI ведёт себя как раньше | тесты, `sat-cli analyze/sync/commit` на тестовом экземпляре дают тот же результат, CI |
| 2. Пробег в окне | задача `run` с поколением, стадии, прогресс, отмена, «поверхность» / «полный»; публикация новых фактов в сессию | тест: поздний пробег не публикуется, сбой не портит поколение; скриншоты окна |
| 3. Синхронизация в окне | вкладка SYNC на поколении пробега: записи, ответы, свежесть; поверхность одной кнопкой | тест слияния ответов через два пробега в окне |
| 4. Обработка с сохранением | ревизия проекта, «не сохранено», сохранение `.stll` (за флагом записи) | тест: сохранили → открыли → то же |
| 5. Фиксация в окне | полный план в окне = план CLI, ворота, исполнение задачей, проверка, отчёт, откат | тест: план окна == план CLI; фиксация и откат на тестовом экземпляре |
| 6. Правки файлов в плане | правки ini и пресетов в окне → патчи → `DiskOp::Patches` в том же плане | тест: правка в окне → файл в Satellite Patches после фиксации |

Каждый шаг — своя Distance со своим контрактом; проверки на сборке владельца — пачкой после шагов 2, 3, 5.

## Последствия

- `sat-cli` теряет ≈ 600 строк пробега и ≈ 300 строк достройки плана, devserver — ≈ 300 строк загрузки; они живут в
  `sat-home` один раз.
- `@sat:run` и `@sat:jobs` перестают быть ядром без потребителя.
- Предпросмотр фиксации в окне становится точным; сейчас он не видит фабрик, патчей и плагинов.
- Окно с флагом записи меняет файлы сборки; без флага — песочница, как раньше.
