# ADR 0016 — Список как рабочая среда: дерево контейнеров и канон по индикаторам

- Статус: **предложено** (2026-11-02), идеи владельца; обсуждено, реализация — после ADR 0007 шаг 4
- Связано: ADR 0008 (декорации), 0010 (пересчёт по ключам), 0011 (расширения), 0012 (стили карточек), 0013
  (метки), 0014 (генераторы при фиксации), 0015 (карточка мода); `order::flow`

## Решение (направление)

### Канон по индикаторам
- Порядок загрузки читается по **индикаторам-переключателям**, не по контейнерам. В строке индикаторы стоят на
  **линии большинства**; меньшинство подтягивается к ней. Контейнер растёт вниз и вбок, индикатор — всегда на линии.
- Вид «порядок» (временно всё строгой линией) и сброс раскладки — всегда в одну клавишу.

### Контейнер мода
- По умолчанию **однострочный на всю ширину**: индикатор слева → бейджи → имя → счётчики. Индикатор и бейджи видны
  всегда; имя урезается при коллизии; счётчики растут влево. Минимальная ширина = индикатор + бейджи + счётчики +
  минимум имени; остаток строки распределяется между контейнерами (как в монолите).
- Многострочный вид (монолит): индикатор слева сверху, имя по центру, счётчики справа снизу.
- **Теги** — полоски по контуру: от центра низа в обе стороны поровну до центра верха; форма не важна (позиция —
  доля периметра). Замкнулся круг — следующий внутри; **не больше двух кругов**, дальше «+N». Имя тега — по
  наведению и в карточке (цвет — не единственный носитель смысла).
- **Стикеры** — не рядом с бейджами. Вариант: ярлычки на верхней грани справа, лишние — «+N». **Не решено**
  (владелец не уверен) — смотреть вживую.

### Дерево контейнеров
- Окно, разделители, лог-группы — узлы одного дерева; порядок загрузки = обход в глубину; плоский канон —
  проекция дерева. MO2 получает плоскую проекцию: **лог-группа в `modlist.txt` — полноценный разделитель**; после
  группы внутри разделителя фиксация ставит продолжение внешнего разделителя («Броня (продолжение)»), иначе MO2
  отнесёт оставшиеся моды к группе.
- Договоры узла: **строгий** (окно, разделитель — позиция = порядок) и **свободный** (лог-группа — подпространство:
  раскладка любая, порядок — внутренний счётчик на индикаторе). В свободном: тащишь контейнер — меняется раскладка;
  тащишь индикатор (или режим «порядок») — меняется порядок.
- Лог-группа — три вида: **свёрнутый** (одна позиция и декорация, как мод), **развёрнутый** (своя рамка, внутренние
  позиции и декорации), **обводка** (только выделение своих модов, строй не меняется; моды идут подряд).
  Декорация хранится по паре «сущность + вид».
- Роль узла: нет (папка) / результирующий мод / **фактори** — генератор при фиксации с параметрами (ADR 0014).
  Пример владельца: фактори костюмов AddItemMenu — ужать то, что редко читается (реальный выигрыш — даунскейл и
  пережатие текстур; сжатие BSA SSE — только LZ4, DDS уже сжаты).
- Раскладка «хозяин + спутники»: большой фреймворк, справа колонка его аддонов (SLAL, RaceMenu…); порядок чтения
  блока задан явно (хозяин, затем спутники сверху вниз), номер — на индикаторе.

### Вспомогательные элементы
- Элементы без индикатора в списке, вне порядка: виды по выбранным модам (победитель вкусового выбора — NIF-вьювер),
  свои чек-листы (проверка BOS), сводки семейств («обнаружено 32 мода 3BA, 2 UBE»), диаграммы. Содержимое — запросы
  к ядру, лениво и только видимое; тяжёлые — изолированно (поток, фрейм). Это виды-расширения ADR 0011.

### Скорость
- Раскладку считает ядро (развитие `order::flow`), окно только рисует; пересчёт по блокам (закон 11); рисуется
  только видимое (пул элементов); ширины имён кешируются, цифры счётчиков моноширинные.
- **Запас пустого места перед разделителями**: глазам легче, а рост контейнеров внутри запаса ничего ниже не
  двигает; кончился — нижние блоки сдвигаются на величину (смещение, не новая раскладка).

## Сделано

- Шаг 1, первая часть (2026-11-02): `order::card` — однострочный контейнер (индикатор → бейджи → имя → счётчики;
  индикатор и бейджи целы, счётчики держат правый край и растут влево, при нехватке места выталкиваются раньше,
  чем имя уйдёт ниже минимума; минимальная ширина). Раскладка flow: **линия индикаторов** — верхние отступы карточек
  строки голосуют, все карточки строки берут отступ большинства (`Placed::dy`); **запас блока** —
  `FlowParams::reserve`: высота блока = естественная + запас, округлённая вверх до кратной ему, так что небольшой
  рост карточки обычно ничего ниже не двигает. Окно применяет `dy`; однострочный вид по умолчанию в окне — вместе
  с владельцем.

- Шаг 2, первая часть (2026-11-02): **вложенность разделителей** — дерево записано в самом порядке, без второй
  структуры: у разделителя есть уровень, разделитель уровня `n` держит следующие разделители уровня выше `n`
  (как заголовки в оглавлении). Порядок загрузки не меняется вовсе — уровень это декорация (`Decor::levels`, по id
  в проекте); MO2 видит обычные разделители, **продолжение внешнего разделителя не нужно**: свои моды разделителя
  идут до вложенных, по устройству записи. Свёрнутый разделитель прячет всё, что держит (и вложенные
  разделители); перенос разделителя переносит поддерево; глубина строки = уровень (мода — уровень его
  разделителя + 1); размер — всё поддерево. Модельный тест (поток патчей = полный пересчёт) прогнан с уровнями на
  300 зёрнах. Команда `SetLevel`, в окне — «Вложить в разделитель выше / Вынести».
- Шаг 2, вторая часть (2026-11-02): **лог-группа — один результирующий мод в анализе** (`@sat:overwrite.units`):
  участники отображаются на представителя (первого участника); путь, общий только участникам, — не конфликт;
  против остальных группа — одна единица стека (цепочки, контексты, счётчики, X); участник, поглощённый группой,
  не бывает «X» сам по себе; сводка участника показывает конфликты его группы, плагины — свои. Подписи в окне —
  имя группы (`Session::unit_label`). Пересчёт — инкрементальный (только пути затронутых модов), на новом виде
  истины `Groups` (операции групп), а не на каждой декорации. `sat-cli analyze` считает так же.
- Шаг 2, третья часть (2026-11-02), по определению владельца (PHILOSOPHY «Лог-группа: подпространство с одним
  лицом»): **инкапсуляция строгая** — за группу стоит участник с наименьшим id таблицы, перестановка внутри его не
  меняет; ключ группы в подписях цепочек — её стабильный id (`lg:<id>`), так что решения по цепочкам с группой не
  зависят от того, кто её представляет и что внутри переставили; перестановка внутри меняет только результат
  (какой файл выигрывает) — наружу уходят лишь байты/VRAM победителя, цепочки и контексты снаружи не трогаются;
  собственные (одиночные) пути участников — тоже результат группы (группа больше не получает ложный X).
  **Внутренность группы** — `@sat:overwrite.inside`, `Session::group_inside`, `Query::GroupInside`: конфликты
  участников между собой, скрытые снаружи. **Ещё нет:** виды «развёрнутый со своей раскладкой» и «обводка»;
  роли «запечь и запечатать» и «живая фабрика» — сделаны (ниже).
- Роли (2026-11-02): `FactoryMode::Live` — пересборка при изменении группы, участники остаются; `Seal` — запечь
  один раз и запечатать: участники уходят в `deleted/`, группа и фабрика выходят из проекта. Запечатывание
  (решение владельца: рискованно, без возврата следующей фиксацией) **требует подтверждения по имени**: фиксация
  стоит с `NeedsConfirmation`, пока не дан `--confirm "ВЫХОД"`. Проверено на копии сборки.

## Порядок работ (набросок)
1. Модель в ядре: контейнер с линией индикаторов, однострочная упаковка, запас блока.
2. Дерево контейнеров в книге порядка; плоский канон — проекция; продолжение разделителя при фиксации.
3. Виды лог-группы и роли узла; фактори — через генераторы ADR 0014.
4. Окно — вместе с владельцем.
