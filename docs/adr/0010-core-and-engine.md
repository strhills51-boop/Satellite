# ADR 0010 — Ядро и движок Satellite: истина, команды, проекции, виды, ресурсы

- Статус: **принято** (2026-10-31), направление владельца: «истина одна, проекций много» (старый Satellite)
- Сводит: ADR 0002 (ярусы), 0006 (канон в проекте), 0007 (контейнер), 0008 (порядок), 0009 (виды и пространства),
  конспекты `docs/semantic/monolith/`, `docs/semantic/old-satellite/` (`BORROW.md`)
- Семантический слой этого решения — `docs/semantic/MAP.md` (раздел «Ядро и движок») и якоря `@sat:` в коде

## Зачем

Монолит — пример того, что бывает без формального ядра: каждый слой заново изобретал сверку истины и
представления, функции переопределялись поверх себя. Старый Satellite нашёл правильные принципы, но держал их
на соглашениях внутри одного JS-объекта. NG фиксирует их как **типы, владельцев и проверки**: нарушение должно
быть ошибкой компиляции, теста или CI, а не стилем.

## Словарь (одно слово — одно понятие)

| Понятие | Определение | Владелец в NG |
|---|---|---|
| **Истина** | То, что нельзя вычислить, — только принять или наблюдать. Пять видов: **канон**, **декорации**, **факты**, **решения**, **настройки** | по виду, ниже |
| Канон | Порядок, вкл/выкл, разделители, состав списка (что уходит в менеджер) | `order::OrderBook` (живой), `canon::Modlist` (снимок) |
| Декорации | Пользовательская разметка поверх канона, никогда не меняющая порядок: цвет, группы, приглушение, свёртка | `order::OrderBook` (decor), `order::decor::Decor` (хранение) |
| Факты | Наблюдения о мире: что лежит на диске и в архивах, заголовки форматов | `sat-scan` → `facts::ModFacts` → `table::ProviderTable` |
| Решения | Выбор пользователя по расхождениям и конфликтам: статусы записей SYNC, разрешения | `sync::records`, `project::Project` |
| Настройки | Конфигурация пробега, ресурсов, политики | реестр ресурсов (будущий) |
| **Команда** | Единственный способ изменить истину. Проверяется политикой, применяется владельцем истины, возвращает **набор изменений** | владелец соответствующей истины |
| **Набор изменений** | Что именно изменилось в истине: вид истины + ключи (или «всё») | `engine::Change` |
| **Проекция** | Чистая функция истины и других проекций с объявленными входами. Не хранится, пересчитывается | `engine::Graph` (регистрация), владелец функции — свой модуль |
| **Вид** | Проекция для одного окна: область, фильтр, свёртка, курсор, строки; изменения — патчи строк | ADR 0008 / 0009 |
| **Событие** | Уведомление, что что-то произошло. Не владеет истиной | канал движка |
| **Ресурс** | Всё, что расширяет Satellite: род окна, команда, клавиша, анализатор, проекция, пресет. Регистрируется через манифест | реестр ресурсов (будущий) |
| **Задача** | Долгое выполнение (пробег, фиксация): очередь, отмена, прогресс, поколение | `run` + задачи NG-D003 |
| **Поколение** | Версия результата задачи; публикуется целиком после печатей или не публикуется вовсе | `run::Authority` |

## Законы ядра

1. **Истина одна.** У каждого вида истины ровно один владелец в коде; второй владелец того же — ошибка (карта
   `MAP.md` + CI).
2. **Изменение — только командой.** Команда не рисует, не пересчитывает проекции и не шлёт патчи сама: она
   изменяет истину и возвращает набор изменений.
3. **Проекции чистые и объявляют входы.** Проекция читает только свои входы, ничего не пишет; граф проекций
   ацикличен (проверяется при регистрации).
4. **Инвалидация — граф, а не автор команды.** По набору изменений движок помечает грязными зависимые проекции
   (транзитивно, в топологическом порядке). Автор команды не перечисляет, что перерисовать (в отличие от
   `invalidate: [...]` прототипа).
5. **Один пересчёт на такт.** Изменения копятся; на такте пересчитываются только грязные проекции, нужные
   кому-то (вид на экране, подписчик, печать). Остальные остаются грязными до запроса (ленивость).
6. **Виды получают патчи.** Строки видов меняются патчами (ADR 0008); вид за кадром копит «грязно» и
   перечитывает окно строк при показе (ADR 0009).
7. **Хранение ≠ runtime.** Хранится истина (и сводки фактов в холодном ярусе); проекции, виды, кеши строк — нет.
8. **Идентичность — id.** Сущность имеет устойчивый id; имя — атрибут. Сейчас проект хранит декорации и
   сигнатуры по именам — это переходное состояние до контейнера (ADR 0007): там у сущностей появятся
   устойчивые id, а имена станут атрибутами (переименование = изменение атрибута + запись SYNC).
9. **Один писатель, много читателей.** Истину меняет один поток движка (команды сериализованы); читатели
   (проекции на пуле, UI, API) получают неизменяемые снимки (`Arc`). Тяжёлые проекции и пробеги — задачи с
   поколениями: результат применяется только если истина, на которой он посчитан, не устарела.
10. **Расширение — ресурс.** Новая возможность входит только через манифест → реестр → политика → runtime.
    Встроенное регистрируется так же, как расширения. Доверие задаёт источник загрузки, а не id; возможности
    выдаются ресурсу, а не проекту; одобрение хранится на машине пользователя, а не в проекте (уроки прототипа).

## Движок: цикл

```
команда ──► политика ──► владелец истины ──► Change{вид, ключи}
                                                    │
                     граф проекций: грязные = зависимые от Change (транзитивно)
                                                    │
такт:  нужные грязные проекции (видимые / подписанные / для печати) пересчитываются по топологии
                                                    │
               виды: патчи строк (на экране) │ флаг «грязно» (за кадром) ──► UI
                                                    │
                                     события (журнал, отладка, расширения)
```

Первая часть, которая реализуется кодом, — **граф проекций** (`sat-core::engine`): регистрация проекций с
входами, проверка ацикличности, топологический порядок, транзитивная инвалидация по `Change`, ленивое «что
пересчитать для этих потребителей». Владельцы истины (книга порядка, проект, таблица) возвращают `Change`;
книга порядка уже отдаёт `Change` в `order::Change::truth` (2026-11-01, вместе с выносом вида — ADR 0009,
шаг 1); проект и таблица — следующие.

## Масштаб (бюджеты не меняются, PHILOSOPHY)

Десятки тысяч модов, сотни миллионов файлов в сумме: истина в столбцах и целых id; проекции инкрементальные
или ленивые; виды — только окно строк; холодный ярус хранит сводки, а не сырые маршруты.

## Семантический слой (обязательная часть ядра)

Семантический слой — это не документация «для людей потом», а **указатели и якоря для агента**, проверяемые CI:

1. **Заголовок модуля.** Каждый `.rs` начинается с `//!`-заголовка: первая строка — что это, с якорем модуля
   `@sat:<id>`; строка `Owns:` — понятия, которыми файл владеет единолично; при необходимости `Not here:` —
   где живёт близкое, чтобы не написать второй раз.
2. **Якоря блоков.** Ключевые типы и функции, на которые ссылается карта, помечаются `// @sat:<id>` (или в
   их `///`-документации). Id — точечный путь (`order.book.move`), уникален во всём репозитории.
3. **Карта** `docs/semantic/MAP.md`: понятие → якорь → файл; «не путать с». Каждый якорь кода есть в карте,
   каждый якорь карты есть в коде ровно один раз, каждый `.rs` имеет якорь модуля и строку `Owns:`.
   Определение якоря — первая строка заголовка модуля или строка из одного `// @sat:<id>`; любое другое
   упоминание (например, в `Not here:`) — ссылка, и CI проверяет, что она ведёт на существующий якорь.
   Проверка — `tools/check-map.sh` в CI.
4. **Конспекты эталонов** (`docs/semantic/monolith/`, `docs/semantic/old-satellite/`) — откуда пришла идея и
   какой дефект не повторять.
5. **Правило изменения:** нет понятия в карте — добавь строку и якорь в том же коммите; есть владелец — расширяй
   его. Обёртка «старое + новое» поверх существующей функции запрещена.
