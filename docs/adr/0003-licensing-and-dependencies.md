# ADR 0003 — Лицензия проекта и политика зависимостей

- Статус: **предложено, ждёт решения владельца**
- Связано: PHILOSOPHY §5 «Этика и право», Фаза 5 (сервис, датасет, авторы)

## Контекст

- Проект будет открытым ядром для сообщества, с будущим сервисом и датасетом.
- Готовые библиотеки экосистемы Bethesda под **GPL-3.0**: `esplugin` и `libloot` (команда LOOT).
  Их подключение делает GPL-3.0 обязательной для всего клиента.

## Решение (предлагается)

1. Код клиента и ядра — **MPL-2.0** (свободная копилефт-лицензия на уровне файлов: правки ядра остаются открытыми,
   но расширения и встраивание в другие продукты возможны). Альтернатива — `MIT OR Apache-2.0`.
2. Зависимости ядра — только permissive-лицензии (MIT / Apache-2.0 / BSD / Zlib / MPL-2.0).
   GPL-зависимости запрещены, пока лицензия не выбрана иначе.
3. Поэтому разбор TES4/BSA/BA2/DDS — **собственный** (`sat-formats`), спецификации форматов публичны (UESP, xEdit docs).
4. Датасет знаний (Фаза 5) — отдельная лицензия данных (например, CC BY-SA 4.0), решается позже.
5. CI проверяет лицензии зависимостей (`cargo-deny`).

## Открытые вопросы к владельцу

- MPL-2.0 или MIT/Apache-2.0?
- Нужна ли совместимость с LOOT-данными (их masterlist под CC BY-NC-SA — некоммерческая)?
