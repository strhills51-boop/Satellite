# ADR 0001 — Ядро на Rust, оболочка Tauri, интерфейс Svelte

- Статус: **принято** (2026-10-30)
- Связано: PHILOSOPHY §5 «Инженерные принципы», §8 Фаза 0

## Контекст

- Монолит (HTML/JS) упёрся в физику: один поток, IndexedDB, строки на каждый путь.
- Прототип v0.1 на Go (`prototypes/go-spike`) доказал модель данных: 2,9 млн файлов, 0,1 с на пересчёт конфликтов, ~0,5 ГБ RAM.
- Долгосрочная цель — сайт-сервис, где ядро может работать **в браузере** (WebAssembly), и нативный клиент для тяжёлых сборок.

## Решение

1. **Ядро — Rust** (edition 2024, stable).
   - Один код для нативного exe и для `wasm32` с настоящими потоками (`rayon` + SharedArrayBuffer).
     У Go в WASM нет многопоточности.
   - Детерминированная работа с памятью: колонки, интернер, mmap для холодного яруса.
2. **Нативная оболочка — Tauri v2**: окно приложения, родные диалоги, без ограничений браузерного FS API.
3. **Интерфейс — Svelte 5 + TypeScript + Vite**, один и тот же для Tauri, dev-сервера и будущего сайта.
4. **Dev/headless-оболочка** — HTTP + WebSocket сервер на том же API (ADR 0004). Нужна для Playwright-тестов
   паритета, CI без GUI и будущего локального MCP.
5. Go-прототип замораживается как эталон для сверки результатов (`prototypes/go-spike`), новых фич в нём нет.

## Последствия

- Windows-сборки Rust делает CI (GitHub Actions, windows-latest): в среде разработки агента недоступна
  стандартная библиотека Rust для Windows. Локально — Linux, тесты и бенчмарки.
- Tauri под Linux требует webkit2gtk; локальные UI-тесты идут через dev-сервер (п. 4).
- Порог входа для контрибьюторов выше, чем у JS. Компенсируется тем, что расширения пишутся
  не на Rust, а как WASM-модули на любом языке (Фаза 3.5).

## Отвергнутые варианты

- **Go**: отличный нативный рантайм, но слабый WASM (без потоков) — закрывает дорогу «сайт = инструмент».
- **Чистый браузер (как монолит)**: FS Access API медленный на миллионах файлов, только Chromium, нет фоновой работы.
- **Electron**: тяжёлый рантайм, Node-бэкенд без выигрыша по сравнению с Rust.
