# ADR 0006 — Канон в проекте, сборка как сторона синхронизации

- Статус: **принято** (2026-10-30)
- Заменяет: строку «Канон» в ADR 0002
- Связано: PHILOSOPHY §4 «Слои истины», монолит: слой SYNC (`createEmptySyncState`, `buildSyncReconcileResult`,
  `buildSyncCommitPlan`), внешние доноры (`ExternalDonorSession`)

## Контекст

В ADR 0002 канон (порядок, вкл/выкл, разделители) читался из `modlist.txt` адаптером `sat-mo2`.
Это модель MO2, а не монолита. Первый прогон `sat-cli` на реальной сборке показал, что она неверна на практике:
активный профиль описывал 1 118 модов, все выключены, а в папках модов на диске их тысячи.

Владелец уточнил: **`modlist.txt` — не истина.** В монолите пробег анализов — это прежде всего синхронизация
реальной сборки с проектом. Как это устроено в коде монолита:

1. Пробег читает **все папки** в каталоге модов (`readModsEntriesFromHandle`), а не строки `modlist.txt`.
2. Поверхностная стадия считает сигнатуру каждой папки (`surfaceSignature`) и сравнивает её с прошлой:
   `unchanged / changed / new`.
3. Сверка (`buildSyncReconcileResult`) сопоставляет папки с сущностями **проекта** (разделители + моды) и создаёт
   записи синхронизации:
   - `fs_created` — папка есть на диске, в проекте нет;
   - `fs_deleted` — сущность есть в проекте, папки нет;
   - `fs_rename_candidate` — имя другое, но сигнатура совпала ровно с одним кандидатом;
   - со стороны проекта: `project_created / project_deleted / project_renamed / project_modlist_reordered /
     project_restored`, плюс `external_migration_pending` для переноса из донора.
4. У записи есть статус (`pending / confirmed / ignored / resolved`) и решение. Пока хоть одна запись в `pending`,
   фиксация заблокирована.
5. Записи видны пользователю как прокси-моды в служебном разделителе «SYNC / Синхронизация» (всегда первый).
6. Фиксация — это план операций (`buildSyncCommitPlan`): workspace `profiles/<p>/monolith/`, версия с копиями
   `modlist.txt` (и по флагу `plugins.txt` / `loadorder.txt`) и `project.before.json`. Удаление — это перенос
   в `deleted/<время>`, а не стирание. Перед фиксацией идёт pre-commit проверка с отпечатком набора записей.
7. Внешний донор — отдельная сессия: чужой `modlist.txt` + папка модов. Её кандидаты переносятся в проект
   записями миграции.

## Решение

### Слои

| Слой | Где живёт | Кто пишет |
|---|---|---|
| Факты сборки | `sat-core::facts` + инвентарь папок (`DiskInventory`) | только сканер |
| **Канон** | **проект Satellite**: `sat-core::canon` (разделители, моды, порядок, вкл/выкл) | команды пользователя |
| Сторона менеджера | снимок файлов MO2 (`modlist.txt`, `plugins.txt`, `loadorder.txt`, `meta.ini`) | только адаптер `sat-mo2` при чтении |
| Синхронизация | `sat-core::sync`: записи расхождений и их решения | сверка (создаёт), пользователь (решает) |
| Намерение / Знание / Представление | как в ADR 0002 | как в ADR 0002 |

- **Сверка — чистая функция** `reconcile(project, inventory, previous_signatures, planned) -> Vec<SyncRecord>`
  в `sat-core`, без I/O. Её можно проверить тестами на таблицах и запускать в WASM.
- Записи идемпотентны: их ключ — отпечаток `(тип, сущность, имя)`, как в монолите. Повторный пробег обновляет
  запись, а не плодит дубли.
- Переименование распознаётся по сигнатуре **содержимого** папки. Имя самой папки в сигнатуру не входит
  (в `sat-scan::signature` это уже так).
- Стороны: `project` ↔ `disk` (папки `mods`) ↔ `manager` (`modlist.txt` профиля).
  Расхождение «проект ↔ modlist» — тоже запись (порядок, вкл/выкл). Тихой подмены нет ни в одну сторону
  (урок `pendingOrder` из NG-D001).
- **Фиксация** — `Plan` из операций (`mkdir`, `backup_file`, `move_to_deleted`, `rename`, `rewrite_modlist`, …)
  → pre-commit проверка (отпечаток записей + свежесть пробега) → бэкап → применение → журнал.
  Пока есть `pending`, фиксация заблокирована. Удаление всегда означает перенос в `deleted/`.
- Первое открытие сборки без проекта — это **импорт**: проект строится из `modlist.txt` и папок, а всё,
  что не сошлось, сразу становится записями синхронизации.
- **Экземпляр — одна папка `mods`**, как в MO2 и монолите (плюс профиль и `overwrite`). «Дополнительных корней»
  нет: любая другая папка с модами — это **внешний донор**.
- Внешний донор — сессия: `modlist.txt` донора (необязателен) + папка модов донора. Правила монолита
  перенесены 1:1 в `sat-core::sync` (`names`, `donor`):
  - ключи имени: raw (нижний регистр), norm (`normalizeName` + `se`/`ae` → издания), loose (без изданий,
    версий `v1 2` и серий чисел). Сверено с JS монолита на 1 128 реальных именах: **0 расхождений**;
  - поиск папки для строки modlist: сначала точное имя, затем любой ключ;
  - соответствие донора проекту: `exact` (общий ключ) / `contains` (norm или loose содержат друг друга, оба ≥ 5 символов)
    / `donor_only` / `folder_missing`;
  - категории: `ready` / `exist` / `similar` / `missing` / `folder_only`;
  - пригодность папки к modlist: `score = round((recall · 0,65 + precision · 0,35) · 100)`, ≥ 80 — ok, ≥ 50 — warn.
  Кандидаты попадают в проект только через записи `external_migration_pending` и черновики в целевом разделителе.
  **Пробел монолита:** физический перенос донорских папок в план фиксации не входил (`contract-gap` в его
  карте действий) — в NG это операция плана (`move_from_donor`) с бэкапом.

### Пробег

Пробег сканирует **все папки `mods`**. Кеш сканов и сигнатуры остаются ключом на уровне папки.
Приоритеты для перезаписи берутся из **проекта**; моды на диске, которых нет в проекте, сканируются, но в перезапись
не входят, пока запись `fs_created` не решена.

## Последствия

- ADR 0002: строка «Канон … пишет только manager adapter» заменяется этой моделью.
- NG-D002 (конвейер пробега) получает сверку и импорт проекта; NG-D003 — решения по записям и план фиксации.
- UI (NG-D004+): служебный разделитель SYNC с прокси-модами и кнопками решений, как в монолите.
- `sat-cli analyze` по умолчанию сканирует все папки `mods` и печатает инвентарь сторон
  (`--listed-only` — только моды из `modlist.txt`); `--extra` удалён.
- `sat-cli donor <instance> --mods DIR [--modlist FILE]` — сессия донора против профиля экземпляра
  (профиль временно заменяет проект до NG-D002).
