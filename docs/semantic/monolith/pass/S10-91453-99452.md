## 1. Обзор
Сегмент почти целиком — **презентационный слой эффектов** (область 17) плюс сводка/мета (20) и классическая карточка мода (18). ### Спорные места и вероятные ошибки
1. `matchesBadgeHeaderFilterV481` возвращает **true**, пока коллекция не загружена: фильтр шапки по контексту/цепочке на мгновение показывает всё, потом сужает (мигание; у пользователя впечатление «фильтр не сработал»). В NG — состояние «загрузка» вместо «совпадает».
2. `finalizeBadgesMetaCollectionV482` пишет identity обратно в `chain.raw` (RAM-цепочки проекта) — побочный эффект чтения; может «перекрашивать» цепочки в модалке конфликтов после открытия меты.
3. `loadBadgesMetaCollectionV480` (IDB) — до 700 последовательных await `getOverwriteChainPreview`: медленно на больших сборках; нет батча.
4. Пороги «общих тегов» разные: .58 (снимок v433 / arkanoid-cracks), .62 (Aura v3 v441), .44 (Field). Вероятно намеренно, но в NG держать как именованные константы режима.
5. Ключи рецептов дублируются строками в 3 местах (`getTagPatternRecipeKeyV436`, `collectTagPatternCompositeEntriesV436`, `primeTagPrimaryAssetsV444`) — правка одного ломает кэш тихо.
6. Компоновщик v445 drawImage-only: на холодном кадре stripes/cracks не рисуются вовсе до запекания (кадр-«вспышка»).
7. `scheduleClassicModGridPocketPullUp` держит **один** rAF на `state`: два вызова подряд с разными контейнерами (например, разные секции разделителей в `renderClassicModsChunkedInto`) — первый контейнер теряется до следующего вызова. Возможная причина «не подтянутых карманов» в секционном виде.
8. `refreshOverwriteBadgeEffectDomV364` делает точечные DOM-патчи и сразу `renderAllPreserveScroll()` — двойная работа.
9. `openCollectionEditor` правит коллекцию по месту: «Закрыть» не откатывает добавленные/удалённые строки (они остаются в памяти и уйдут в следующий autosave); нет истории. Имя тега в редакторе тегов не экранируется (`<span class=pill>${tag.name}</span>`, только `"` в value).
10. `openSeparatorDecorationModal` выставляет `state.__separatorDecorationModalActive` только на время построения DOM — обработчики полей модалки видят прежнее значение; если поведение полей зависит от флага (выбор целевых разделителей), модалка может применять изменения к текущему выделению окна. Здесь это нейтрализовано тем, что выделение принудительно ставится = этот разделитель.
11. `colorFocus`: MutationObserver на весь body + полный проход всех карточек с `findModById` на каждом rAF после любой смены class — дорого на 2 TB-сборке (тысячи карточек).
12. `runEnabledCustomRuns`: `new Function` с полным `state.project` — пользовательский код может портить проект; уникальность имён через `includes` O(N²); последовательное чтение дерева каждого мода из IDB.
13. `renderModsHeaderContent` 92647 мёртв (см. §3) — не переносить его семантику (одиночный `tagFilter.value`); живая — мультифильтры v479.
14. Резонанс считает популяцию по **всей доске**, а Aura/Field — **по разделителю**; это разные «контексты редкости». Сохранять в NG.
