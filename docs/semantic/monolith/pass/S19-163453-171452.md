## 1. Обзор

Сегмент — стык двух миров. До **166 057** идёт хвост главного IIFE приложения (открыт на 19 456): последняя обёртка `renderAll`/`renderClassic` (v147), ворота старта после восстановления autosave, графовая идентичность v476–v478 (логические группы, цепочки и контексты overwrite получают имена/цвета из контекста Project Relation Graph, очередь миграции с записью в IDB, явный перерасчёт), аудит графа v477, пассивный инвентарь ядра пробега **Run Kernel recovery CP1** (карта владельцев состояния, побочных эффектов, границ коммита, фикстура сигнатуры) и диагностика кэшей конфликтов v683–v691. После **166 057** код живёт на **верхнем уровне скрипта, вне замыкания приложения**: console-help v254 (+ сломанный мост PHONE CP6), тень идентичности v475, поздние публикации фасадов `window.ProjectRelationGraph` / `__projectRelationGraphApi` / `__projectIdentityApi` (v476 → v560 → v477), и модули **Analysis Orchestrator v503 CP1–CP7 полностью и начало CP8**: базовая линия старого пробега, словарь сущностей и контрактов, ядро с ограниченными очередями и барьерами, транзакционные поколения (staging → promote/abort), теневой планировщик RouteSource, единый обход свободных файлов, динамические источники BSA/BA2, потоковые агрегаты. Модули вне IIFE видят приложение **только через `window.*`-мосты** (`ModlistToolAnalysisStorageRuntimeV503`, `ModlistToolAnalysisRuntimeInputsV503`, `modlistToolPathStorage`, `ModlistToolArchiveEntrySizeAuthorityV555`, `ModlistToolExactCounterFactsV602`, `ModlistToolPathTopologyProfileV607`); каждое прямое обращение к имени из IIFE (`state`, `buildAnalysisSignature`, `normalizeAnalysisPath`…) там либо падает, либо молча уходит в fallback — это главный источник расхождений, найденных в этом сегменте.

## 4. Для NG

### Переносить как правила
- **Модель поколений (CP4)** — почти 1:1 в `sat-core`: запись `{projectId, runId, previousRunId, status ∈ staging|authoritative|aborted, createdAt, updatedAt, commitReadyAt, promotedAt, abortedAt, abortReason, promotionError, authorityPatch, metadata}`; promote разрешён только из staging при `runtime.canCommitReady()`; **оптимистическая проверка предка** (текущий авторитет == previousRunId, иначе «explicit rebase»); первое поколение не может заменить существующий авторитет без явного флага; promote не имеет права менять SYNC (сравнение до/после); при ошибке persist — откат указателя + компенсирующая запись + статус обратно staging с `promotionError`; abort запрещён для авторитетного; при переключении удаляются указатели, ссылающиеся на previousRunId.
- **Ядро (CP3)**: `canCommitReady = !failed && !cancelled && нет очередных/активных источников && пусто в наблюдениях && нет очередной/активной работы && пусто в route-writes && нет открытых токенов барьеров`. Политики сбоя: mandatory → фаза failed + отмена всего пробега с причиной `mandatory analyzer <id> failed: stage=… · observation=…`; degraded → warning + событие; optional → warning. Анализаторы диспатчатся **в порядке регистрации**, результат анализатора строго `{facts, sources, work, warnings}`.
- **Барьер `routes.complete` (CP7)**: токены physical-root, storage-flush и по одному на каждый архив; барьер закрыт, когда закрыты все токены; сбой архива закрывает свой токен со `status:'error'` и **не** валит прогон (деградация). В NG — явный счётчик «ожидаемых источников» и join-точка перед финализаторами.
- **Слияние метаданных пути (v554, 169794)**: loose побеждает архив; два архива одного пути → `archive-ambiguous` без размера; разные источники → `ambiguous` с сохранением совпадающих полей; счётчики sourceCount/shadowedSourceCount. Это прямой предок правила «кто владеет виртуальным путём внутри мода».
- **Роли маршрутов**: `content-file`, `archive-container` (сам .bsa/.ba2 как файл), `archive-entry`; «эффективное содержимое» = content-file + archive-entry (контейнеры исключены); покрытие размеров `round(known·10000/count)/100`; `archiveEntryBytes = null`, если хоть один размер неизвестен.
- **Идентификаторы**: sourceId мода `route-source:mod-folder:${fnv2(projectId\0mod)}`, архива `route-source:archive-bsa|ba2:${fnv2(projectId\0mod\0path)}`; хэш = двойной FNV (`h1` FNV-1a 32, `h2 = imul(h2^c, 2246822507)+i`) в base36 — если NG хочет сверяться с IDB монолита, формулу надо воспроизвести точно.
- **Детекторы тегов (CP8)**: группы `{path,file,plugin,name,folder,root,ext} + all[] + none[]`; `folder/root/ext` — точное сравнение (lower), остальные — подстрока или шаблон `*` (без якорей); совпадение = (нет позитивов ИЛИ хоть одно поле) И все `all` И ни одного `none`; стикеры исключены из списка разрешённых тегов.
- **Инварианты печатей** как проверки перед публикацией (CP1 Run Kernel, 165689): promote только при complete staging + witness commit-ready + conflict parity + no archive failure (последнее — **в противоречии** с деградацией архивов в CP7; см. ниже).
- **Идентичность (v476/v478)**: входная подпись сущности (163637) — готовая формула «когда пересчитывать имя»; ручные поля (`locks.name/color/icon`, `generated:false`) не трогаются перерасчётом; принудительный пересчёт = порча `sourceFingerprint` префиксом. Для NG: явный `identity_input_hash` и правило «залоченное не регенерируется».

### Спорные места и вероятные ошибки
1. **Регистр путей.** CP7/CP8 вне IIFE не видят `normalizeAnalysisPath` и используют fallback **с `toLowerCase()`** (170442, 171336), тогда как legacy `normalizeAnalysisPath` (113557) и CP6-fallback регистр сохраняют. Живой staging (CP7 → `PathStorage.writeModPaths`) пишет пути в нижнем регистре; legacy-поколения — в исходном. Сравнение поколений reuse/indexed, паритет с legacy и конфликты по точному пути могут расходиться. В NG: одна каноническая нормализация (вероятно, case-insensitive ключ + исходное написание для показа).
2. **Сигнатура поверхности в CP6** (169743): `buildAnalysisSignature` недоступен → `surface_shadow_v1_${hash(JSON)}` вместо `Alpha|4|…`. Если какой-то путь берёт `surfaceSignature` из манифеста CP6 и сравнивает с legacy — всё станет `changed`. В живом CP7-пути `surfaceSignature` в `completeMod` не передаётся (манифест без неё; `writeModPaths(..., surfaceSignature: '')`).
3. **CP6 `consume` ссылается на `ARCHIVE_EXTENSIONS_V503`, которого в области CP6 нет** (170016; объявлен только в CP7 170412 и CP8 171315) → ReferenceError на первом файле → mandatory-сбой → отмена. Самотест CP6 (`window.modlistToolAnalysisOrchestratorCP06SelfTestV503`) почти наверняка `ok:false`. Живой путь CP6-обход не использует (CP7 имеет свою копию анализатора), но `createPathStorageSink`/`createMemorySink` из CP6 используются.
4. **Сломанные ссылки вне IIFE:** `ModlistToolPhoneBridgeV1` (весь объект), стартовая постановка тени v475 (`state?.project` в try → тихо ничего), CP1-диагностика `modlistToolCollectAnalysisBaselineV503` (`getCurrentAnalysisRunRef`, `state`, `PathStorage` — ReferenceError; `?.` не спасает от необъявленного имени), console-help `escapeHtml`/`openAnalysisIdbDiagnosticsModal` (модалка помощи бросит на `escapeHtml`). Все — диагностика/мобильный, не ядро.
5. **Статусы:** словарь CP2 — `error`, ядро CP3 пишет `failed` (source и work); снимок считает `failed`. В NG — один enum.
6. **Очереди CP3**: обратное давление реализовано **исключением** при переполнении (не ожиданием) — вызывающий код обязан сам дренировать до порога (так и делают CP6/CP7). `shift()` по массиву — O(n).
7. **`cleanup` при abort (168782)** сканирует все хранилища IDB целиком — O(размер БД) на каждый откат.
8. **«no archive failure» как предусловие promote** (Run Kernel CP1) vs CP7, где битый архив = деградация, а прогон завершается `complete`. Где именно cutover решает (блокирует ли promote при `archiveSourcesFailed > 0`) — в S20/S21 или 134039+.
9. **Версия фасада** `ProjectRelationGraph.version = 'project-relation-graph-v477'` после v478 — диагностика по версии вводит в заблуждение.
10. `modlistToolCommandSafety`: подстрока `set` раньше `get` → `getSettings…` классифицируется как «writes» (косметика).

### Не переносить
- Тень v475 (сравнение токенов legacy/graph) и аудит v477 — исследовательские инструменты; из аудита взять только метрики-инварианты (ограниченный обход, нет петель обратной связи «имя из собственного имени», нет глобальной материализации контекстов).
