## 4. Для NG

**Автосохранение = база + журнал доменных патчей (ADR 0007).** Переносить модель, а не код:
1. Хранилище: workspace (`meta.workspaceId`), base (сжатый снимок), один документ «patches» (весь массив, переписывается целиком), head (указатели baseKey/patchesKey),
   meta (updatedAt — для выбора последнего workspace). Восстановление: явный id → указатель → текущий проект → самый свежий meta; base + последовательное применение патчей,
   битый патч пропускается.
2. Когда база: `run-surface|run-full`, `start-*`, `load_*`, `manual-save-slot`, `sync-commit(-failed)`, `save_project*`, либо базы ещё нет. База обнуляет журнал патчей.
3. Маршрут причины → тип патча (65 246, живой): `toggle_mod|rename_mod|paint_mod|clear_mod_color` → `mod_update`; `paint_separator|rename_separator` → `separator_update`;
   `reorder_mods|full-modlist-card-drop|modlist-move|logical-group-aware-modlist-move|logical-group-internal-drop` (+ `conflict-*-modlist-move`) → `modlist_order_state`;
   `update-settings`(`update_settings`) → `ui_settings_state`; `overwrite-user-composite-v658` → `overwrite_user_composites_state`;
   `toggle-conflict-(chain-done|context-collapsed)` → `conflict_done_state`; структурные (alt, create/delete/move/reorder separator/mods, restore_sync_*, bulk-operations, logical-group ops) → `structure_state`;
   иначе — `light_state` (полный лёгкий снимок). Плюс «почтовый ящик» `state.pendingAutosavePatch` для заранее собранных (mods_bulk_update, plugin_update, reorder_ops, presentation identity).
4. Правила вытеснения в конверте (65 553–65 635): light → очистить всё; structure → убрать mod/mods_bulk/separator/structure/order/reorder_ops/separator_order; modlist_order → убрать order-типы;
   separator_order → убрать прежний; reorder_ops → слить операции (`coalesce…V496`, ≤500, журнал ≤80); ui_settings / conflict_done → убрать свой тип и light с той же причиной;
   separator_update — по separatorId; mod_update / mods_bulk_update — по пересечению modId; plugin_update — по ключу имени. Потолок 80 патчей.
5. Derived Runtime: таблица источник→цели (59 422) и версия-снимок для отбрасывания устаревших фоновых задач — хорошая модель инвалидации для `sat-core` (версии доменов, задачи несут снимок).
6. Поиск: модель «поверхность поиска» (id, контроллер, приоритет, контекст, запрос на поверхность, курсор совпадения, порядковый номер активности), правила клавиатуры:
   печать вне поля → поверхность сессии или самая глубокая под указателем внутри верхней модалки; Enter → первое совпадение; Shift+Enter → следующее, аддитивно;
   Backspace правит запрос; Escape — фокус → сессия → самая свежая активная. Нормализация `trim().toLocaleLowerCase('ru-RU')`, совпадение — подстрока.
7. История undo: три уровня по числу модов (900 / 1800), ≤8 шагов, маркеры пропускаются.

**Вероятные ошибки / спорные места:**
- `applyAutosavePatch` для `mod_update`/`mods_bulk_update` не применяет `visual` и `tagEffectSettingsOverride`, для `separator_update` — `visual`, хотя построители их пишут → после
  восстановления из патчей визуал/оверрайды эффектов теряются до следующей базы. Аналогично light-разделитель без `visual` (64067) + `overlayAutosaveLightState` заменяет
  separators целиком → визуал разделителей теряется при любом light_state.
- Потолок `slice(-80)`: при >80 различных mod_update/separator_update без новой базы самые старые изменения молча выпадают (база создаётся только по п.2).
- `ui_settings_state` содержит `conflictTableFileTypeBeautyEnabled`/`showFunctionalSeparators`, light-state — нет; light_state очищает конверт → эти флаги откатываются к базе.
- Аудит-классификатор 66 959 расходится с живым маршрутизатором: `toggle_mods_bulk|paint_mods_bulk|clear_mods_color_bulk|toggle-conflict-chain-mod` он считает `mods_bulk_update`,
  а живой путь даёт их только через pending-ящик, иначе light_state. Самотест `known-reasons-do-not-fallback…` поэтому может «зеленеть» при реальном откате в light.
- `recordHistory` → `autosave(type)`: причина = тип журнала; `manual_save_slot`, `paint_mod` и т. п. маршрутизируются, но любой незнакомый тип = полный light_state (дорого на 6k+ модах).
- `getAutosaveBaseSnapshot()` ≡ null → `getPatchedAutosaveSnapshot` мёртв, bootstrap базы перед патчами 62646 ничего не делает.
- quota-ветки `autosave` ловят только синхронные ошибки; асинхронные ошибки IDB лишь пишут `state.autosaveIdbMirrorError`.
- `overwrite_presentation_identity_state` не имеет правила вытеснения → копии копятся до 80.
- `patchSeparatorStats`: плитка считает через `getSeparatorMeta`, шапка — через `getSeparatorEnabledStats` (возможное расхождение чисел).
- `cancelDerivedJobs` поднимает все версии → после отмены `dirty` уже никогда не снимется текущим снимком без новой постановки.
- `buildStructureAutosavePatch` ищет запись журнала по **нормализованной** причине (`create-logical-group`), а журнал пишет `create_logical_group` → `journalEntry` часто null.
