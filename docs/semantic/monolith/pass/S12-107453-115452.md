## 4. Для NG

**Формулы и форматы (порт 1:1 или как контракт):**
1. Отпечаток порядка modlist: `join('|')` от `${sepId}:${modId}` по не-SYNC разделителям, без представителей разделителей, SYNC-прокси и припаркованных SYNC-модов (110626). Одна SYNC-запись на весь порядок: `project_modlist_reordered::modlist.txt` (110699).
2. Fingerprint'ы SYNC-записей проекта: `project_{created|renamed|deleted|restored}::{mod|separator}::<id>`; разделитель на диске — `<name>_separator` (+ `meta.ini`); удаление мода = парковка `parked_real_mod` в SYNC и `deleted/` при commit; удаление разделителя = снимок `separator_representative_snapshot`. Миграция донора: `external_migration_pending::<sessionId>::<nameKey>::<targetSepId>`, confidence из matchStatus (exact/contains/manual).
3. `hashAnalysisPathList` (113937) — двойной FNV-подобный хэш, вход: отсортированные (`localeCompare base`) нормализованные пути; формат `pathlist_v1_<n>_<h1>_<h2>`. Если NG сохраняет совместимость с `.mnlth`, нужен точный порт (включая `+ i + c` во втором хэше).
4. `conflictPathId` / `makeOverwriteRouteGroupId` / `conflictPathShard` (114992, 115050, 115006) — зависят от `hashStringToInt`; shard = hash % 64 в hex(2), bucket `<root lower>::<shard>`.
5. Компактная ссылка владельца — кортеж `[modId, modName, sepId, sepName, priority, enabled01]`, сортировка по priority ↑ (114936).
6. Leaf-id compact tree — дельта-кодирование отсортированных положительных целых в CSV (113096).
7. Слияние метаданных маршрута одного пути (114096): loose > archive; два разных архива → `archive-ambiguous`; иначе поле-в-поле → `ambiguous-multiple-sources`. Метаданные выровнены по индексу нормализованного списка путей, длина обязана совпадать.
8. Контракт горячей записи v519: горячая копия в IDB всегда; dual-write только при явном запросе и валидной cold-ссылке; `reuse`/`indexed` маршруты — только hot.
9. Порядок чтения путей (114745): hot-recovery > cold `.mnlth` > hot chunks > inline `paths`; проверка хэша и числа путей обязательна. В NG: различать «ошибка чтения» и «пустой мод» (монолит возвращает `[]` в обоих случаях).
10. Нормализация пути анализа: `\`→`/`, схлопнуть `/`, без ведущих/хвостовых `/`, регистр сохраняется; сортировка `localeCompare(sensitivity:'base')`. Для путей цепочек — `normalizeTreeConflictPath` + `.sort()` по кодам (разный порядок!).
11. Валидность папки mods: `score >= 50` и есть handle (109933). Порог порядка UI-модалки пробега: deep требует валидную overwrite.
12. Фильтры хедера: AND по дескрипторам `{type, key}`; провайдеры tag/sticker/overwrite-context/overwrite-chain; overwrite-фильтры группируются по контексту (111768).
13. `analysisConfig` по умолчанию: `{deepEnabled:true, compactBuildEnabled:true, archiveScanEnabled:true, tagRulesEnabled:false, stickerRulesEnabled:false, customArmed:false}`; `legacyFullOverwriteChainPathChunks` (скрытый) — полный режим чанков цепочек.
14. Горячие клавиши (108907): Ctrl+O импорт `.mnlth`, Ctrl+S экспорт `.mnlth`, Ctrl+Shift+S запись modlist.txt, Ctrl+Z/Ctrl+Shift+Z, Space, Ctrl+C (Shift — расширенно), Delete → SYNC-парковка, печать → поиск, Esc. Alt+клик мод = вкл/выкл, Alt+клик разделитель = вкл/выкл его модов.

**Вероятные баги / спорное:**
- `deleteModsToRecycle` (112454–112455): `mod.enabled=false` до чтения `wasEnabled` → `originalEnabled` всегда false; восстановленный мод всегда выключен. В NG сохранять исходный enabled.
- Дефолт `enabled` при восстановлении расходится: `restoreSyncParkedEntity` → `?? true`, `prepareMovedSyncRealModForProject` → `?? !!enabled` (а после бага — `false`).
- `createNewSeparator` без SYNC-разделителя вставляет в **начало** (`max(0,-1)=0`).
- Восстановленный разделитель встаёт сразу после SYNC-разделителя, не на прежнее место.
- `reorderSeparatorsCanonicalCP19` (телефон) не создаёт SYNC-запись порядка — commit modlist.txt может не узнать о переупорядочивании (если `phoneV2PersistSeparatorOrderCP17` этого не делает — не проверено).
- `reorderMods` fast-lane (conflict/phone) не пишет историю и SYNC-запись порядка — только `queueConflictReorderPersistenceV496`; надо убедиться, что дельта-персистенция поднимает `project_modlist_reordered` (S15?).
- `bindGlobalEvents` неидемпотентна (click/keydown/resize без флагов); `patchDropTargets` копит `dragleave` на каждом `renderAll`; Ctrl+Shift+S обрабатывается дважды (вторая ветка мертва из-за capture-stopImmediatePropagation).
- `injectCustomMetaBlocks` исполняет пользовательский JS через `new Function` для всех custom-блоков (включая выключенные) — в NG не переносить как есть (песочница/декларативные эффекты); проект из чужих рук = выполнение кода.
- `addStickerToMod` обновляет MRU до проверки пустого emoji.
- `scheduleSelectionDependentRender` — один таймер на все окна.
- `getProjectRuns` (живая 131983) не создаёт `runs.pluginsState`, хотя 109952 создавала — потребители `pluginsState` должны сами ленить.
- `putModAnalysisState` — read и write в разных транзакциях (гонка при параллельной записи одного мода); `putModAnalysisStates` перезаписывает без merge.
- `putModPathsManifestOnly` удаляет метаданные маршрутов и горячие чанки — после перевода в cold маршрутные метаданные невосстановимы без повторного пробега.
- `hasHotChunkEvidenceV519` срабатывает на любой записи с `chunkPrefix` (cold-записи его тоже пишут) — лишнее горячее чтение перед cold.
- `pruneAnalysisWarmCache` пересчитывает сумму байт в цикле вытеснения (O(n²)), вызывается на каждое чтение.
- `writeOverwriteChainPathChunksToStore` пишет запись словаря на каждый путь каждой цепочки (дубликаты put).
- Донор: сессии живут только в памяти (текст подтверждения 108126) — в NG решить явно (ADR донора).
- `externalDonorInput` переименовывает донора без autosave/истории.
