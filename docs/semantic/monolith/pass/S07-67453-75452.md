### 67569–67738 · обл. 22/5 · `buildRunSessionDeepMasterV503` — главная шкала глубинного анализа · живое · v503 graphical CP4/CP5
Вход: `runSession, config, runtime (проекция CP11), stages: Map, analyzers: Map, cutoverResult`. Ветки по приоритету:
1. `!deepEnabled` → `off`.
2. `failed` = `rs.completionState==='error'` ∨ runtime failed ∨ `issues.errors>0` ∨ любая стадия deep/compact/overwrite/finalize в `error` → `error`, текст из стадии/последнего issue.
3. `finalized` = есть `cutoverResult` ∨ стадия finalize `done` ∨ (`canAccept` ∧ `completionState==='done'`) → фаза promotion, 100, `warning` если были предупреждения.
4. `runtime.attached` (живая проекция оркестратора):
   - источники не все готовы → traversal, `candidate = 70 * complete/total`, текст — активный источник (последний `recent` со `status==='active'`);
   - иначе пока очереди (`sources/observations/work/routeWrites`) не пусты, барьеры (`openTokens`, `open`) не закрыты или `drainRatio<1` → drain, `candidate = 70 + 15*drainRatio`, где `drainRatio = min(observationsTotal, consumed(cp08.streaming-aggregates), consumed(cp10.path-owner-stream)) / observationsTotal` (оба обязательных анализатора должны присутствовать);
   - иначе post-deep: `postRatio` = max из: compact active → `.10+.20*p`, compact done → `.30`, overwrite active → `.30+.58*p`, overwrite done → `.92`; `candidate = 85 + 12*min(1,postRatio)`.
5. Без runtime (легаси-стадии): finalize active → `97+3*p`; compact/overwrite active|done → `85 + 12*max(compactRatio*.35, .35+overwriteRatio*.65)` (замечание: второй аргумент max всегда ≥ .35 ≥ первого, т.е. compact на шкалу не влияет); deep active/draining → `70*p`; deep done → 85, иначе 0.
**Монотонность**: `progress = max(previous, candidate)` в пределах `sessionKey = rs.uiSessionId || runtime.runId`; пишет `rs.deepProgressUi = {sessionKey, progress, phaseId, updatedAt}` — **побочная запись в state из «построителя модели»**. `off`→0, `done`→100.
