## 4. Для NG

### Формат `.mnlth` монолита (для импортёра Фазы 1, ADR 0007 п.6)
- Поток NDJSON, по записи на строку, поле `type`. Порядок экспорта: `container-manifest` → `project-json` → `plugin-state-pack` → `analysis-manifest` → `cold-path-segment`* (вшитые) → для каждого хранилища плана `store-begin` / `store-record {store, key, value}`* / `store-end` → `container-end`. Также в файле могут быть (дописаны позже) `cold-path-segment` и `active-container-binding` (пишутся вне этого сегмента) и **файл без `container-end`** (дописываемый холодный контейнер) — импортёр должен это терпеть.
- Импортёру NG достаточно: `project-json.value` (форма stage9, ниже), `plugin-state-pack.value` (`mnlth-plugin-state-pack-v1`), записи `cold-path-segment` (пути модов). `store-record` аналитики можно игнорировать (ADR 0007: дешевле пересчитать), кроме, возможно, `modAnalysisState` (сигнатуры).
- Схемы: `mnlth-container-v1`, `mnlth-ndjson-v1`, `mnlth-analysis-pack-v1`, `mnlth-cold-path-segment-v1`, `mnlth-route-entity-persistence/v1`, `mnlth-plugin-state-pack-v1`, `mnlth-storage-boundary-v1`.
- Холодный сегмент: `{segmentId, projectId, runId, modName, pathCount, samplePaths≤40, contentHash, contentHashAlgorithm:'pathlist-fnv1a-dual-v1', contentHashInput:'normalized-analysis-paths-v1', payload.paths[], meta{source, truncated, originalPathCount}}`. Проверка: пересчитать хеш `PathStorage.computePathContentHash(normalizeAnalysisPaths(paths))` (алгоритм — вне сегмента, нужно перенести побитно для сверки) и сравнить с `contentHash`.

### Правила, которые стоит перенести
- Правила стикеров (живая 157 411) и `applyStickerNamesToMod`: `stickers = ручные ∪ найденные`, найденные отдельно в `derived.stickers` (NG: слой «намерение» vs «факт» — держать раздельно, объединять в проекции).
- Контекст правил тегов: `exts` берутся из **каждого** сегмента пути (папка `a.b` даёт расширение `.b`) — в NG брать только у имени файла (спорно, сверить с владельцем).
- Охранник экспорта (`finalizeMnlthExportGuard`) — готовый образец для NG-контейнера: счёт «до» по ожиданиям из манифеста (какие слои проект объявляет), запрет пустых ожидаемых, после записи — `written === expected` (с учётом намеренных пропусков: dedupe → `written+skipped ≥ idbCount`; live-отбор → `exportCountExpected`).
- Импорт: «стереть слой целиком при неверном дайджесте» (карантин v556) — совпадает с ADR 0007 п.3.
- Пост-проверка графа: owners⇒modFiles, chains⇔contexts, chains∧contexts⇒все виды — инварианты для тестов NG.
- Шкала прогресса импорта (фазы и проценты, 161 832) — для UI-паритета.
- Режимы `pathStorageMode`: `idb-chunks` / `dual-idb-mnlth` / `mnlth-cold-segment` — история миграции хранения путей (F5 dual-write, F6 cutover).
- PLUGINS: позиция после «Skyrim»-разделителя, иначе после SYNC; DONOR: после PLUGINS, иначе после SYNC; оба всегда пусты в `mods`, заблокированы, `getSeparatorMeta` подменяет счётчики (PLUGINS: все/активные плагины; DONOR: total/exact/missing).

### Спорные места и вероятные ошибки
1. **`isPluginsSystemSeparator` срабатывает на `name === 'PLUGINS'`** (19 465): пользовательский разделитель с именем PLUGINS станет системным, `ensurePluginsSystemSeparator` удалит дубликаты и обнулит `mods` → **потеря модов**. В NG — только по id/роли.
2. `makeMnlthColdPathSegmentId` недетерминирован (`Date.now()+Math.random()`) — повторная запись тех же путей плодит сегменты; GC (`planMnlthColdSegmentGc`, вне сегмента) обязателен. NG: id = хеш содержимого.
3. `readMnlthColdPathSegment` — линейный скан всего файла с `JSON.parse` каждой строки, хотя `coldSegmentRef` несёт `byteOffset/byteLength`. Для многогигабайтного контейнера — O(файл) на мод. NG: случайный доступ по смещению/индексу.
4. Весь экспорт собирается в памяти (`parts[]` строк → Blob) — для ~2 ТБ сборки контейнер в сотни МБ держится в RAM целиком. `appendMnlthNdjsonRecordsToFileHandle` без `seek` перезаписывает весь файл через `previousFile.text()`.
5. `importMnlthContainer`: очистка старых хранилищ пробега происходит при первой `store-record` **до** проверки целостности; если затем нет `project-json` или поток оборвался — старый пробег стёрт, проект не заменён. Нет транзакционности «staging → swap».
6. Импорт игнорирует `cold-path-segment` записи (не кладёт в IDB) — манифесты `modPaths` в режиме `mnlth-cold-segment` после импорта читаются только через привязанный файл; без `showOpenFilePicker` (fallback `<input>`) хэндла нет → привязка `writable:false`, а `PathStorage.readModPaths` для холодного чтения ждёт `fileHandle` — пути таких модов, вероятно, недоступны до перепривязки (`modlistToolRebindActiveMnlthFromPicker`); не проверено, см. §5.
7. Действия меню `import` и `import-validate` идентичны (оба `fullConflictValidation:true, profile:true`) — обычный импорт всегда тяжёлый.
8. `readMnlthLineStringField` — регэксп по первому вхождению, без учёта `\"`; для `store-record` поле `store` стоит вторым, поэтому работает, но формат хрупок к порядку ключей.
9. `getConflictModalBakedRenderKey` не включает состояние user-composites V657 / presentation identity / нормализованного слоя — при включённой оптимизации возможна устаревшая разметка модалки.
10. `collectConflictFileExplorerDirFromIdb`/`…RelatedFromIdb` — полный проход по всем путям всех модов на каждую смену каталога/выделения; мёртвые `db`/`prefix`. NG: индекс каталогов один раз.
11. `getPluginContextStatsForToolbar` (owner 19 556) возвращает `true` вместо статистики.
12. Лог прогресса импорта склеивается `'\\n'` → в debug-панели одна строка с литералами `\n`.
13. `stage9CompactPluginEntry` вызывает `normalizePluginHeaderFacts(plugin)` на живом объекте (мутация при сериализации); `stage9CompactModForProjectJson` генерирует новый `uid('mod')` для мода без id — id нестабилен между сохранениями.
14. `stage9…analysisRef` не сохраняет `lastTagRulesRunAt/lastStickerRulesRunAt` (пишутся 157 439/157 452) — поля живут только до перезагрузки.
15. `validateMnlthPostImport` и `stage10CheckProjectIdbAvailability` по умолчанию **пишут** в `runs.treeFull` (writeBack) — проверка с побочным эффектом, может перевести `status` в `manifest-only-missing-idb`.
16. Правый клик по тегу/стикеру (v482, capture на document) **молча удаляет** его со всех выделенных модов — нет подтверждения и нет контекстного меню.
17. `runPathStorageDualWriteValidation`/`runPathStorageCutoverValidation` — «валидации», которые меняют манифест реального мода (cutover удаляет IDB-чанки).
18. `renderAbstractFileExplorerNode` — мёртвая (только рекурсия); `__stage9OrigBuildProjectSnapshot` — мёртвая.
