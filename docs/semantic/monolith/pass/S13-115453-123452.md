> Проход 1, главный курсор. Сегмент прочитан целиком (115 453–123 452); раздел 2 писался по ходу чтения, разделы 1, 3–5 — в конце.

## 1. Обзор

Сегмент целиком лежит внутри IIFE `AnalysisPathStore` (113615 → `window.AnalysisPathStore` 124498) и содержит **IDB-конвейер overwrite-анализа**
(обл. 6 «Хранилище анализа» + обл. 10 «Нормализованный слой цепочек») в его последней, «ограниченной по памяти» форме: внешняя сортировка через
work-store `overwriteWorkPartitions` (256 партиций по FNV-1a, буферы 8192, keyset-страницы по 500–1000). Живой порядок стадий:
`owners` (`rebuildOverwriteOwnersFromPaths` 120968) → `mod-files` → `chains-build` (точные цепочки = стеки с одинаковым упорядоченным набором владельцев и победителем)
→ идентичности цепочек → `chains-normalize` (производные route groups, точный слой неизменяем) → `contexts-build` (компоненты связности label propagation + identity v468)
→ `read-views` (лёгкие проекции для UI). Плюс телеметрия-владелец v503, «истина стека» v503, адаптеры к legacy «conflict group», и read-only
лаборатория нормализации v498 (археология) / v499 (safe route-DAG) / начало v500 (repeat-cover), которую позже живо вызывает `materializeV501`.
Переопределений «функция поверх функции» в сегменте нет (xref: 0); но 6 методов объекта `AnalysisPathStore` перезаписаны позже (v501 cutover, 125594–126802).

## 4. Для NG

**Правила, которые надо перенести точно**
1. **Нормализация пути конфликта**: `\`→`/`, срез `^selected/`, срез ведущих `/`, lowercase (143074). Игнор-правила — три формы (143212). Путь-id: двойной FNV-1a + длина (114992).
2. **Владельцы пути**: только пути с ≥2 владельцами — конфликт; одновладельческие удаляются из словаря (121480). Порядок владельцев — по живому приоритету
   модлиста ↑ (тай — имя, base-collation); **победитель = последний enabled**. Сохранённые priority/enabled — лишь снимок, при чтении всегда
   живой оверлей (`applyLiveOverwriteOwnerPriority` 116262 с флагами `livePriorityChanged/liveEnabledChanged/livePriorityMissing`).
3. **Точная цепочка = стек**: ключ `route:${all}###active:${enabled}###winner:${w}` (имена через `|||`); id `owchain_${fnv36(sig###sortedPaths)}_${n}`; stackId `owstack_${fnv36(sig)}`.
   Участник: `owned = |paths|`, `extra = max(0, modConflictPaths − |paths|)`, wins/loses по победителю.
4. **Сводка мода**: `conflictPaths, wins, losses`, sample ≤12 (лексикографически), соперники ≤32 (первые по (path, order, name)); `opponentsCount` = Σ ссылок (не уникальных) — в NG переименовать.
5. **Route groups** (производный слой, точный неизменяем): exact по `routeSignature`; similarity — жадно в 3 прохода внутри одного победителя:
   упорядоченный подмаршрут → общий хвост ≥2 → ≥1 общее ребро (117278). Главная — самая длинная, затем больше файлов, затем id.
6. **Контексты** = компоненты связности графа «две цепочки делят мод» (label propagation по min-label, 119373); наследование старого контекста:
   `score = 0.65·max(J(chainIds), J(chainFingerprints)) + 0.30·J(mods) + 0.05·J(sampleFiles)`, порог **0.28**, каждый старый контекст — максимум одному новому (118220, 119544).
   id = старый либо `owctx_${fp}_${chainCount}` с суффиксами. Ручные поля (customName/Icon/Color) переносятся.
7. **Фоллбек-идентичность цепочки**: hue `fnv(fp::chain)%360`, шаг золотым углом 137.508° до 16 раз при близости <18°, `hsl(h,70%,42%)`; палитра 12 эмодзи (118149).
8. **Safe route-DAG (v499)**: слияние только при общих модах, одном ключе победителя, ацикличном объединении рёбер, кап 256 узлов/128 вариантов; супер-маршрут — Кан с
   тай-брейком `minRouteIndex → firstVariant → firstPosition → имя`; ранжирование кандидатов `tier·1e6 + shared·1e4 + round(J·1000) + min(999,Σexact) − 10·addedComplexity`.
   Цель v500 — лексикографически `repeatedAppearances → chainCount → routeComplexity → routeVariants → totalModAppearances`.

**Формы данных (stores)** — см. раздел 2: `overwritePathOwners`, `conflictPathDict`, `overwriteModSummary`, `overwriteModFiles`, `overwriteChains` (lite v2), `overwriteChainByMod`,
`overwriteChainPathChunks`, `overwriteRouteGroups` / `…ByChain` (v2), `overwriteContexts` (lite v1) / `…ByChain`, `overwriteContextView`, `overwriteChainPreview`, `overwriteModView`,
`overwriteMeta` (+telemetry), `overwriteWorkPartitions` (временный, не экспортируется). В NG (ADR 0007) хранилище не переносится как есть — переносятся **инварианты**,
а партиционирование/телеметрия заменяются нативной памятью Rust.

**Спорные места и вероятные баги**
- `buildProjectModLookup` (owners) vs `getLiveOverwriteOwnerLookup` (оверлей): разные наборы пропускаемых разделителей (SYNC vs SYNC+PLUGINS+donor) и разный дефолт
  `enabled` (`!!mod.enabled` vs `!== false`) → ложные «изменения приоритета/включения», а при модах в PLUGINS/донор-разделителе — сдвиг шкалы priority.
- `readOverwriteChainPathBundleFromChunks` 115486: при наличии хоть одного прямого пути `pathIds` игнорируются — смешанные чанки теряют пути.
- `getOverwriteContextViewsPage` 118931 (и `getOverwriteRouteGroupsPage`, `getOverwriteChainsPage`): `limit` берётся по порядку ключей, сортировка после — «первые N по order» не гарантированы.
- `buildFallbackOverwriteChainIdentity` в read-views (118680) вызывается с пустыми usedNames/Icons/Hues → коллизии имён/цветов между безымянными цепочками.
- `buildConflictGroupsFromOverwriteModView` 118994 ждёт `context.groups`, а текущий mod view (118858) их не пишет → для новых данных пусто; живой путь — `…Lite` (144359 выбирает по `isLiteModView`).
- `rebuildOverwriteChainsAndContextsFromOwners`/`rebuildOverwriteOwnersFromPaths`: при исключении `overwriteMeta.status` остаётся `'running'` (нет `failed`).
- `buildOverwriteContextsFromChains`: при ошибке после частичной записи `writeDurableContext` sweep не выполняется → смесь поколений `generation`.
- `assignAuthoritativeExactChainIdentities` грузит все цепочки в RAM — единственный неограниченный шаг пайплайна.
- `hydrateOverwriteChainFullDetails`/`buildOverwriteStacksForPaths` — по одному IDB-запросу на путь и на участника (медленно для больших цепочек).
- Маршрут стека в preview (118412) пересортирован по смешанной шкале (живой priority для живых модов, индекс для остальных).
- `mod-files`: priority/enabled в записи мода — из первого встретившегося вклада (снимок), не живые.
- Identity-pass v468 мутирует `state.project` (реестр идентичности) изнутри IDB-стадии — побочный эффект, который NG должен сделать явным.
