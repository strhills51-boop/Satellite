Проход 1, главный курсор. Монолит: `monolith.html` (копия `index.html`). Связи — по `xref chunk 27453 35452`

## 1. Обзор

Сегмент — это **модельный слой «украшений» карточек и SYNC-модели**, почти без DOM-рендера крупных видов.
Первая половина (27 453–30 816) — хвост статической таблицы `BUILTIN_TAG_DETECTORS` (257 правил автотегов).
Дальше идут: системные коллекции тегов и стикеров (30 818–30 887); канонические режимы эффекта «Теги» и миграция
старых режимов (v431/v438); модель шаблона счётчика (v371/v375/v528/v619/v649); облачко при наведении целиком —
настройки, реестр секций, менеджер с таймерами, закреплением, правкой тегов, заметок и plugins (v378–v398);
единая модель `effectSettings` из 7 эффектов с нормализацией и миграцией (v361–v370, v438, v644, v650); профиль
визуала тегов для отдельного мода и индексы большой доски (v439–v450); реестр эффектов; мета-стек по умолчанию.
Последние ~860 строк — модель **SYNC**: состояние, записи, прокси-моды, сверка «диск ↔ проект» и карточки записей.
Всё здесь — живой код верхнего уровня. Делегатов v527 в сегменте нет, есть только пометки об удалённых
хелперах (`/* v527 CPnn: unused … removed */`). Теней под флагами тоже нет.

  (вместе с префиксом — 84).
- **effectSettings** (`project.ui.effectSettings`), значения по умолчанию:
  - `tags`: `{enabled:true, primaryMode:'none', markerMode:'dots', resonance:false, intensity:1, opacity:1,
    animation:true, area:'all'}`;

  вида становится источником `statistics`, а счётчик сбрасывается на значения по умолчанию.

  «смысловой» текст, без строк из одних разделителей `^[\s:;|/\\·.,\-–—()[\]{}]+$`. Ведущий и хвостовой регионы:
  если в регионе была удалённая метрика — только смысловой текст, иначе весь текст. Регион между двумя валидными
  метриками: без удалённой — весь текст; с удалённой — смысловой текст, а если его нет — **первый** текстовый

   один раз при загрузке.
3. **`getEffectSettings`** при каждом вызове делает полную нормализацию и сверку с реестром счётчика и пишет в
   проект. Это дорого, а главное, это чтение с побочным эффектом. В NG — нормализация при загрузке и чтение без записи.
4. **`upsertSyncRecord`** сопоставляет по `fingerprint || id`. Новая запись без id получает `uid`, так что
   совпадение по id срабатывает только у явно переданных id. После слияния fingerprint берётся из новой записи и
   может поменяться.
5. **Rename-кандидат** не удаляет соответствующие fs_created и fs_deleted: в UI три записи на одно переименование.
6. В `normalizeCounterTemplateTokenV371` метрика с неизвестной областью (её нет ни в реестре, ни в статической
   карте) **не** отбрасывается. Отбрасывает её только сверка v619, когда реестр готов.
7. Матрица контекстов облачка объявляет `classic-logical-member` и `conflict-row`, но код определения контекста
   их никогда не возвращает (конфликтные карточки облачко подавляют явно). Для NG: либо реализовать, либо убрать.
8. `ModlistToolHoverCloudAPI` присваивается дважды. Внешний код, сохранивший ссылку между 32 184 и 33 333
   (в синхронном потоке такого нет), получил бы v1.
9. `renderHoverCloudTagsV379` для пустого мода пишет «У мода пока нет тегов.», а у разделителя кнопки правки нет.
   Пикер и правка — только для мода; заметку можно править и у разделителя.
10. В `getBadgeDensityLimitsV367` значение 0 — по смыслу «без ограничения» (full = все нули, normal modContexts = 0).
    Проверить у потребителя.
11. `getIndicatorInlineColorV367(mod, enabled=false)` всегда возвращает `#475569`, даже при включённых цветах plugins.

### Что не переносить как есть
Рантайм холста тегов (индексы DOM, IntersectionObserver, debounce 52 мс, кэши кадра) — оптимизации под
`<canvas>` монолита. Переносить смысл (три слоя, профиль мода, корзины), а не механику. Менеджер облачка —
UI-паритет (NG-D004+): переносить поведение — таймеры, блокировки, позиционирование, матрицу контекстов.
