### 148 021–148 414 — построение stack-view: `buildOverwriteContextStacksChunkedAsync` 148021 / `buildOverwriteContextStacks` 148222 (обл. 8/9)
Две копии одного алгоритма: асинхронная с уступкой кадра (`maybeYield` каждые `chunkSize` шагов, дефолт 350, мин. 50; `options.shouldCancel` → `null`) и синхронная. Логика идентична (расхождений не найдено, кроме уступок).
1. `flatRows`: для каждой строки `stateByPath = Map(cell.path → cell.state||'missing')`.
2. Черновики stack из «запечённых» `chain.fileStacks[]` (`stack.files|paths|samplePaths`, `normalizeAnalysisPaths`+`normalizeTreeConflictPath`, сортировка):
   - `groupFileStacks` (дефолт) — ключ `baked:${stack.signature || stack.routeSignature || paths.join('|||')}`: стеки разных цепочек с одной подписью сливаются в одну колонку;
   - иначе — ключ `path:${path}` (колонка на файл).
   - Черновик несёт `route/routeSignature/activeRoute/activeRouteSignature/activeWinnerModName`, `sourceStackIds`, `sourceChainIds`.
3. Непокрытые `context.files`: если запечённых стеков нет и группировка включена — ключ `fallback-state:${состояния всех строк по пути через '|'}` (группировка по одинаковому вектору состояний), иначе `path:`.
4. На колонку: `merged = mergeOverwriteContextCellState(...)` по всем путям колонки для каждой строки → `stateByRow`; счётчики: `strongCount = win+lose`, `linkedStrongCount = win-linked+lose-linked`, `winLoseCount`, `ownedCount = owned+extra`, `activeModCount` (≠missing), **`activityScore = strong*100 + linkedStrong*70 + owned*30 + activeMods*10`**.
5. Сортировка `compareOverwriteContextStacksWithDirection(a,b,mode,dir)` → `order`, `representativePath = paths[0]`, `count`, `folderMeta`.
6. Строки клонируются с `__owctxSourceRow`, `__owctxStateByPath`. Результат `{...context, stacks, rowsBySeparator}` в LRU.
Статус: живое (синхронная — из рендера; асинхронная — из ленивой очереди `ensureOverwriteContextStackViewLazy`, см. §3).
