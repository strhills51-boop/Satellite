### 148 021–148 414 — построение stack-view: `buildOverwriteContextStacksChunkedAsync` 148021 / `buildOverwriteContextStacks` 148222 (обл. 8/9)
Две копии одного алгоритма: асинхронная с уступкой кадра (`maybeYield` каждые `chunkSize` шагов, дефолт 350, мин. 50; `options.shouldCancel` → `null`) и синхронная. Логика идентична (расхождений не найдено, кроме уступок).
1. `flatRows`: для каждой строки `stateByPath = Map(cell.path → cell.state||'missing')`.
2. Черновики stack из «запечённых» `chain.fileStacks[]` (`stack.files|paths|samplePaths`, `normalizeAnalysisPaths`+`normalizeTreeConflictPath`, сортировка):
   - `groupFileStacks` (дефолт) — ключ `baked:${stack.signature || stack.routeSignature || paths.join('|||')}`: стеки разных цепочек с одной подписью сливаются в одну колонку;
   - иначе — ключ `path:${path}` (колонка на файл).
   - Черновик несёт `route/routeSignature/activeRoute/activeRouteSignature/activeWinnerModName`, `sourceStackIds`, `sourceChainIds`.
3. Непокрытые `context.files`: если запечённых стеков нет и группировка включена — ключ `fallback-state:${состояния всех строк по пути через '|'}` (группировка по одинаковому вектору состояний), иначе `path:`.
4. На колонку: `merged = mergeOverwriteContextCellState(...)` по всем путям колонки для каждой строки → `stateByRow`; счётчики: `strongCount = win+lose`, `linkedStrongCount = win-linked+lose-linked`, `winLoseCount`, `ownedCount = owned+extra`, `activeModCount` (≠missing), **`activityScore = strong*100 + linkedStrong*70 + owned*30 + activeMods*10`**.
5. Сортировка `compareOverwriteContextStacksWithDirection(a,b,mode,dir)` → `order`, `representativePath = paths[0]`, `count`, `folderMeta`.
6. Строки клонируются с `__owctxSourceRow`, `__owctxStateByPath`. Результат `{...context, stacks, rowsBySeparator}` в LRU.
Статус: живое (синхронная — из рендера; асинхронная — из ленивой очереди `ensureOverwriteContextStackViewLazy`, см. §3).

## 4. Для NG

### Модель «истины» и отпечатки (переносить точно)
- Атом истины = `sourceTruthFingerprints[]` у safe-группы V499 (из нормализатора V501). Нормализация: trim → дедуп → sort.
- Отпечаток членства: `prefix + base36(hashStringToInt(join('|||') || 'empty') >>> 0) + '_' + n`. Префиксы: `owcomptruth_` (композиты V657, идентичности V666), `owrestruth_` (Done V665, фронт V667). Ключ фильтра шапки V670: `owtruth:` + hash('v670|'+sorted) + '.' + hash('v670r|'+reversed) + '.' + n. Хеш — `hashStringToInt` (взять реализацию 1-в-1 или заменить и мигрировать сохранённые ключи: они лежат в `project.ui` как ключи словарей).
- Done (V665), имя/иконка/цвет (V666) и композиты (V657) привязаны к **точному множеству атомов**; подмножество/надмножество не наследует (самотесты «not smeared»). В NG — одна сущность «presentation record по membership», три вида полезной нагрузки.
- Сверка композита (V657): `ORPHANED` (нет пересечений) / `AMBIGUOUS` (группа выходит за границу, или >1 контекста) / `PARTIAL` (не все атомы) / `REDISTRIBUTED` (атомы те же, разбиение другое) / `EXACT`. Применяются только EXACT и REDISTRIBUTED; PARTIAL/AMBIGUOUS показываются плашкой восстановления и блокируют пересекающиеся предложения слияния.
- Создание композита: ≥2 членов, у всех есть атомы, идемпотентно по отпечатку, запрет пересечения атомов с другим композитом.
- Защита коммита слияния (V695): ключ поколения V660 (`v501-generation-v660|pid|rid|builtAt|orderDigest|exactChains|normalizedChains`), ревизия поколения, `conflictOrderStamp`, материализованный и текущий дайджест порядка (`oworder_<hash>_<entries>_<len>` от `getCurrentModlistOrderFingerprint()`), совпадение членов и наличие атомов. Перечень причин отказа — 11 кодов (см. 149080–149090) — годится как enum ошибок в NG.
- Свежесть линии (V658): карточки V499 остаются видимыми после перестановки (маршруты пересортировываются по живому приоритету), но **предложения слияния** отключаются, пока дайджест материализации ≠ текущему.

### Формулы UI
- `activityScore = strong*100 + linkedStrong*70 + owned*30 + activeMods*10` (strong = win+lose, linked = win-linked+lose-linked, owned = owned+extra); вес состояния ячейки win 8 > lose 7 > win-linked 5 > lose-linked 4 > owned 3 > extra 2 > missing 0.
- Группировка колонок: по `stack.signature || routeSignature || paths.join('|||')`; fallback без запечённых стеков — по вектору состояний строк.

- Порог отложенной сборки stack-view: `rows*files > 8000 || files > 240 || rows > 90`.
