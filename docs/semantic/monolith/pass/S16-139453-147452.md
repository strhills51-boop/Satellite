## 1. Обзор

Сегмент из двух частей. Первая (139 453–141 500) — **граф связей проекта и контекст идентичности** v470–v474 (обл. 16): шесть провайдеров рёбер,

сводный `window.__projectIdentityApi`. Это инфраструктура, которую потребляют движок идентичности v476 и Logical Group NG v560 (вне сегмента).
Вторая часть (141 502–147 452) — **модель конфликтов overwrite для модалки** (обл. 8/9): legacy RAM-цепочки из `treeFull`, ленивая материализация порядка после

**переназначены** обёртками нормализованного слоя в 125956/126009), ограниченные кеши v684–v686, контекст цепочки (связная компонента), мастер порядка перезаписи,
«Копия ИИ» с исполнением JS, селектор контекстов с каноническим порядком v651 и слой presentation-наложения таблицы v672–v677 (много самотестов).

## 4. Для NG

**Переносить как правила (`sat-core::overwrite` / `identity`):**
1. Путь конфликта: `normalizeTreeConflictPath` = `\`→`/`, снять `selected/`, ведущие `/`, lowercase. Игнор-лист (`analysisConfig.conflictIgnorePaths`): точный путь; имя файла без `/`
   (в любой папке); `folder/` — папка в начале или в середине пути. Пустой путь считается игнорируемым.
2. Победитель пути = последний **активный** владелец по приоритету MO2 (возрастающий priority); выключенные участвуют в маршруте, но не побеждают.
   Подпись стека: `route:<все>###active:<активные>###winner:<имя>` (разделитель `|||`).
3. Контекст = связная компонента графа «цепочка — проецированная единица участника» (логическая группа схлопывает членов); решённые цепочки исключаются.
   Матрица ячеек `win | win-linked | lose | lose-linked | owned | extra | missing`, столбцы = файлы выбранной цепочки, затем связанные.
4. Канонический порядок карточек v651: вектор отсортированных ординалов участников (id → min членов логической группы → имя → сохранённый), лексикографическое
   сравнение, короче — раньше, пустой — в конец; порядок хранилища не трогать.
5. Presentation-наложение v672: ячейка вне файлов выбранной сущности понижается (`win→win-linked`, `lose→lose-linked`, `owned→extra`), внутри — точное состояние из
   участников детальной цепочки. Ранжирование v675: full > partial > linked независимо от направления сортировки.
6. Жизненный цикл UI v677 — хорошая готовая спецификация для NG-D004 (происхождение выбора `manual|cell|auto|focus|search|legacy`; что сбрасывается на какой границе).
7. Граф идентичности: формула бюджета v474 (`budget = 8·B/5`, `minSignalWeight = 0.05·4^((5−B)/5)`, `maxVisited = round(256·B/5)`, B=0 → только корень), вес сигнала по пути
   `w·Π(edge.weight·0.85)`, барьер обратной связи v473, отпечаток источника — хеш отсортированных принятых сигналов. Это детерминированно и переносимо как есть;
   альтернативно NG может материализовать граф (в монолите он федеративный, ленивый, с `queue.sort` на каждом шаге).
8. Веса сигналов (§2, 140503–140615) и токенизация (camelCase-разрез, `\p{L}\p{N}`, ≥2 символа, ≤24 токена; путь — 5 последних сегментов, `max(0.35, 1−0.12·depth)`).
9. Порог «тяжёлого» глобального контекста: `>40` контекстов или `>350` цепочек или `>9000` файлов.

**Не переносить:** legacy RAM-цепочки `buildOverwriteChainsFromTreeFull` (перекрывающиеся цепочки по базовому моду, id `owchain_<N>` нестабилен), `buildConflictCache`/`conflictIndex`,
