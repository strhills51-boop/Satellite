## 1. Обзор

Сегмент — вторая половина эпопеи Logical Group NG: группа модов (`project.logicalGroups[]`, исходник,
«source-private») наружу показывается **одним обычным модом** `composite-mod:<groupId>` (Composite Mod),
участники наружу не утекают нигде — ни в списке, ни в выделении, ни в конфликтах, ни в журнале.
Здесь лежат: глобальное хранилище конфликтов на внешнем графе (v565, **живое** — через него идут
`getStoredOverwriteChains`/модалка при активных группах), строгий кодек `modlist.txt` с маркерами
`⟦MLT-LG:v1:<id>:<i>/<n>⟧` (v566, **живое** — `serializeModlist` переопределён целиком), транзакционные
операции над исходником (v567), серия «запечатываний» границ идентичности v568–v583 (в основном инспекторы,
самотесты и обёртки диагностик) и публикация `window.ModlistToolLogicalGroupNG*` (v582).
С 58 005 — не-LG код: `ensureProjectStructure` (нормализатор проекта, переопределён позже на 131 963),
теги и цвета, буфер обмена, `renderAllPreserveScroll` / `refreshCurrentModsViewPreserveScroll`, таблицы derived-runtime.
Самотестов ~25, каждый подменяет `state.project` фикстурой и восстанавливает в `finally`.

## 4. Для NG

**Модель Composite Mod (обязательна к переносу как инвариант):**
- Исходник: `LogicalGroup {id, name, color, icon, separatorId, memberModIds[≥2], enabled, broken, brokenReason, projectionMode, orderPolicy:'current-modlist-order', compositeIdentity{name,color,icon,fingerprint,generated,locks}, createdAt, updatedAt}`. Участники — непрерывный диапазон в одном разделителе, `memberModIds` = физический порядок.
- Наружу: ровно один ModLike `composite-mod:<groupId>` на месте диапазона, **даже если группа выключена** (enabled=false не раскрывает участников). Ключ маршрута анализа `mod:composite-mod:<id>`; ключ хранения `logicalGroup:<id>` — только внутри слоя хранения. Конвертация хранения — одна функция (`…StorageEntityKeyFromRuntimeCommandV578`).
- Выделение: только `mods`/`separators`; `logicalGroups` мигрирует на входе (restore) и чинится на выходе (serialize). Обычные mod-id не переинтерпретируются.
- Журнал/квитанции: без groupId/modIds, только `entityKey/compositeModId` + счётчики.

**Кодек modlist.txt (точно):**
- Маркер: `<имя> ⟦MLT-LG:v1:<encodeURIComponent(groupId)>:<ordinal>/<count>⟧`, ordinal 1..count, count≥2, маркер — последний суффикс имени; разбор берёт последнее вхождение регэкспа `/⟦MLT-LG:v1:([^:\]⟧]+):(\d+)\/(\d+)⟧/g`.
- Канонический порядок — **снизу вверх** по файлу (как MO2), строки `#`, `*`, пустые пропускаются, `…_separator` задаёт текущий разделитель.
- Нет маркеров в тексте → кодек полностью прозрачен (CP26). Есть маркеры и ошибка → импорт отклоняется целиком с откатом состояния; экспорт при ошибке группы — исключение. Никакого тихого ремонта.
- Ошибки валидации (имена-коды): см. §2 52 336 и 52 456 — перенести как enum.

**Конфликты при активных группах:** атомарный стор: либо полностью эффективный (из внешнего графа, без участников), либо pending-пустой; никогда не смешанный. Цепочка эффективна целиком: wins/loses = весь набор путей цепочки (победитель/остальные). Контекст = компонента связности цепочек по общему участнику. Приоритет composite = min приоритетов участников. Для обычных модов при pending — `null` → наследный путь (v643 CP45).

**Транзакции исходника:** pre-валидация → снимок → мутация → post-валидация (валидатор групп + план экспорта) → инвалидация производного (кэш composite, lifecycle dirty persist+parity, сброс конфликтного стора, рендерер) → журнал/автосейв. Семантика `remove` (удалённый — сразу за диапазоном), `add` (в конец диапазона), запрет частичного переноса и вставки внутрь диапазона (цель сдвигается на границу).

**Нормализация проекта:** список умолчаний `analysisConfig`/`ui`/`runs` из 58 059 — источник для `sat-core::canon` defaults (сверить с обёрткой 131 963). `compactOverwriteChainPathChunks` всегда true; `conflictIgnorePaths` по умолчанию `meta.ini, desktop.ini, thumbs.db`.

**Формулы UI:** `colorToBg` α .58/.38 (выкл .28/.18); круговое среднее оттенков; вес цвета контекста `1+9·log1p(f)/log1p(fmax)`, порог 0.22; порядок выбора цвета тега; таблицы `TAG_COLORS`/`TAG_GROUP_COLOR_RULES` — перенести как данные.

**Вероятные ошибки / спорное:**
1. `getRealSeparatorMods` объявлен дважды; живая 59 029 **не исключает** parked-sync моды и `sync.role==='separator_representative_snapshot'` (в отличие от 34 743 с `isRealOrderableMod`). Счётчики модов (38 738), индексы (70 686–70 720), буфер обмена считают parked-моды. Скорее всего непреднамеренно; в NG — одно правило «реальный упорядочиваемый мод» = версия 34 743.
2. `serializeModlist` живая версия бросает исключение при любой проблеме группы — SYNC-фиксация (36 117, 37 321…) может падать из-за группы, не связанной с синхронизацией. В NG: валидация до плана фиксации с понятной ошибкой.
3. `restoreLogicalGroupNGSourceSnapshotV567` откатывает только состав `separator.mods` и `enabled`; изменения других полей модов (в мутаторах их нет сейчас) и добавленные/удалённые разделители не откатываются.
4. `sanitizeLogicalGroupNGConflictChainNameV571` ищет имена участников **подстрокой** — ложные срабатывания на короткие имена («A» внутри «Armor») и переписывание пользовательского имени цепочки.
5. `invalidateLogicalGroupNGCompositeCacheV578`: пустой набор id трактуется как «очистить всё» — вызов с нераспознанным ключом сносит весь кэш.
