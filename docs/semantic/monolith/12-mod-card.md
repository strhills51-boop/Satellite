# 12 — Карточка мода, бейджи перезаписи, декорация, таблица конфликтов (монолит → NG)

Снято вживую 2026-11-01: монолит в Chromium, синтетическая сборка 60 модов / 12 разделителей / ~5 тыс. файлов /
54 цепочки, полный путь «новый workspace → пробег анализа». Скриншоты — `docs/parity/monolith/` (имена ниже).
Повод — замечания владельца: счётчики W/L/M на карточке не отвечают на вопрос «с кем и в чём мод конфликтует»;
эталон карточки — монолит, лучший вид бейджей — тяжёлая модель монолита, но её нужно сделать лёгкой.

## 1. Анатомия карточки мода (`.mod-card`)

Порядок слоёв в DOM (`st-card-*.html` из прогона; всё ниже — один элемент сетки):

1. `selection-visual-layer` — слой выделения (рамка-уголки фокуса рисуется здесь).
2. `mod-state-dot` — точка состояния слева: вкл/выкл + вариант плагинов (`mod-plugin-dot-empty` и др.: есть ли
   плагины и их состояние).
3. `mod-overwrite-context-strip` — **полоса бейджей перезаписи** (см. §2). Слева от имени.
4. `mod-main` → `mod-name` (по центру, класс `mod-name-center-fits`, обрезка справа), слот меты, `sync-card-meta`
   (тип записи SYNC: `sync`, `potential` и т. п.).
5. `structural-counter mod-priority` — `глобальный порядок : порядок в разделителе` (`51:3`), токены с «качеством»
   значения (`quality-exact` — точный факт).
6. Слоты: точечная полоса тегов (`mod-tag-dotbar`), стопка стикеров.

Карточки идут **потоком в несколько колонок** внутри разделителя (`--mod-card-flow-basis: 174px` — ширина
зависит от содержимого: в классической модели бейджей 308px). Декорация мода (§3) задаёт ширину, перенос строки
до/после, «вся ширина», высоту и поля — то есть контейнер элемента списка настраивается пользователем.

Строка-представитель разделителя — во всю ширину: имя `X_separator`, замок, «Представитель разделителя», пилюля
`OW 206` (сумма по блоку), справа счётчик `11:49:5`.

Плитки разделителей слева: `порядок : глобальный индекс первого мода : число модов`, справа сверху число
включённых (зелёная точка) и Overwrite-точка (фиолетовая); системные плитки Skyrim и Overwrite.

## 2. Бейджи перезаписи: две модели (`OVERWRITE_BADGE_MODE_*_V644`, 33 389)

Переключаются в сводке: «Эффекты → Бейджи → Модель overwrite» (`effects-badges-model.png`), там же «Плотность»
(сколько значков помещается), «Область» (где показывать), «Прозрачность».

| Модель | На карточке | Скриншот |
|---|---|---|
| `summary` — «OW N — оптимизированная» | одна пилюля `OW 61` с точкой цвета контекста; подсказка: `61 conflict paths · 46 wins · 15 losses · 105 opponents · <первые соперники>` | `card-badges-summary.png` |
| `classic` — «Коллекция цепочек — классическая» (**тяжёлая, любимая владельцем**) | по бейджу на **каждый контекст** мода: точка цвета контекста + **значок на каждую цепочку** мода в этом контексте (эмодзи на фоне цвета цепочки), решённая цепочка — `✓`, лишние — `+N`; подсказка контекста — список имён цепочек | `card-badges-classic.png` |

Код классической полосы — `renderModOverwriteContextStrip…` (~81 400–81 500):
- группы цепочек мода собираются по контекстам (`bucket` = контекст, `bucket.groups` = цепочки);
- лимит значков `limits.chains` из «Плотности»; `+N` — если включена статистика `conflictStats` и контекст не решён;
- значок: `--chain-icon-bg = цвет цепочки α.34`, рамка α.70, тень α.38; содержимое — эмодзи из визуальной
  идентичности цепочки (`getConflictPresentationBadgeVisualMetaV669(group)` → `{name, icon, color}`), `title` —
  сгенерированное имя цепочки;
- бейдж контекста: `--ctx-color` и производные α.10/.26/.14/.44/.13;
- результат кэшируется на мод (`renderModOverwriteContextStripCached`).

**Почему тяжело:** на каждую карточку — HTML со значками всех цепочек (до сотен) и длинными `title`; пересборка
полосы при каждом изменении; идентичность цепочки (имя, эмодзи, цвет) вычисляется из нормализованного слоя
(обл. 10, см. `08-conflicts.md` §4.6–4.10).

## 3. Декорация мода (ПКМ → «Покрасить…» и блок сводки «Декорация мода»)

Контекстное меню мода (`mod-context-menu-hover-cloud.png`): заголовок `Мод: X`, **поле-фильтр разделителей**,
«Перекинуть в: <разделитель>» ×N, «Создать новый пустой мод», «Переименовать», «Массовые операции…», «Выключить»,
«Покрасить…», «Скопировать в буфер имя / с метой», «В корзину». При наведении на мод — **облачко «Наведение»**:
Теги (+Добавить), Plugins (blacklist), Note (+Создать note), с кнопкой закрепления.

«Покрасить…» — палитра 8×16 цветов, «Отмена», «Сбросить» (`mod-paint-palette.png`).

Блок сводки «Декорация мода» (для выделенных модов; режимы Default / Скрыть):
- **Раскраска фона:** тип (цвет, градиент →, градиент ↓, радиальный, конический, полосы, диагональ, шахматка,
  точки), Фон, Фон 2;
- **Размеры / Flow:** Width (250), «Новая строка до», «Новая строка после», «Вся ширина», Height (30), Margin top /
  bottom — **это и есть настройка контейнера элемента списка**;
- **Форма / обводка:** скругление, толщина, стиль (solid / dashed / dotted / double), цвет;
- **Текст:** цвет, размер, жирность 400–800, разрядка, регистр;
- **Акцент:** цвет, ширина; **Эмодзи-watermark:** набор по категориям, позиция, размер, opacity, blur;
- **Эффект тегов** (индивидуальный профиль: аура, поле, арканоид, трещины, точки / полоски, резонанс,
  интенсивность, анимация); **Эффекты декорации:** тень soft / deep, glow.

## 4. Блок «Конфликты» в сводке (`summary-conflicts-block.png`)

- Список **цепочек мода**: значок (эмодзи цепочки) + сгенерированное имя
  (`long chain·armor·textures·core·archit…`) + кружок «решено»; рамка цвета цепочки; `+4` свёрнутых.
- Ниже — **участники** (моды цепочки), сгруппированные по разделителям, со счётчиком `44:1`; фон строки —
  **«зубы»** (вертикальные полосы: красные — проигрывает, зелёные — выигрывает) и **пунктирная жёлтая кромка**;
  выбранный мод — зелёный, мод без участия — «potential» приглушённо.

## 5. Таблица конфликтов с флажком «красоты» (`conflicts-table-beauty.png`)

Флажок: Настройки → «Модалка конфликтов — цветные типы файлов в таблице и мягкая заливка столбцов»
(`setConflictTableFileTypeBeautyEnabled`). С ним:
- заголовок контекста — сгенерированное имя с цепочкой «A → B → C»; «Цепочек: 54 · Модов: 60 · Файлов: 307»;
  селектор контекста, поиск, тумблеры «Фронт решений» / «✓ Решённые», строка «файл не выбран · <мод>»;
- **ось столбцов = файлы**, над каждым столбцом **цветная иконка типа файла** (dds, nif, hkx… — своим цветом);
  сортировка «Сила конфликта» / «Релевантность цепочке»; маркеры «2», «10» над группами столбцов;
- строки — моды, сгруппированные по разделителям (сворачиваемые), `глобальный:локальный`, фиолетовая кромка слева
  у участников; клетки — **зелёная = мод выигрывает этот файл, красная = проигрывает, пустая = не владеет**;
- строка состояния внизу: `Stack stack_33 · 1 files · 1 папок · textures · 1 × .dds`.
Без флажка — те же клетки без цвета типов и без заливки столбцов (`conflicts-table.png`).

## 6. Как NG повторит это без тяжести

Принцип: всё тяжёлое — в ядре, по ключам и лениво; страница получает только то, что видно.

1. **Идентичность цепочки** (имя, эмодзи, цвет) — функция содержимого, а не порядка: хэш отсортированного по id
   множества модов цепочки (урок старого Satellite: сигнатура не должна зависеть от порядка). Эмодзи — из
   фиксированного набора по хэшу, цвет — оттенок по хэшу; имя — генератор по путям (верхние папки, расширения,
   семейства) + «первый → последний мод». Живёт в ядре рядом с цепочками, вычисляется при создании цепочки
   (интернирование уже инкрементальное — `@sat:overwrite.update`).
2. **Полоса бейджей на карточке**: в ответ `Rows` для видимых строк — по контекстам мода первые `K` цепочек
   (идентичности) + число остальных; `K` задаёт плотность. Список цепочек мода кэшируется в проекции (лениво,
   как контексты) — не скан путей на каждый запрос.
3. **Решённость** («✓», «решено») — истина «решения» на устойчивом id цепочки (сигнатура содержимого), переживает
   повторный пробег (сверка matched / new / removed, как в прототипе, но без зависимости от порядка).
4. **Карточка = данные декорации**: ширина, перенос, вся ширина, высота, поля, фон, обводка, текст, акцент,
   watermark — декорации ядра (`order::decor`), а раскладка потока — проекция вида: блок разделителя = ряды карточек
   по ширинам; виртуализация по блокам (раскладывается только видимый блок).
5. **Таблица конфликтов** — отдельное окно с виртуализацией по обеим осям (в монолите тормозит на больших
   контекстах): ось файлов и ось модов приходят окнами из ядра; клетка = победитель пути (`path_winner`) и
   владение (`path_providers`); цвет типа файла — по расширению.
6. **Режимы бейджей** (`summary` / `classic`) — настройка вида, а не два кода: одна проекция, два способа показа.

Порядок работ (без спешки, по одному слою): идентичность цепочек в ядре → полоса бейджей на карточке → блок
«Конфликты» с цепочками и участниками → декорации контейнера и поток → таблица контекста.

## 7. Сделано в NG (2026-11-01)

- Внешний вид цепочки — `@sat:identity`: эмодзи и оттенок из отсортированных имён участников, порядок и
  перенумерация модов не влияют.
- Бейджи на карточке — `@sat:app.badges`: ядро отдаёт их только для видимых строк; модель «коллекция цепочек» и
  `OW N` — переключатель и плотность на странице, данные одни.
- **Расхождение:** на синтетике монолита у NG 172 точные цепочки, у монолита 54 — монолит сводит повторы в
  нормализованные цепочки и группы маршрутов (обл. 10, `08-conflicts.md` §4.4–4.7). Нормализованный слой — NG-D002;
  до него значков больше, чем в монолите.
- Блок «Конфликты» в сводке: цепочки с иконкой, сгенерированным именем (`пути · первый → последний`), числом
  файлов и кружком «решено» (6 видно, `+N` раскрывает); выбор цепочки — её пути и подсветка её «зуба» у
  участников; участники сгруппированы по разделителям, фон — зубы по цепочкам (зелёный — выигрывает, красный —
  перекрыт), жёлтая пунктирная кромка, сам мод выделен; клик — фокус на участника.
- «Решено» — истина «решения» в ядре (`@sat:decisions`) на подписи содержимого: переживает перестановку (тест
  `sat-app`), на карточках решённая цепочка — ✓. В проекте — поле `decisions` (отсортированные hex-подписи,
  без потери точности в JavaScript); devserver поднимает их из проекта, `sat-cli --reimport` их сохраняет. Запись
  из окна — вместе с контейнером проекта (ADR 0007): devserver остаётся песочницей.
- Контейнер карточки (ADR 0012): поток в несколько колонок внутри разделителя, стиль карточки как декорация,
  редактор «Декорация мода» в сводке (поля, `mixed`, Default, последние декорации).
- Таблица контекста (`@sat:app.context-table`, кнопка «Таблица» в блоке «Конфликты»): строки — моды контекста,
  сгруппированные по разделителям (`▲` выигрывает / `▼` проигрывает файлов), столбцы — пути, над столбцом полоса
  цвета цепочки и плитка цвета типа файла, клетка — зелёная / красная / пустая; порядок «Релевантность цепочке» и
  «Сила конфликта»; строка состояния — путь, цепочка, стек, роль мода; клик — фокус на мод. Обе оси приходят окнами,
  клетка не хранится — берётся из стека цепочки пути. Снимок: `docs/parity/ng-context-table.png`.
  **Ещё нет:** сворачивание групп, поиск, «Фронт решений» / «✓ Решённые», отметка решения прямо из таблицы.
