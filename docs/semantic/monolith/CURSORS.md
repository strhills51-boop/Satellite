# Протокол конспекта монолита: главный курсор и курсоры связей

Идея владельца. **Главный курсор** читает монолит строго сверху вниз и ведёт конспект.
**Курсоры связей** уходят туда, куда ведёт код: объявление ниже по файлу, переопределение позже,
зависимость в другом блоке.

## Инструменты

- `tools/monolith/xref.mjs build <monolith.html> <index.json>` — индекс по настоящему JS-парсеру (acorn):
  объявления (function / const / method), присваивания (`x = function`, `window.X =`), ссылки по строкам.
- `node tools/monolith/xref.mjs chunk <index.json> <start> <end>` — задания для курсоров связей по куску:
  «используется здесь, объявлено ниже», «объявлено здесь, переопределено в другом месте», «хабы».
- `node tools/monolith/xref.mjs sym <index.json> <monolith.html> <name>` — где объявлено, где переназначено, где используется.
- `docs/semantic/monolith/structure.md` — блоки, заголовки разделов, API, переопределения.

## Проход 1 (2026-10-30)

Монолит поделён на сегменты. Внутри сегмента главный курсор идёт подряд, без пропусков. Сегменты идут
параллельно. Связи между сегментами разбираются по индексу, поэтому параллельность не теряет связей.
Итог каждого сегмента — `pass/SNN-<start>-<end>.md`:

1. **Обзор** — что в сегменте, в двух–пяти предложениях.
2. **Последовательный конспект** — подряд идущие участки `a–b`: область (по `00-index.md`), ключевые имена со строками,
   что делает, какое состояние читает и пишет, статус (живое / тень под флагом / мёртвое / самотест), версия.
3. **Связи** — по выводу `xref chunk`: куда ведёт ссылка и что там. Для переопределений — какая версия живая
   (последняя по порядку исполнения) и чем она отличается.
4. **Для NG** — точные правила и формулы, которые надо перенести; спорные места; вероятные ошибки.
5. **Открытые нити** — что не успел разобрать, для следующего прохода.

## Проход 2 (сшивка)

По открытым нитям и связям — сводные конспекты областей `NN-<область>.md`, на которые ссылается `00-index.md`.
