# Монолит — конспект: оглавление по областям

Копия: `index.html`, 196 155 строк, 8,9 МБ (`structure.md`: блоки, заголовки, API, переопределения — автоматически).
Здесь — смысловая карта: какая область где лежит, что в ней живое, что «тень» и что брать в NG.
Подробные конспекты областей — в файлах `NN-<область>.md` (пишутся по мере изучения; статус в последней колонке).

## Как устроен файл

- **Строки 121–19 452: CSS** (14 блоков `<style>`, главный — 18 тыс. строк). Слои стилей наслаиваются версиями
  (`v282 … v704`); поздние правила перекрывают ранние. Для паритета вида это источник цветов, отступов и плотности.
- **Строки 19 453–173 827: один огромный `<script>`** (154 тыс. строк) — всё приложение.
- **Строки 173 829–196 155: ещё 50 скриптов** с id: восстановление ядра пробега (Run Kernel recovery CP2–CP12),
  контракты процессов и развёртывания (v526Raw, v527 Deployment), мобильный режим (PHONE CP2–CP6).

## Слои истории (как читать версии)

- `vNNN` — версия монолита, в которой появился блок; `CPn` — контрольная точка внутри версии.
- **v527 «behavior-preserving refactor»** — последний большой рефакторинг: код разложен по 88 «владельцам»
  (`create…RuntimeOwnerV527`). Старые глобальные функции остались тонкими делегатами
  (`function x(){ return owner.x.apply(this, arguments) }`). Ищешь реализацию — иди в объект владельца.
- **«shadow» / «теневой»** — новая реализация работает рядом со старой и сравнивается с ней; включается флагами
  `window.modlistToolFlags.*` / `window.__modlistTool*` (по умолчанию выключены). **Не путать с живым путём.**
- **cutover** — момент, когда новая реализация стала главной (пример: пробег «Бездна» — `runOrchestratedAnalysisCutoverV503`).
- **Переопределения**: 49 функций переназначены поверх себя, в том числе `renderAll` 11 раз, `parseModlist` 5 раз,
  `renderClassic` 6 раз (`structure.md` → «Переопределения»). Живая версия — **последняя по порядку исполнения**.
  Это главный источник путаницы в монолите и причина семантического слоя NG.
