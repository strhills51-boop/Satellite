# Старый Satellite → NG: что берём

Сводка конспекта `00-conspectus.md`. Каждая строка — принцип или контракт, у которого будет **один владелец** в NG
(после формализации ядра — в `docs/semantic/MAP.md`).

> **Граница источников (решение владельца, 2026-11-01).** Из прототипа берём только **архитектуру**: законы,
> контракты, устройство движка. **Функционал** — конфликты, цепочки, плагины, архивы, импорт — берём из монолита:
> там он реализован на порядок полнее (`docs/parity/`, `docs/semantic/monolith/`). Функциональные строки ниже —
> подсказки об устройстве, а не эталон поведения. Конспект прототипа закрыт.

## Принципы (дословно из прототипа, остаются законом)

1. **Истина одна, проекций много.** UI наблюдает проекции, истиной владеет логика (`no-ui-state-as-truth`).
2. **Идентичность — id, не имя** (`stable-id-only`). Имя — отображение; одинаковые имена — разные сущности.
3. **Команды не вызывают рендер** (`no-render-from-command`): изменение → инвалидация → один пересчёт на кадр.
4. **Хранение ≠ runtime** (`storage-not-runtime`): производное не хранится, после загрузки пересобирается.
5. **Новые возможности — только через ресурсный путь** (`manifest → registry → policy → runtime`).
6. **Проверка архитектуры при старте, загрузке и регистрации** (`guarded-runtime`).
7. **События не владеют истиной**, только уведомляют.
8. **Ресурс не трогает истину напрямую**: читает копии через API, пишет только командами.
9. **Стадию вызывает только оркестратор**; стадии возвращают факты.

## Не повторяем (дефекты прототипа)

- Доверие по префиксу id; поля определения перетирают нормализованные; источник ресурса переопределяется
  внутри манифеста; нет пространств имён — повышение доверия и тихая подмена ресурсов.
- Возможности глобальны на проект, `requestedCapabilities` не проверяются.
- Одобрение хранится в ресурсе и в файле проекта; `new Function` в главном потоке; фабрика исполняется до
  одобрения; шаблоны в `innerHTML`.
- Позиции (`order.global`) хранятся в сущностях; перемещение O(n·k); проекция окна пересобирается целиком.
- Изменение выделения грязнит все окна; состояние окон конфликтов и файлов глобально на проект.
- `commitDock` теряет группу; `concurrencyKey` задач не работает; у задач нет поколений; `hashText` — не FNV.
- Три независимых источника правды о плагинах без канона (вероятная «ловушка версионности»).
- Сигнатура цепочки конфликта зависит от порядка (владельцы отсортированы по порядку): перестановка + пробег
  теряют решения пользователя. Сигнатура — от множества по id.
- Патч перезаписи после перемещения обходит все конфликтные файлы; `find` в циклах (O(n²)); заголовки-проекции
  хранятся.
- Версия заголовка плагина читается и не проверяется; «вне списков» = «скрыт лимитом MO2» (на деле чаще
  выключенный мод); читается первый кандидат, а не победитель; нет проверки отсутствующих мастеров и лимита
  индексов.
- Два парсера на каждый формат архива; размер сжатой записи BSA угадывается.
- Каталог стадий не управляет вызовом (`if (stage.id === …)`); `sourceKind` по подстроке; запасной решатель по
  жёсткому id.
- Итог пробега пишется в проект по частям во время пробега, а не публикуется поколением.
- Вставка окна сама активирует ресурс (активация без одобрения); две реализации «можно ли показать окно»;
  `reconcileProjectResources` только растит списки.
- `*` в `modlist.txt` считается «включён», хотя это неуправляемый мод.
