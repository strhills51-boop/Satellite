Все контролы в этой секции работают локально. Для Satellite NG здесь нет записи канона, вызова MO2, движка конфликтов или прав доступа. При переносе Claude подключает события к существующему владельцу команды, а не создаёт новый слой истины.


INTEGRATION PROTOCOL / CLAUDE
Как пользоваться пакетом, не превращая NG в монолит
Эти правила — инструкции к эталонам дизайна, не альтернатива ADR и не новый runtime.


Перед изменением
  1. Открыть актуальный docs/semantic/MAP.md; найти понятие, владельца, @sat:-якорь.
  2. Проверить статус ADR: 0012 принято; 0020, 0009 и 0016 содержат предложенные части.
  3. В components.registry.json выбрать существующий образец; статус «концепт» не принимать за код.
  4. Установить источник состояния: канон / декорация / факт / решение / вид.


При интеграции
  1. Редактировать существующего владельца интерфейса. Не создавать component-v2 поверх component-v1.
  2. Если берёшь .satui-* — импорты CSS один раз и явный адаптер событий к существующему API.
  3. Четыре рода контролов ADR 0020: режим (зуб), действие (ghost), данные (динамические чипы), включатель блока (кружок). Их роли не смешивать.
  4. Не копировать демонстрационные данные, DOM-скриншоты, toast/подсказки и код галереи в production.
  5. Не менять канонический порядок загрузки CSS-раскладкой: он сверху вниз, в строке слева направо.


Проверка результата
  1. Сравнить до/после в живом runtime с тестовыми данными, а не только в HTML.
  2. Проверить тему, плотность, 390/900/1450 px, wheel, Shift+wheel, drag, фокус и скролл.
  3. Проверить отсутствие двойных обработчиков и поздних !important-перебивок.
  4. Изменения семантики и владельца отразить в карте тем же коммитом.
